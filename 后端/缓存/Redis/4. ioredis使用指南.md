### 建立 Redis 连接

```TypeScript
读取 REDIS_URL
  ↓
创建单个 ioredis 客户端
  ↓
配置重连策略、连接超时
  ↓
监听 connect / ready / error 事件
  ↓
导出客户端给业务模块复用
  ↓
进程收到退出信号时，优雅断开 Redis
```

```TypeScript
*// src/redis/client.ts*
import Redis from 'ioredis';

const redisUrl = process.env.REDIS_URL;

export const redis = new Redis(redisUrl, {
  // **连接超时时间，单位是毫秒**
  connectTimeout: 10_000,
  // **单个 Redis 命令的最大重试次数**
  maxRetriesPerRequest: 3,
  // **是否开启 Redis 就绪检查**
  // 当连接建立后，ioredis 会检查 Redis 是否真正已准备好接受命令，例如 Redis 是否仍在加载持久化数据（LOADING 状态）
  // **生产环境建议使用 true**
  enableReadyCheck: true,
  // **定义 Redis 连接断开后的重连策略**
  // 当重试次数大于 10 时返回 null，表示停止自动重连。此后 Redis 客户端不再继续尝试建立连接。
  // 返回指定下一次重连前需要等待多久，单位是毫秒。
  retryStrategy: (retryCount) => {
    if (retryCount > 10) {
      return null;
    }

    return Math.min(retryCount * 200, 2_000);
  },
});

// **监听 connect 事件**
// 当 Redis 的 TCP 连接成功建立时触发。此时只能说明网络连接已连通，Redis 服务未必已经完全可处理请求。
redis.on('connect', () => {
  console.info('[Redis] Connected...');
});

// **监听 ready 事件**
// 当 Redis 客户端确认 Redis 已经可以正常接收命令时触发
redis.on('ready', () => {
  console.info('[Redis] Ready');
});

// **监听 error 事件**
// 连接失败、认证失败、网络中断、Redis 服务不可达等问题都可能触发该事件
// error 是原始错误对象，通常会包含错误类型、消息及堆栈
// **为 Redis 客户端添加 error 监听非常重要。Node.js 的 EventEmitter 如果发出 error 事件却没有对应监听器，可能导致进程异常退出。**
redis.on('error', (error) => {
  console.error('[Redis] Connection error:', error);
});

// **监听 close 事件**
// Redis 底层连接关闭时触发，可能是以下原因：
// 1. Redis 服务停止；
// 2. 网络断开；
// 3. 调用了 redis.quit()；
// 4. 调用了 redis.disconnect()；
// 5. 重连策略达到上限，不再重连。
redis.on('close', () => {
  console.warn('[Redis] Connection closed');
});

// 定义异步关闭函数，返回值为 Promise<void>。
// 它会在进程接收到退出信号时执行。
// ioredis 常见状态包括：
// - wait：等待连接；
// - connecting：正在连接；
// - connect：已建立 TCP 连接；
// - ready：Redis 已可用；
// - close：连接已关闭；
// - reconnecting：正在重连；
// - end：客户端已彻底结束，不会再重连。
const handleShutdown = async (): Promise<void> => {
  // 如果 Redis 当前状态已经是 end，直接返回，避免重复关闭。
  if (redis.status === 'end') {
    return;
  }

  try {
    // 调用 redis.quit() 优雅地关闭连接。
    // 它通常会：
    // 1. 等待已经排队或正在处理的 Redis 命令完成；
    // 2. 向 Redis 发送 QUIT 命令；
    // 3. 关闭连接；
    // 4. 停止后续自动重连。
    await redis.quit();
    console.info('[Redis] Disconnected gracefully');
  } catch (error) {
    // 如果 quit() 失败，例如 Redis 已经断开、网络异常或命令无法发送：
    // 1. 输出错误日志；
    // 2. 调用 redis.disconnect() 强制关闭底层连接。
    // disconnect() 不会等待队列中的命令完成，也不保证向 Redis 发送 QUIT，因此适合作为失败时的兜底措施。
    console.error('[Redis] Failed to disconnect:', error);
    redis.disconnect();
  }
};

// 监听 SIGINT 信号
// 常见触发方式：
// 1. 本地终端按 Ctrl + C；
// 2. 进程被手动中断。
process.once('SIGINT', () => {
  void handleShutdown().finally(() => process.exit(0));
});

// 监听 SIGTERM 信号。
// SIGTERM 是生产部署中最常见的终止信号，例如：
// 1. Docker 停止容器；
// 2. Kubernetes 终止 Pod；
// 3. PM2 或 systemd 停止服务；
// 4. 执行 kill <pid>（默认就是发送 SIGTERM）。
process.once('SIGTERM', () => {
  void handleShutdown().finally(() => process.exit(0));
});
```

### 基础 String：缓存、验证码、临时数据

#### 缓存 JSON 对象

```TypeScript
读取缓存：
  从 Redis GET key
  ↓
不存在则返回 null
  ↓
存在则 JSON.parse
  ↓
解析失败时删除异常缓存，并返回 null

写入缓存：
  JSON.stringify(value)
  ↓
SET key value EX ttlSeconds
```

```TypeScript
*// src/redis/cache.ts*
import { redis } from './client.js';

export const getJsonCache = async <T>(key: string): Promise<T | null> => {
  const serializedValue = await redis.get(key);

  if (!serializedValue) {
    return null;
  }

  try {
    return JSON.parse(serializedValue) as T;
  } catch {
    await redis.del(key);
    return null;
  }
};

export const setJsonCache = async <T>(
  key: string,
  value: T,
  ttlSeconds: number,
): Promise<void> => {
  await redis.set(key, JSON.stringify(value), 'EX', ttlSeconds);
};

export const deleteCache = async (key: string): Promise<void> => {
  await redis.del(key);
};
```

##### 使用实例：防缓存穿透和缓存雪崩

```TypeScript
import { getJsonCache, setJsonCache } from '../redis/cache.js';

type Article = {
  id: string;
  title: string;
  content: string;
  updatedAt: string;
};

const getArticleFromDatabase = async (articleId: string): Promise<Article | null> => {
  // 用实际数据库查询逻辑替换
  return {
    id: articleId,
    title: 'Redis 实战',
    content: 'Node.js + ioredis 示例',
    updatedAt: new Date().toISOString(),
  };
};

const getArticleById = async (articleId: string): Promise<Article | null> => {
  const cacheKey = `v1:article:detail:${articleId}`;

  const cachedArticle = await getJsonCache<Article>(cacheKey);

  if (cachedArticle) {
    console.log('Cache hit');
    return cachedArticle;
  }

  console.log('Cache miss');

  const article = await getArticleFromDatabase(articleId);

  if (!article) {
    // 防缓存穿透：缓存空结果，但 TTL 应较短
    await setJsonCache(cacheKey, null, 60);
    return null;
  }

  const baseTtlSeconds = 10 * 60;
  const randomTtlSeconds = Math.floor(Math.random() * 60);

  // TTL 加随机值，降低大量 Key 同时失效的风险
  await setJsonCache(
    cacheKey,
    article,
    baseTtlSeconds + randomTtlSeconds,
  );

  return article;
};
```

#### 验证码：防重复发送、自动过期

```TypeScript
Key: auth:email-code:<email>
Value: 验证码
TTL: 5 分钟
```

```TypeScript
import { redis } from '../redis/client.js';

const verificationCodeTtlSeconds = 5 * 60;

const createEmailCode = (): string => {
  return Math.floor(100_000 + Math.random() * 900_000).toString();
};

export const sendVerificationCode = async (
  email: string,
): Promise<{ success: boolean; code?: string }> => {
  const normalizedEmail = email.trim().toLowerCase();
  const cacheKey = `auth:email-code:${normalizedEmail}`;
  const code = createEmailCode();

  // NX: 仅当 Key 不存在时设置成功。
  // 防止用户在验证码过期前不断重复发送。
  const result = await redis.set(
    cacheKey,
    code,
    'EX',
    verificationCodeTtlSeconds,
    'NX',
  );

  if (result !== 'OK') {
    return {
      success: false,
    };
  }

  // 实际项目中：调用邮件服务发送 code，不应将 code 返回给客户端
  console.log(`Send verification code ${code} to ${normalizedEmail}`);

  return {
    success: true,
    code,
  };
};

export const verifyEmailCode = async (
  email: string,
  inputCode: string,
): Promise<boolean> => {
  const normalizedEmail = email.trim().toLowerCase();
  const cacheKey = `auth:email-code:${normalizedEmail}`;

  const storedCode = await redis.get(cacheKey);

  if (!storedCode) {
    return false;
  }

  if (storedCode !== inputCode) {
    return false;
  }

  // 验证成功后立即删除，确保验证码一次性使用
  await redis.del(cacheKey);

  return true;
};
```

```TypeScript
import { redis } from '../redis/client.js';

type UserProfile = {
  id: string;
  name: string;
  email: string;
  role: 'user' | 'admin';
};

export const saveUserProfile = async (
  profile: UserProfile,
): Promise<void> => {
  const cacheKey = `user:profile:${profile.id}`;

  await redis.hset(cacheKey, {
    name: profile.name,
    email: profile.email,
    role: profile.role,
    loginCount: '0',
  });

  await redis.expire(cacheKey, 60 * 60 * 24);
};

export const getUserProfile = async (
  userId: string,
): Promise<Omit<UserProfile, 'id'> | null> => {
  const cacheKey = `user:profile:${userId}`;
  const userData = await redis.hgetall(cacheKey);

  if (Object.keys(userData).length === 0) {
    return null;
  }

  return {
    name: userData.name,
    email: userData.email,
    role: userData.role as UserProfile['role'],
  };
};

export const increaseLoginCount = async (
  userId: string,
): Promise<number> => {
  return redis.hincrby(`user:profile:${userId}`, 'loginCount', 1);
};
```

```TypeScript
import { redis } from '../redis/client.js';

export const likeArticle = async (
  articleId: string,
  userId: string,
): Promise<{ liked: boolean; totalLikes: number }> => {
  const cacheKey = `article:likes:${articleId}`;

  // SADD 返回 1：新增成功；返回 0：用户此前已经点过赞
  const addedCount = await redis.sadd(cacheKey, userId);

  return {
    liked: addedCount === 1,
    totalLikes,
  };

  articleId: string,
  userId: string,
): Promise<{ removed: boolean; totalLikes: number }> => {
  const cacheKey = `article:likes:${articleId}`;

  const removedCount = await redis.srem(cacheKey, userId);
  const totalLikes = await redis.scard(cacheKey);

  return {
    removed: removedCount === 1,
    totalLikes,
  };
};

export const hasLikedArticle = async (
  articleId: string,
  userId: string,
): Promise<boolean> => {
  const cacheKey = `article:likes:${articleId}`;

  const result = await redis.sismember(cacheKey, userId);

};
```

```TypeScript
import { redis } from '../redis/client.js';

type LeaderboardItem = {
  userId: string;
  score: number;
};

const leaderboardKey = 'leaderboard:weekly:2025-02-17';

export const addUserScore = async (
  userId: string,
  score: number,
): Promise<number> => {
  return redis.zincrby(leaderboardKey, score, userId);
};

export const getTopUsers = async (
  limit = 10,
): Promise<LeaderboardItem[]> => {
  const membersWithScores = await redis.zrevrange(
    leaderboardKey,
    0,
    limit - 1,
    'WITHSCORES',
  );

  const result: LeaderboardItem[] = [];

  for (let index = 0; index < membersWithScores.length; index += 2) {
    result.push({
      userId: membersWithScores[index],
      score: Number(membersWithScores[index + 1]),
    });
  }

  return result;
};

export const getUserRank = async (
  userId: string,
): Promise<{ rank: number; score: number } | null> => {
  const [rank, score] = await Promise.all([
    redis.zrevrank(leaderboardKey, userId),
    redis.zscore(leaderboardKey, userId),
  ]);

  if (rank === null || score === null) {
    return null;
  }

  return {
    // Redis 排名从 0 开始，业务展示通常从 1 开始
    rank: rank + 1,
    score: Number(score),
  };
};
```

#### 延迟任务的简单实现

生产任务队列优先推荐 BullMQ。

以下代码用于理解 Redis ZSet 延迟任务原理。

```TypeScript
添加任务：
  将任务 JSON 存入 ZSet
  score = 预计执行时间戳

消费任务：
  获取 score 小于当前时间的任务
  ↓
通过 Lua 原子删除任务
  ↓
删除成功才真正执行任务
```

```TypeScript
import { randomUUID } from 'node:crypto';
import { redis } from '../redis/client.js';

type DelayedTask = {
  id: string;
  type: 'send-email' | 'close-order';
  payload: Record<string, unknown>;
};

const delayedTaskKey = 'queue:delayed-tasks';

export const addDelayedTask = async (
  type: DelayedTask['type'],
  payload: Record<string, unknown>,
  delayMilliseconds: number,
): Promise<DelayedTask> => {
  const task: DelayedTask = {
    id: randomUUID(),
    type,
    payload,
  };

  const executeAt = Date.now() + delayMilliseconds;

  await redis.zadd(
    delayedTaskKey,
    executeAt,
    JSON.stringify(task),
  );

  return task;
};

const removeTaskIfExistsLua = `
  if redis.call("ZREM", KEYS[1], ARGV[1]) == 1 then
    return 1
  end

  return 0
`;

export const consumeDueDelayedTasks = async (): Promise<void> => {
  // 查找所有“执行时间小于等于现在”的任务，最多取前 100 个
  const dueTaskValues = await redis.zrangebyscore(
    delayedTaskKey,
    0,
    Date.now(),
    'LIMIT',
    0,
    100,
  );

  for (const taskValue of dueTaskValues) {
    // 优先删除再处理，避免多应用实例同时消费延迟任务
    const removed = await redis.eval(
      removeTaskIfExistsLua,
      1,
      delayedTaskKey,
      taskValue,
    );

    if (removed !== 1) {
      continue;
    }

    const task = JSON.parse(taskValue) as DelayedTask;

    console.log('Processing delayed task:', task);

    // 根据 task.type 执行真实业务逻辑
    // await processTask(task);
  }
};
```

定时执行：

```TypeScript
setInterval(() => {
  void consumeDueDelayedTasks();
}, 1_000);
```

#### 限流：固定窗口与 Lua 原子实现

```TypeScript
接收用户 ID 或 IP
  ↓
根据当前时间计算窗口编号
  ↓
Lua 中对指定 Key 执行 INCR
  ↓
若是第一次访问，为 Key 设置 EXPIRE
  ↓
读取当前 TTL
  ↓
若请求数超过限制，拒绝请求
  ↓
返回允许状态、剩余次数、重试秒数
```

使用 Lua 的原因：

```TypeScript
INCR 与 EXPIRE 必须原子执行。
否则应用在 INCR 后崩溃，可能产生永不过期的限流 Key。
```

```TypeScript
import { redis } from './client.js';

type RateLimitResult = {
  allowed: boolean;
  current: number;
  remaining: number;
  retryAfterSeconds: number;
};

const fixedWindowRateLimitLua = `
  local current = redis.call("INCR", KEYS[1])

  if current == 1 then
    redis.call("EXPIRE", KEYS[1], ARGV[1])
  end

  local ttl = redis.call("TTL", KEYS[1])

  return { current, ttl }
`;

export const checkFixedWindowRateLimit = async (
  identifier: string,
  options: {
    action: string;
    limit: number;
    windowSeconds: number;
  },
): Promise<RateLimitResult> => {
  const { action, limit, windowSeconds } = options;
  const currentWindow = Math.floor(Date.now() / (windowSeconds * 1_000));

  const cacheKey = `rate-limit:${action}:${identifier}:${currentWindow}`;

  const result = (await redis.eval(
    fixedWindowRateLimitLua,
    1,
    cacheKey,
    windowSeconds,
  )) as [number, number];

  const [current, ttl] = result;
  const allowed = current <= limit;

  return {
    allowed,
    current,
    remaining: Math.max(limit - current, 0),
    retryAfterSeconds: Math.max(ttl, 0),
  };
};
```

调用：

```TypeScript
import { checkFixedWindowRateLimit } from '../redis/rate-limit.js';

const main = async (): Promise<void> => {
  const rateLimitResult = await checkFixedWindowRateLimit('127.0.0.1', {
    action: 'login',
    limit: 5,

  });

  if (!rateLimitResult.allowed) {
    console.log('Too many requests:', rateLimitResult);
    return;
  }

};
```

### 分布式锁：防止热点缓存击穿

适用场景：

```Bash
热点缓存失效
  ↓
多个 Node.js 实例同时发现缓存未命中
  ↓
只允许一个实例查询数据库并重建缓存
  ↓
其他实例等待或短暂返回旧数据
```

```Bash
生成随机 token 代表锁持有者
  ↓
SET lockKey token NX PX lockTtl
  ↓
加锁失败，直接返回 false
  ↓
执行业务逻辑
  ↓
finally 中执行 Lua：
  仅当当前锁 value 等于 token 时才 DEL
```

```TypeScript
// src/redis/lock.ts
import { randomUUID } from 'node:crypto';
import { redis } from './client.js';

const releaseLockLua = `
  if redis.call("GET", KEYS[1]) == ARGV[1] then
    return redis.call("DEL", KEYS[1])
  end

  return 0
`;

type Lock = {
  key: string;
  token: string;
};

/**
 * 加锁
 */
export const acquireLock = async (
  lockKey: string,
  ttlMilliseconds: number,
): Promise<Lock | null> => {
  const token = randomUUID();

  const result = await redis.set(
    lockKey,
    token,
    'PX',
    ttlMilliseconds,
    'NX',
  );

  if (result !== 'OK') {
    return null;
  }

  return {
    key: lockKey,
    token,
  };
};

/**
 * 释放锁
 */
export const releaseLock = async (lock: Lock): Promise<boolean> => {
  const result = await redis.eval(
    releaseLockLua,
    1,
    lock.key,
    lock.token,
  );

  return result === 1;
};

/**
 * 判断分布式锁执行某函数
 */
export const withLock = async <T>(
  lockKey: string,
  ttlMilliseconds: number,
  callback: () => Promise<T>,
): Promise<{ acquired: boolean; value?: T }> => {
  const lock = await acquireLock(lockKey, ttlMilliseconds);

  if (!lock) {
    return {
      acquired: false,
    };
  }

  try {
    const value = await callback();

    return {
      acquired: true,
      value,
    };
  } finally {
    await releaseLock(lock);
  }
};
```

### Pub/Sub：实时通知、WebSocket 广播

Pub/Sub 特点：

- 发布者发送消息后不会保存。

- 订阅者离线时会丢失消息。

- 不支持确认、重试、消费进度。

- 适合在线通知、WebSocket 广播、临时事件。

- 不适合订单、支付、邮件等可靠任务。

```Bash
普通 Redis 客户端负责 PUBLISH
  ↓
创建 duplicated Redis 客户端
  ↓
订阅客户端只负责 SUBSCRIBE
  ↓
收到消息后解析 JSON
  ↓
转发给 WebSocket 或执行实时通知逻辑
```

```TypeScript
// src/redis/pubsub.ts

import { redis } from './client.js';

/**
 * 事件处理器类型。
 *
 * T 表示事件负载（payload）的类型。
 *
 * 处理器既可以是同步函数：
 * (payload) => { ... }
 *
 * 也可以是异步函数：
 * async (payload) => { await ... }
 */
type EventHandler<T> = (payload: T) => void | Promise<void>;

/**
 * 创建一个专门用于 Redis Pub/Sub 的连接。
 *
 * 不能直接使用普通 redis 客户端订阅频道：
 * Redis 连接执行 SUBSCRIBE 后会进入“订阅模式”，此时不能再正常执行
 * GET、SET、DEL、HGETALL 等普通 Redis 命令。
 *
 * redis           -> 普通 Redis 命令、发布消息（PUBLISH）
 * redisSubscriber -> 订阅频道、接收消息（SUBSCRIBE）
 */
export const redisSubscriber = redis.duplicate();

/**
 * 保存每个频道对应的事件处理器。
 *
 * 数据结构：
 *
 * Map<
 *   channelName,
 *   Set<handler>
 * >
 *
 * 示例：
 *
 * {
 *   "order:created": Set([
 *     handleCreateOrderNotification,
 *     handleCreateOrderStatistics,
 *   ]),
 *   "cache:invalidate": Set([
 *     handleInvalidateLocalCache,
 *   ]),
 * }
 *
 * 使用 Set 而不是数组：
 * - 同一个函数不会被重复注册；
 * - 删除处理器时效率更高；
 * - 可以判断一个频道是否仍然有处理器。
 *
 * 这里使用 unknown，是因为不同频道可以有不同的 payload 类型。
 * 在 subscribeEvent<T> 中通过泛型约束调用方的类型。
 */
const eventHandlers = new Map<string, Set<EventHandler<unknown>>>();

/**
 * 监听订阅连接本身的错误。
 *
 * 可能出现的错误包括：
 * - Redis 服务不可用；
 * - 网络连接中断；
 * - Redis 身份认证失败；
 * - DNS 解析失败；
 * - 重连失败。
 *
 * 对 EventEmitter 而言，监听 error 事件很重要；
 * 若没有 error 监听器，某些错误可能导致 Node.js 进程异常退出。
 */
redisSubscriber.on('error', (error) => {
  console.error('[Redis Subscriber] Connection error:', error);
});

/**
 * 只注册一次全局 message 监听器。
 *
 * ioredis 收到 Redis Pub/Sub 消息时，会触发：
 *
 * redisSubscriber.on('message', (channel, message) => {})
 *
 * - channel：实际收到消息的频道名称
 * - message：发布者发送的原始字符串
 *
 * 注意：
 * 不应在每次 subscribeEvent() 调用时重复注册 message 监听器，
 * 否则会造成监听器累积、消息重复处理，甚至触发
 * MaxListenersExceededWarning。
 */
redisSubscriber.on('message', (channel, message) => {
  // 获取该频道注册的所有业务处理器。
  const handlers = eventHandlers.get(channel);

  // 没有处理器时直接忽略。
  //
  // 正常情况下不会进入这里；但在取消订阅、重连或消息到达时序特殊时，
  // 仍可能出现，因此需要安全处理。
  if (!handlers || handlers.size === 0) {
    return;
  }

  let payload: unknown;

  try {
    /**
     * publishEvent() 使用 JSON.stringify 序列化 payload，
     * 因此接收方在此使用 JSON.parse 还原。
     *
     * 若消息不是合法 JSON，JSON.parse 会抛出异常。
     */
    payload = JSON.parse(message);
  } catch (error) {
    console.error('[Redis Subscriber] Invalid JSON message:', {
      channel,
      message,
      error,
    });
    return;
  }

  /**
   * 为每个处理器分发消息。
   *
   * 不使用 await：
   * - 某一个慢处理器不应阻塞其他处理器；
   * - 不应阻塞 Redis 后续消息的接收回调。
   *
   * 使用 Promise.resolve()：
   * - 同时兼容同步和异步 handler；
   * - 若 handler 抛出同步异常，也会转换为 rejected Promise。
   *
   * 使用 .catch()：
   * - 防止异步 handler 的异常成为未处理 Promise rejection；
   * - 一个 handler 失败不影响其他 handler。
   */
  for (const handler of handlers) {
    void Promise.resolve(handler(payload)).catch((error) => {
      console.error('[Redis Subscriber] Failed to handle message:', {
        channel,
        payload,
        error,
      });
    });
  }
});

/**
 * 发布一个 Redis Pub/Sub 事件。
 *
 * @param channel - Redis 频道名称，例如 "order:created"
 * @param payload - 要发送的任意可 JSON 序列化的数据
 * @returns 当前成功接收到该消息的订阅者数量
 *
 * 注意：
 * 返回 0 不表示发布失败，只表示发布当刻没有客户端订阅该频道。
 *
 * Redis Pub/Sub 不保存离线消息：
 * 若没有订阅者在线，消息会直接丢失。
 */
export const publishEvent = async <T>(
  channel: string,
  payload: T,
): Promise<number> => {
  /**
   * Redis Pub/Sub 的消息内容是字符串 / 二进制数据。
   *
   * 因此对象、数组、布尔值等 JavaScript 数据需要先转换为 JSON 字符串。
   */
  const message = JSON.stringify(payload);

  /**
   * 等价 Redis 命令：
   *
   * PUBLISH <channel> <message>
   *
   * 返回值是当前订阅者数量。
   */
  return redis.publish(channel, message);
};

/**
 * 订阅某一个频道，并注册对应的事件处理器。
 *
 * @param channel - Redis 频道名称，例如 "order:created"
 * @param handler - 收到消息后执行的业务处理函数
 * @returns 一个异步取消订阅函数
 *
 * @example
 * const unsubscribe = await subscribeEvent<{ orderId: string }>(
 *   'order:created',
 *   async ({ orderId }) => {
 *     await sendOrderCreatedNotification(orderId);
 *   },
 * );
 *
 * // 应用关闭或不再需要监听时：
 * await unsubscribe();
 */
export const subscribeEvent = async <T>(
  channel: string,
  handler: EventHandler<T>,
): Promise<() => Promise<void>> => {
  /**
   * 由于 eventHandlers 用 unknown 统一存储不同频道的处理器，
   * 此处需要进行类型转换。
   *
   * 类型安全由 subscribeEvent<T>() 的调用方保证：
   *
   * subscribeEvent<OrderCreatedEvent>(
   *   'order:created',
   *   (payload) => { ... },
   * );
   */
  const typedHandler = handler as EventHandler<unknown>;

  // 查找该频道是否已被订阅并已有处理器。
  const existingHandlers = eventHandlers.get(channel);

  if (existingHandlers) {
    /**
     * 该频道已经订阅过 Redis。
     *
     * 此时无需重复执行 SUBSCRIBE，只要把新处理器加入 Set。
     * Set 会自动避免同一个函数引用被重复添加。
     */
    existingHandlers.add(typedHandler);
  } else {
    /**
     * 这是本进程首次监听该频道：
     *
     * 1. 先记录处理器；
     * 2. 再向 Redis 发起 SUBSCRIBE。
     *
     * 这样全局 message 监听器收到该频道消息时，
     * 能够通过 eventHandlers 找到对应业务处理器。
     */
    eventHandlers.set(channel, new Set([typedHandler]));

    try {
      /**
       * 等价 Redis 命令：
       *
       * SUBSCRIBE <channel>
       */
      await redisSubscriber.subscribe(channel);
    } catch (error) {
      /**
       * 订阅失败时回滚内存状态。
       *
       * 否则 eventHandlers 虽然记录了频道，
       * 但 Redis 实际没有订阅成功，后续调用会误认为已订阅。
       */
      eventHandlers.delete(channel);

      console.error('[Redis Subscriber] Failed to subscribe:', {
        channel,
        error,
      });

      throw error;
    }
  }

  /**
   * 返回取消订阅函数。
   *
   * 它只移除“当前调用注册的 handler”，
   * 不会影响同一频道中其他模块注册的处理器。
   */
  const unsubscribe = async (): Promise<void> => {
    const handlers = eventHandlers.get(channel);

    // 频道已不存在，说明已取消订阅或清理完成，直接返回。
    if (!handlers) {
      return;
    }

    // 从当前频道的处理器集合中移除当前 handler。
    handlers.delete(typedHandler);

    /**
     * 如果仍有其他业务处理器监听这个频道，
     * 则保持 Redis SUBSCRIBE 状态。
     */
    if (handlers.size > 0) {
      return;
    }

    /**
     * 没有任何处理器继续监听该频道：
     *
     * 1. 移除内存映射；
     * 2. 向 Redis 取消订阅，释放不必要的频道监听。
     */
    eventHandlers.delete(channel);

    try {
      /**
       * 等价 Redis 命令：
       *
       * UNSUBSCRIBE <channel>
       */
      await redisSubscriber.unsubscribe(channel);
    } catch (error) {
      /**
       * 这里记录错误但不重新抛出。
       *
       * 原因是本地已经不再有该频道的处理器；
       * 即便 Redis 侧取消订阅失败，也不会再有业务逻辑处理该消息。
       *
       * 若订阅连接断开并重连，ioredis 通常会依据其订阅状态处理恢复；
       * 具体行为应结合 ioredis 版本和重连配置验证。
       */
      console.error('[Redis Subscriber] Failed to unsubscribe:', {
        channel,
        error,
      });
    }
  };

  return unsubscribe;
};
```

使用示例：

```TypeScript

  userId: string;

  'order:created',
```

```TypeScript
const streamKey = 'stream:order-created';
const groupName = 'order-service';
const consumerName = `worker-${process.pid}`;

type StreamFields = Record<string, string>;

const fieldsToObject = (fields: string[]): StreamFields => {
  const result: StreamFields = {};

  for (let index = 0; index < fields.length; index += 2) {
    result[fields[index]] = fields[index + 1];
  }

  return result;
};

const processOrderCreated = async (
  eventId: string,
  fields: StreamFields,
): Promise<void> => {
  console.log('Processing event:', eventId, fields);

  // 真实业务示例：
  // 1. 创建订单通知
  // 2. 扣减积分
  // 3. 发放优惠券
  // 4. 写入业务数据库
};

const consumeMessages = async (): Promise<void> => {
  while (true) {
    const results = await redis.xreadgroup(
      'GROUP',
      groupName,
      consumerName,
      'COUNT',
      10,
      'BLOCK',
      5_000,
      'STREAMS',
      streamKey,
      '>',
    );

    if (!results) {
      continue;
    }

    for (const [, messages] of results) {
      for (const [eventId, fields] of messages) {
        try {
          await processOrderCreated(eventId, fieldsToObject(fields));

          // 只有业务处理完成后才确认消息
          await redis.xack(streamKey, groupName, eventId);
        } catch (error) {
          console.error(`Failed to process event ${eventId}:`, error);

          // 不执行 XACK，消息会留在 Pending Entries List 中，
          // 后续可通过 XAUTOCLAIM 等方式重新认领。
        }
      }
    }
  }
};

void consumeMessages();
```

### Pipeline：批量执行减少网络往返

适合批量读取或写入多个独立 Key。

```JavaScript
import { redis } from '../redis/client.js';

const main = async (): Promise<void> => {
  const pipeline = redis.pipeline();

  pipeline.set('user:1001:name', 'Alice');
  pipeline.set('user:1002:name', 'Bob');
  pipeline.incr('article:view-count:2001');
  pipeline.expire('user:1001:name', 60);

  const results = await pipeline.exec();

  if (!results) {
    return;
  }

  for (const [error, result] of results) {
    if (error) {
      console.error('Pipeline command failed:', error);
      continue;
    }

    console.log('Pipeline result:', result);
  }
};

void main();
```

注意：

- Pipeline 是减少网络往返，不是事务。

- 命令会依次发给 Redis，但某个命令失败不代表其他命令自动回滚。

- 需要事务语义时学习 `MULTI` / `EXEC`，需要复杂原子逻辑时优先 Lua。

### 事务：MULTI / EXEC

适用于简单的多命令顺序执行。

```TypeScript
import { redis } from '../redis/client.js';

const transferPoints = async (
  fromUserId: string,
  toUserId: string,
  points: number,
): Promise<void> => {
  const fromUserKey = `user:points:${fromUserId}`;
  const toUserKey = `user:points:${toUserId}`;

  const currentPoints = Number(await redis.get(fromUserKey) ?? 0);

  if (currentPoints < points) {
    throw new Error('Insufficient points');
  }

  await redis
    .multi()
    .decrby(fromUserKey, points)
    .incrby(toUserKey, points)
    .exec();
};
```

注意：上述代码中“查余额”和“扣积分”不是完整原子操作。

高并发积分扣减应使用 Lua：

```TypeScript
import { redis } from '../redis/client.js';

const transferPointsLua = `
  local fromBalance = tonumber(redis.call("GET", KEYS[1]) or "0")
  local points = tonumber(ARGV[1])

  if fromBalance < points then
    return {0, fromBalance}
  end

  redis.call("DECRBY", KEYS[1], points)
  redis.call("INCRBY", KEYS[2], points)

  return {1, fromBalance - points}
`;

export const transferPointsAtomically = async (
  fromUserId: string,
  toUserId: string,
  points: number,
): Promise<{ success: boolean; remainingPoints: number }> => {
  if (points <= 0) {
    throw new Error('Points must be greater than 0');
  }

  const result = (await redis.eval(
    transferPointsLua,
    2,
    `user:points:${fromUserId}`,
    `user:points:${toUserId}`,
    points,
  )) as [number, number];

  const [success, remainingPoints] = result;

  return {
    success: success === 1,
    remainingPoints,
  };
};
```

```TypeScript
// src/redis/client.ts
import Redis from 'ioredis';
import { redisConfig } from './redis.config.js';
import {
  redisClientConnectionState,
  redisClientErrorsTotal,
  redisClientReconnectsTotal,
} from './metrics.js';

/**
 * 重试策略
 */
const getReconnectDelay = (retryCount: number): number | null => {
  if (retryCount > redisConfig.maxReconnectRetries) {
    return null;
  }

  const exponentialDelay = redisConfig.retryBaseDelayMs * 2 ** (retryCount - 1);
  const maxDelayMs = 5_000;
  const jitterMs = Math.floor(Math.random() * 100);

  return Math.min(exponentialDelay, maxDelayMs) + jitterMs;
};

export const redis = new Redis(redisConfig.url, {
  // **启动连接超时**
  connectTimeout: redisConfig.connectTimeoutMs,
  
  // **命令执行超时**
  commandTimeout: redisConfig.commandTimeoutMs,

  // **Redis 不可用时，缓存类请求应快速失败并降级，**
  // 不应在 Node.js 内存中无限积压命令。
  enableOfflineQueue: false,

  // 一般 HTTP API 可设置为 1~3。
  // 对“绝不能重复执行”的非幂等写操作，应在业务层使用幂等键，
  // 或为该场景单独创建 maxRetriesPerRequest: 0 的客户端。
  maxRetriesPerRequest: 1,

  // **重试策略**
  retryStrategy: getReconnectDelay,

  // **报错时是否重新连接**
  reconnectOnError: (error) => {
    const reconnectableErrors = [
      'READONLY',
      'ECONNRESET',
      'ETIMEDOUT',
    ];

    const shouldReconnect = reconnectableErrors.some((message) =>
      error.message.includes(message),
    );

    return shouldReconnect;
  },

  // 
  // 避免在客户端连接建立后自动执行 readonly。
  // 主从读写分离应通过专用架构和客户端配置实现。
  showFriendlyErrorStack: process.env.NODE_ENV !== 'production',
});

const updateConnectionState = (state: 0 | 1): void => {
  redisClientConnectionState.set(state);
};

redis.on('connect', () => {
  console.info('[Redis] TCP connected');
});

redis.on('ready', () => {
  updateConnectionState(1);
  console.info('[Redis] Client ready');
});

redis.on('reconnecting', (delayMilliseconds: number) => {
  updateConnectionState(0);
  redisClientReconnectsTotal.inc();

  console.warn('[Redis] Reconnecting', {
    delayMilliseconds,
  });
});

redis.on('close', () => {
  updateConnectionState(0);
  console.warn('[Redis] Connection closed');
});

redis.on('end', () => {
  updateConnectionState(0);
  console.warn('[Redis] Connection ended');
});

redis.on('error', (error) => {
  updateConnectionState(0);

  redisClientErrorsTotal.inc({
    code: error.code ?? 'UNKNOWN',
  });

  // 不要记录 Redis URL、密码、完整业务数据或完整 Key。
  console.error('[Redis] Client error', {
    name: error.name,
    code: error.code,
    message: error.message,
  });
});

export const connectRedis = async (): Promise<void> => {
  if (redis.status === 'ready' || redis.status === 'connecting') {
    return;
  }

  await redis.connect();
};

export const disconnectRedis = async (): Promise<void> => {
  if (redis.status === 'end') {
    return;
  }

  await redis.quit();
};
```

#### 为缓存操作增加命中率、延迟、失败监控

```Plain Text
执行 GET：
  开始计时
  ↓
  Redis 返回空值：记录 miss 和耗时
  Redis 返回数据：记录 hit 和耗时
  Redis 异常：记录 error、耗时、fallback
  ↓
  返回数据或 null

执行 SET / DEL：
  开始计时
  ↓
  成功：记录 success 和耗时
  失败：记录 error 和耗时
  ↓
  缓存写入失败通常不阻塞主要业务
```

```TypeScript
// src/redis/cache.ts
import { redis } from './client.js';
import {
  redisCacheRequestsTotal,
  redisCommandDurationSeconds,
  redisFallbackTotal,
} from './metrics.js';

const getElapsedSeconds = (startTime: bigint): number => {
  return Number(process.hrtime.bigint() - startTime) / 1_000_000_000;
};

export const getJsonCache = async <T>(key: string): Promise<T | null> => {
  const startTime = process.hrtime.bigint();

  try {
    const serializedValue = await redis.get(key);

    if (!serializedValue) {
      redisCacheRequestsTotal.inc({
        operation: 'get',
        result: 'miss',
      });

      redisCommandDurationSeconds.observe(
        {
          operation: 'get',
          result: 'miss',
        },
        getElapsedSeconds(startTime),
      );

      return null;
    }

    const parsedValue = JSON.parse(serializedValue) as T;

    redisCacheRequestsTotal.inc({
      operation: 'get',
      result: 'hit',
    });

    redisCommandDurationSeconds.observe(
      {
        operation: 'get',
        result: 'hit',
      },
      getElapsedSeconds(startTime),
    );

    return parsedValue;
  } catch (error) {
    redisCacheRequestsTotal.inc({
      operation: 'get',
      result: 'error',
    });

    redisCommandDurationSeconds.observe(
      {
        operation: 'get',
        result: 'error',
      },
      getElapsedSeconds(startTime),
    );

    redisFallbackTotal.inc({
      operation: 'cache_get',
    });

    console.error('[Redis Cache] GET failed', {
      message: error instanceof Error ? error.message : 'Unknown error',
    });

    // Redis 是缓存时，读取失败应降级为缓存未命中。
    return null;
  }
};

export const setJsonCache = async <T>(
  key: string,
  value: T,
  ttlSeconds: number,
): Promise<void> => {
  const startTime = process.hrtime.bigint();

  try {
    await redis.set(key, JSON.stringify(value), 'EX', ttlSeconds);

    redisCacheRequestsTotal.inc({
      operation: 'set',
      result: 'success',
    });

    redisCommandDurationSeconds.observe(
      {
        operation: 'set',
        result: 'success',
      },
      getElapsedSeconds(startTime),
    );
  } catch (error) {
    redisCacheRequestsTotal.inc({
      operation: 'set',
      result: 'error',
    });

    redisCommandDurationSeconds.observe(
      {
        operation: 'set',
        result: 'error',
      },
      getElapsedSeconds(startTime),
    );

    console.error('[Redis Cache] SET failed', {
      message: error instanceof Error ? error.message : 'Unknown error',
    });

    // 缓存写入失败通常仅记录日志和指标，不中断主业务。
  }
};

export const deleteCache = async (key: string): Promise<void> => {
  const startTime = process.hrtime.bigint();

  try {
    await redis.del(key);

    redisCacheRequestsTotal.inc({
      operation: 'delete',
      result: 'success',
    });

    redisCommandDurationSeconds.observe(
      {
        operation: 'delete',
        result: 'success',
      },
      getElapsedSeconds(startTime),
    );
  } catch (error) {
    redisCacheRequestsTotal.inc({
      operation: 'delete',
      result: 'error',
    });

    redisCommandDurationSeconds.observe(
      {
        operation: 'delete',
        result: 'error',
      },
      getElapsedSeconds(startTime),
    );

    // 注意：删除缓存失败会带来短暂数据不一致风险，
    // 此处至少必须告警，而不是静默忽略。
    console.error('[Redis Cache] DEL failed', {
      message: error instanceof Error ? error.message : 'Unknown error',
    });
  }
};
```

#### Redis 健康检查：Liveness 与 Readiness

健康检查不要只检查：

```TypeScript
redis.status === 'ready'
```

因为 TCP 连接可能仍然存在，但 Redis 已无法正常处理命令。

应实际执行一个带超时的 `PING`。

```TypeScript
// src/redis/health.ts
import { redis } from './client.js';
import { redisConfig } from './redis.config.js';
import { redisHealthCheckState } from './metrics.js';

const withTimeout = async <T>(
  promise: Promise<T>,
  timeoutMilliseconds: number,
): Promise<T> => {
  let timeoutId: NodeJS.Timeout | undefined;

  const timeoutPromise = new Promise<never>((_, reject) => {
    timeoutId = setTimeout(() => {
      reject(
        new Error(
          `Operation timed out after ${timeoutMilliseconds} milliseconds`,
        ),
      );
    }, timeoutMilliseconds);
  });

  try {
    return await Promise.race([promise, timeoutPromise]);
  } finally {
    if (timeoutId) {
      clearTimeout(timeoutId);
    }
  }
};

export const checkRedisHealth = async (): Promise<boolean> => {
  try {
    const result = await withTimeout(
      redis.ping(),
      redisConfig.healthCheckTimeoutMs,
    );

    const isHealthy = result === 'PONG';

    redisHealthCheckState.set(isHealthy ? 1 : 0);

    return isHealthy;
  } catch (error) {
    redisHealthCheckState.set(0);

    console.error('[Redis Health] Health check failed', {
      message: error instanceof Error ? error.message : 'Unknown error',
    });

    return false;
  }
};
```

Express 路由示例：

```JavaScript
// src/server.ts
import express from 'express';
import { connectRedis, disconnectRedis } from './redis/client.js';
import { checkRedisHealth } from './redis/health.js';
import { metricsRegistry } from './redis/metrics.js';

const app = express();

app.get('/health/live', (_request, response) => {
  response.status(200).json({
    status: 'ok',
  });
});

app.get('/health/ready', async (_request, response) => {
  const isRedisHealthy = await checkRedisHealth();

  if (!isRedisHealthy) {
    response.status(503).json({
      status: 'not_ready',
      dependencies: {
        redis: 'unavailable',
      },
    });

    return;
  }

  response.status(200).json({
    status: 'ready',
    dependencies: {
      redis: 'available',
    },
  });
});

// 此路由必须只允许 Prometheus、内网或受保护的管理网络访问。
app.get('/metrics', async (_request, response) => {
  response.setHeader('Content-Type', metricsRegistry.contentType);
  response.end(await metricsRegistry.metrics());
});

const port = Number(process.env.PORT ?? 3000);

const startServer = async (): Promise<void> => {
  await connectRedis();

  app.listen(port, () => {
    console.info(`Server started at http://127.0.0.1:${port}`);
  });
};

const handleShutdown = async (): Promise<void> => {
  await disconnectRedis();
  process.exit(0);
};

process.once('SIGINT', () => {
  void handleShutdown();
});

process.once('SIGTERM', () => {
  void handleShutdown();
});

void startServer();
```

健康检查语义：

|**路由**|**含义**|**Redis 故障时**|
|---|---|---|
|/health/live|Node 进程是否活着|通常仍返回 200|
|/health/ready|当前实例是否可接收流量|返回 503|
|/metrics|Prometheus 指标抓取|不作为业务健康接口|

是否让 Redis 故障导致 `/health/ready` 返回 503，要根据 Redis 的角色决定：

```Markdown
Redis 仅作普通缓存：
- 可以仍然 ready
- 业务降级到数据库
- 但必须告警

Redis 用于 Session、限流、分布式锁、队列：
- Redis 不可用通常应 not ready
- 因为认证或关键业务依赖 Redis
```

应用指标只能观察客户端行为；Redis 自身的内存、淘汰、命中率等状态，需要读取 `INFO`。

```TypeScript
// src/redis/info-metrics.ts
import { Gauge } from 'prom-client';
import { redis } from './client.js';
import { redisConfig } from './redis.config.js';
import { metricsRegistry } from './metrics.js';

const redisConnectedClients = new Gauge({
  name: 'redis_connected_clients',
  help: 'Number of connected Redis clients.',
  registers: [metricsRegistry],
});

const redisBlockedClients = new Gauge({
  name: 'redis_blocked_clients',
  help: 'Number of Redis blocked clients.',
  registers: [metricsRegistry],
});

const redisEvictedKeysTotal = new Gauge({
  name: 'redis_evicted_keys_total_snapshot',
  help: 'Current Redis evicted_keys value from INFO stats.',
  registers: [metricsRegistry],
});

const redisExpiredKeysTotal = new Gauge({
  name: 'redis_expired_keys_total_snapshot',
  help: 'Current Redis expired_keys value from INFO stats.',
  registers: [metricsRegistry],
});

const redisKeyspaceHitsTotal = new Gauge({
  name: 'redis_keyspace_hits_total_snapshot',
  help: 'Current Redis keyspace_hits value from INFO stats.',
  registers: [metricsRegistry],
});

const redisKeyspaceMissesTotal = new Gauge({
  name: 'redis_keyspace_misses_total_snapshot',
  help: 'Current Redis keyspace_misses value from INFO stats.',
  registers: [metricsRegistry],
});

const redisOperationsPerSecond = new Gauge({
  name: 'redis_operations_per_second',
  help: 'Redis instantaneous operations per second.',
  registers: [metricsRegistry],
});

const parseRedisInfo = (infoText: string): Record<string, string> => {
  const result: Record<string, string> = {};

  for (const line of infoText.split('\r\n')) {
    if (!line || line.startsWith('#')) {
      continue;
    }

    const separatorIndex = line.indexOf(':');

    if (separatorIndex === -1) {
      continue;
    }

    const key = line.slice(0, separatorIndex);
    const value = line.slice(separatorIndex + 1);

    result[key] = value;
  }

  return result;
};

const toNumber = (value: string | undefined): number => {
  const parsedValue = Number(value);

  return Number.isFinite(parsedValue) ? parsedValue : 0;
};

export const collectRedisInfoMetrics = async (): Promise<void> => {
  try {
    const [memoryInfo, clientsInfo, statsInfo] = await Promise.all([
      redis.info('memory'),
      redis.info('clients'),
      redis.info('stats'),
    ]);

    const memory = parseRedisInfo(memoryInfo);
    const clients = parseRedisInfo(clientsInfo);
    const stats = parseRedisInfo(statsInfo);

    redisMemoryUsedBytes.set(toNumber(memory.used_memory));
    redisMemoryMaxBytes.set(toNumber(memory.maxmemory));

    redisConnectedClients.set(toNumber(clients.connected_clients));
    redisBlockedClients.set(toNumber(clients.blocked_clients));

    redisEvictedKeysTotal.set(toNumber(stats.evicted_keys));
    redisExpiredKeysTotal.set(toNumber(stats.expired_keys));
    redisKeyspaceHitsTotal.set(toNumber(stats.keyspace_hits));
    redisKeyspaceMissesTotal.set(toNumber(stats.keyspace_misses));
    redisOperationsPerSecond.set(
      toNumber(stats.instantaneous_ops_per_sec),
    );
  } catch (error) {
    console.error('[Redis Metrics] Failed to collect INFO metrics', {
      message: error instanceof Error ? error.message : 'Unknown error',
    });
  }
};

export const startRedisInfoMetricsCollector = (): NodeJS.Timeout => {
  void collectRedisInfoMetrics();

  return setInterval(() => {
    void collectRedisInfoMetrics();
  }, redisConfig.metricsIntervalMs);
};
```

Redis 慢日志由 Redis 服务端记录，不是 ioredis 自动提供的。

```Markdown

# 单位：微秒。10000 = 10ms。
slowlog-log-slower-than 10000

# 最多保留 1024 条慢日志。
slowlog-max-len 1024
```

查看慢日志：

```Bash

```

Node 中可定期检查：

```TypeScript
// src/redis/slowlog.ts
import { Counter, Gauge } from 'prom-client';
import { redis } from './client.js';
import { metricsRegistry } from './metrics.js';

const redisSlowLogLength = new Gauge({
  name: 'redis_slowlog_length',
  help: 'Current number of entries in Redis SLOWLOG.',
  registers: [metricsRegistry],
});

const redisSlowCommandsTotal = new Counter({
  name: 'redis_slow_commands_total',
  help: 'Total number of newly detected Redis slow commands.',
  labelNames: ['command'] as const,
  registers: [metricsRegistry],
});

type RedisSlowLogEntry = [
  id: number,
  timestamp: number,
  durationMicroseconds: number,
  command: string[],
  clientAddress: string,
  clientName: string,
];

let latestSlowLogId = 0;

const sanitizeCommandName = (command: string[] | undefined): string => {
  const commandName = command?.[0]?.toLowerCase();

  return commandName || 'unknown';
};

export const collectRedisSlowLogMetrics = async (): Promise<void> => {
  try {
    const slowLogLength = await redis.slowlog('LEN');

    redisSlowLogLength.set(Number(slowLogLength));

    const entries = (await redis.slowlog(
      'GET',
      128,
    )) as RedisSlowLogEntry[];

    for (const entry of entries) {
      const [id, , , command] = entry;

      if (id <= latestSlowLogId) {
        continue;
      }

      redisSlowCommandsTotal.inc({
        command: sanitizeCommandName(command),
      });

      latestSlowLogId = Math.max(latestSlowLogId, id);
    }
  } catch (error) {
    console.error('[Redis Metrics] Failed to collect SLOWLOG', {
      message: error instanceof Error ? error.message : 'Unknown error',
    });
  }
};
```

注意：

- 不要将完整慢命令参数作为 Prometheus Label。

- 例如 `GET auth:session:xxx` 中的完整 Key 不能进入 Label。

- 只记录命令类型：`get`、`hgetall`、`zrange`、`eval` 等。

- 若频繁出现 `KEYS`、`HGETALL`、`SMEMBERS`、`LRANGE 0 -1` 等慢命令，需要重点排查 Big Key 和错误查询方式。

#### 推荐使用 redis\_exporter 采集 Redis 服务指标

生产环境中，Redis 服务自身指标建议由 `redis_exporter` 采集，而不是让每个 Node 实例周期性执行 `INFO`。

原因：

```Bash
Node 实例有多个时：
每个实例都采集 INFO
  ↓
对 Redis 产生重复监控流量
  ↓
指标也会重复，不适合统一监控

redis_exporter：
一个 exporter 统一采集 Redis
  ↓
Prometheus 定时抓取 exporter
  ↓
Grafana 统一展示和告警
```

#### 核心 Grafana 监控面板

至少应创建以下面板。

---

##### Redis 可用性

PromQL： `redis_up`。

告警条件：`redis_up == 0`。

持续：1 分钟。

---

##### Redis 内存使用率

```Markdown
redis_memory_used_bytes / redis_memory_max_bytes
```

注意：如果没有配置 `maxmemory`，`maxmemory` 可能是 `0`，该公式无意义。

告警建议：

```Markdown
Warning: 内存使用率 > 75%，持续 10 分钟
Critical: 内存使用率 > 90%，持续 5 分钟
```

---

##### Key 淘汰速率

只要 Redis 作为缓存，淘汰不一定完全错误；但突然增长通常意味着内存不足、TTL 策略错误或缓存写入异常。

```Markdown
rate(redis_evicted_keys_total[5m])
```

告警建议：

```Markdown
rate(redis_evicted_keys_total[5m]) > 0
持续 5 分钟
```

如果你要求“缓存不能被淘汰”，应使用：

```Markdown
maxmemory-policy noeviction
```

并在写入失败前进行内存告警。

---

##### Redis 缓存命中率

若使用 `redis_exporter`：

```Bash
rate(redis_keyspace_hits_total[5m])
/
(
  rate(redis_keyspace_hits_total[5m])
  +
  rate(redis_keyspace_misses_total[5m])
)
```

若分母为 0，查询可能返回空结果；可根据 Grafana 表达式处理。

告警建议不能一概而论：

```Markdown
缓存命中率低不一定是故障：
- 冷启动
- 新功能发布
- Key 设计变化
- 流量结构变化

应结合数据库 QPS、Redis QPS、接口延迟一起判断。
```

---

##### Redis 连接数

```Markdown
redis_connected_clients
```

需要结合 Redis 配置：

```Markdown
maxclients 10000
```

告警示例：

```Markdown
redis_connected_clients / 10000 > 0.8
```

---

##### Redis 命令延迟 P99

应用侧 `ioredis` 操作延迟：

```Bash
histogram_quantile(
  0.99,
  sum(
    rate(redis_command_duration_seconds_bucket[5m])
  ) by (le, operation)
)
```

重点观察：

```Bash
get
set
delete
eval
xreadgroup
```

建议告警：

```Bash
P99 > 100ms，持续 5 分钟
```

具体阈值需结合网络、Redis 部署区域、业务 SLA 调整。

##### Node 应用 Redis 降级次数

```Bash
sum(rate(redis_fallback_total[5m])) by (operation)
```

如果 Redis 是缓存，出现少量降级不一定立刻中断服务，但应重点关注：

```Bash
缓存降级增加
  +
数据库 QPS 增加
  +
接口响应时间上升

可能正在发生缓存故障或雪崩
```

#### Prometheus 告警规则示例

```YAML
# redis-alerts.yml
groups:
  - name: redis-alerts
    rules:
      - alert: RedisUnavailable
        expr: redis_up == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: Redis is unavailable
          description: Redis exporter cannot connect to Redis for more than 1 minute.

      - alert: RedisMemoryUsageHigh
        expr: |
          redis_memory_max_bytes > 0
          and
          redis_memory_used_bytes / redis_memory_max_bytes > 0.85
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: Redis memory usage is high
          description: Redis memory usage is above 85% for 10 minutes.

      - alert: RedisEvictionsDetected
        expr: rate(redis_evicted_keys_total[5m]) > 0
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: Redis key eviction detected
          description: Redis is evicting keys because memory capacity may be insufficient.

      - alert: RedisClientReconnectsHigh
        expr: rate(redis_client_reconnects_total[5m]) > 1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: Redis client reconnects are frequent
          description: Node.js application Redis clients are reconnecting frequently.

      - alert: RedisClientErrorRateHigh
        expr: rate(redis_client_errors_total[5m]) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: Redis client error rate is high
          description: Redis client errors exceed 0.1 per second.

      - alert: RedisCommandLatencyP99High
        expr: |
          histogram_quantile(
            0.99,
            sum(rate(redis_command_duration_seconds_bucket[5m])) by (le)
          ) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: Redis command P99 latency is high
          description: Redis command P99 latency is above 100ms for 5 minutes.
```

#### Redis 服务端推荐配置

以下是一个偏通用的生产配置方向，具体数值必须根据机器内存、Redis 用途和业务特点调整。

```Markdown
# redis.conf

# 不允许公网直接访问 Redis。
bind 127.0.0.1 10.0.0.0/8
protected-mode yes

# 使用 ACL，避免只依赖默认用户密码。
aclfile /etc/redis/users.acl

# 内存上限：不能直接等于机器总内存。
# 要为 OS、AOF rewrite、复制缓冲区等预留空间。
maxmemory 4gb

# 纯缓存场景通常可考虑 LFU。
# Session、队列、重要状态场景不能盲目依赖淘汰。
maxmemory-policy allkeys-lfu

# AOF 持久化。
appendonly yes
appendfsync everysec

# 慢日志：超过 10ms 的命令记录。
slowlog-log-slower-than 10000
slowlog-max-len 1024

# 禁用或重命名高风险管理命令应结合运维方案处理。
# Redis 7+ 建议使用 ACL 精细限制用户命令权限。
```

不同用途的淘汰策略建议：

|**Redis 用途**|**常见策略**|
|---|---|
|纯接口缓存|allkeys\-lfu 或 allkeys\-lru|
|Session / 登录态|谨慎设置 maxmemory；不能依赖淘汰保证可用性|
|BullMQ / Stream 消息|不应因为内存不足随意淘汰任务数据|
|分布式锁|不应依赖淘汰；锁必须仅通过 TTL 控制|
|限流|必须设置 TTL；避免 Key 无限累积|

#### Redis Cluster 与 Sentinel 的监控补充

##### Redis Sentinel

除了监控主节点外，还应监控：

```Markdown
- Sentinel 是否存活
- 当前 master 是否切换
- slave 数量
- replication lag
- 主从复制链路状态
```

ioredis Sentinel 示例：

```TypeScript
import Redis from 'ioredis';

export const redis = new Redis({
  sentinels: [
    {
      host: 'sentinel-1.internal',
      port: 26379,
    },
    {
      host: 'sentinel-2.internal',
      port: 26379,
    },
    {
      host: 'sentinel-3.internal',
      port: 26379,
    },
  ],
  name: 'mymaster',
  sentinelPassword: process.env.REDIS_SENTINEL_PASSWORD,
  password: process.env.REDIS_PASSWORD,
  connectTimeout: 5_000,
  commandTimeout: 3_000,
  enableOfflineQueue: false,
  maxRetriesPerRequest: 1,
});
```

##### Redis Cluster

Cluster 需要监控：

```Markdown
- cluster_state 是否为 ok
- 是否发生 slot fail
- 各分片内存是否均衡
- 各节点 QPS 是否均衡
- 是否出现 Hot Key
- 主从复制延迟
```

ioredis Cluster 示例：

```TypeScript
import { Cluster } from 'ioredis';

export const redisCluster = new Cluster(
  [
    {
      host: 'redis-cluster-1.internal',
      port: 6379,
    },
    {
      host: 'redis-cluster-2.internal',
      port: 6379,
    },
    {
      host: 'redis-cluster-3.internal',
      port: 6379,
    },
  ],
  {
    redisOptions: {
      password: process.env.REDIS_PASSWORD,
      connectTimeout: 5_000,
      commandTimeout: 3_000,
      enableOfflineQueue: false,
      maxRetriesPerRequest: 1,
    },

    clusterRetryStrategy: (retryCount) => {
      if (retryCount > 10) {
        return null;
      }

      return Math.min(200 * retryCount, 2_000);
    },
  },
);
```

#### 最终生产检查清单

```Markdown
客户端配置
[ ] Redis Client 是应用级单例，不在每个请求中 new Redis()
[ ] 设置 connectTimeout 和 commandTimeout
[ ] 配置有限重连与指数退避 + 随机抖动
[ ] 缓存场景使用 enableOfflineQueue: false
[ ] 正确监听 error、ready、close、reconnecting、end
[ ] 优雅处理 SIGTERM / SIGINT 并 quit()

应用指标
[ ] 暴露受保护的 /metrics
[ ] 统计 Redis 错误、重连、操作耗时
[ ] 统计缓存 hit / miss / error
[ ] 统计 Redis 不可用时的业务降级次数
[ ] 不以完整 key、userId、token 作为 Prometheus Label

Redis 服务监控
[ ] 部署 redis_exporter 或使用云厂商监控
[ ] 监控 redis_up、内存、连接数、QPS、淘汰数
[ ] 监控 keyspace hit/miss、慢日志、复制状态
[ ] 配置 maxmemory 和合理的淘汰策略
[ ] 设置 SLOWLOG

告警
[ ] Redis 不可用
[ ] 内存使用率过高
[ ] evicted_keys 持续增加
[ ] 连接数接近 maxclients
[ ] 应用 Redis 重连频繁
[ ] Redis 命令 P99 延迟升高
[ ] 缓存降级导致数据库压力升高

安全
[ ] Redis 不暴露在公网
[ ] 使用 ACL 用户和强密码
[ ] 密码不提交到 Git
[ ] /metrics 不对公网匿名开放
[ ] 不使用 MONITOR 作为长期监控方案
```

核心原则是：

```Markdown
ioredis 事件监控应用连接状态；
prom-client 监控业务侧缓存行为；
redis_exporter 监控 Redis 服务本身；
Prometheus + Grafana + Alertmanager 负责统一展示和告警。
```
