# 权限、加密、审计、隐私与数据质量

数据库安全的目标是让主体只能以被允许的方式访问必要数据，并让高风险操作可追溯、数据泄露后影响受限。治理则覆盖数据从采集到删除的生命周期和可信度。

## 威胁与控制

| 风险 | 首要控制 | 控制不了什么 |
| --- | --- | --- |
| 凭证泄露 | Secret 托管、短期凭证、轮换、网络隔离 | 已拥有该角色权限的滥用 |
| 越权访问 | 最小权限、职责分离、应用对象级授权 | 合法权限读取后的外泄 |
| 网络窃听 | TLS 与证书校验 | 端点或应用进程被攻破 |
| 磁盘/备份泄露 | 静态加密、独立密钥与访问控制 | 在线数据库通过合法接口泄露 |
| SQL 注入 | 参数化查询、标识符白名单、低权限账户 | 业务授权逻辑缺陷 |
| 误操作 | 审批、审计、备份/PITR、Blast Radius 限制 | 未演练的恢复流程 |
| 隐私与质量问题 | 数据分级、最小化、生命周期、约束与对账 | 所有权和责任人不明确 |

安全依赖纵深防御：私网或受控网络入口、强认证、最小数据库权限、应用授权、加密和审计同时存在。仅启用某个“安全功能”不能抵消共享超级账号或公网暴露。

## 数据面与控制面

数据面包括业务查询、写入、备份和导出；控制面包括建库、DDL、角色、复制和配置。业务账户不应拥有控制面权限，迁移、备份、分析与运维分别使用独立身份，详见 [[后端/数据库/10. 数据库安全与治理/3. 身份、权限与变更审计|身份与权限]]。

敏感数据的保护范围包括表、索引、日志、慢查询、错误堆栈、临时文件、快照、导出和下游副本。加密与密钥边界见 [[后端/数据库/10. 数据库安全与治理/4. TLS、加密与Secret管理|TLS、加密与 Secret 管理]]；采集、保留、删除和质量见 [[后端/数据库/10. 数据库安全与治理/2. 数据生命周期、合规与质量运营|数据生命周期与质量]]。

安全控制必须有可验证结果：权限审计能列出谁可读敏感表，轮换能证明旧凭证失效，删除流程能追踪下游副本，恢复演练能证明加密备份可解密。这里的验证对象是具体控制效果，而不是通用检查表。
