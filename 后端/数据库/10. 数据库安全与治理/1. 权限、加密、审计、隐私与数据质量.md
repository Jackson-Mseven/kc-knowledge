# 权限、加密、审计、隐私与数据质量

数据库安全不仅是防 SQL 注入，也包括身份、权限、密钥、传输、备份、审计和数据生命周期。治理目标是让数据可控、可追溯且长期可信。

## 最小权限

业务读写、迁移、分析、备份和运维使用不同账户。业务账号仅拥有需要的库、表和 DML 权限，不使用超级用户；生产数据库不应直接暴露公网。动态 SQL 的值必须参数化，标识符使用严格白名单，详见 [[后端/数据库/1. 关系模型与SQL/9. SQL 注入、参数化查询与动态 SQL 白名单|SQL 注入防护]]。

## 加密与 Secret

客户端到数据库启用 TLS；密码、证书和连接串由 Secret 管理系统托管并支持轮换；静态数据、备份和导出按敏感等级加密与访问控制。日志、慢查询、诊断转储也可能包含个人信息和凭证。

## 审计与隐私

审计 DDL、权限变更、敏感表读取和批量修改。生产数据用于测试或分析前需脱敏；数据保留、导出、删除和备份清理遵从适用的隐私与合规要求。软删除不等于完成合规删除，备份和下游副本也要纳入生命周期。

## 数据质量

用主键、唯一、外键、检查约束和 Schema 校验防止源头脏数据；通过定期对账、重复检测、分布监控和血缘记录发现下游问题。质量指标应明确准确性、完整性、唯一性、及时性和一致性定义。

## 面试自测

1. 为什么数据库权限不能替代应用授权？

数据库权限通常按服务角色而非终端用户授予，业务对象级权限仍需在服务层验证；两者应叠加。

2. 为什么测试环境也要治理数据？

测试环境权限和监控通常更弱，直接复制生产数据会扩大隐私与泄露风险。
