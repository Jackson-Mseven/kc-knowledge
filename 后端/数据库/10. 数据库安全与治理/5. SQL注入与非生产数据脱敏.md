# SQL 注入与非生产数据脱敏

SQL 注入发生在不可信输入被解释为 SQL 结构时；脱敏则降低数据离开生产控制域后的泄露影响。两者都不能只靠“使用 ORM”或替换部分字符解决。

## SQL 注入防护

值使用驱动的参数绑定，让 SQL 结构与数据分别传输。表名、列名、排序方向等标识符通常不能作为普通参数，必须由代码内固定映射选择；映射失败直接拒绝请求，不能回退为拼接用户输入或手工转义。

ORM 的 Raw Query、模板字符串、动态 Filter 和存储过程内部拼接仍可注入。数据库账户保持低权限并设置语句超时，可限制成功注入后的 Blast Radius，但不是参数化查询和输入校验的替代。

## 审计与日志脱敏

安全审计记录主体、来源、动作、对象、时间、结果和关联 ID；查询参数默认不记录原文敏感值。邮箱、手机号等可记录带密钥的 Hash 以支持关联调查，密钥与日志分离。慢查询、错误堆栈和 APM Span 同样可能泄露 SQL 参数，需要统一脱敏规则。

## 非生产数据策略

优先级从高到低是合成数据、按约束生成的子集、不可逆脱敏副本、受控 Tokenization。常见方法：

- Redaction 删除不需要的字段；
- Consistent Substitution 用稳定假值保持 Join 和唯一性；
- Generalization 把精确日期、位置等转换为区间；
- Tokenization 允许受控还原，Token Vault 属于高敏感系统；
- Shuffle 仅打乱单列容易破坏关联，也可能被外部数据重新识别，不能单独依赖。

脱敏必须保持主外键、唯一约束、格式和测试所需分布，同时破坏姓名、地址、证件号等字段间可重新识别的组合关系。

## 下发流程

从只读快照提取最小字段/时间窗口，在隔离任务中脱敏，扫描结果确认无原始敏感模式，再写入访问更受限且有自动过期的测试环境。任务日志不输出原值；中间文件加密并在成功或失败后清理。每次下发记录数据版本、规则版本、接收环境和销毁时间。
