# TLS、加密与 Secret 管理

不同加密层防御不同泄露路径。TLS 防传输链路被窃听或篡改；静态加密防磁盘、快照或备份介质泄露；列级/应用层加密减少数据库管理员或存储层直接看到明文的范围。

## 传输与静态加密

数据库连接启用 TLS 并验证服务端证书链和主机名。只设置“使用加密”但接受任意证书，仍可能遭受中间人攻击。双向 TLS 可认证客户端，但证书仍应映射到最小权限角色并可撤销。

磁盘/TDE 加密通常对数据库透明，能保护离线介质，但数据库进程和合法查询仍看到明文。备份、快照、导出、临时文件和日志可能绕过主数据盘加密，必须分别配置加密与访问策略。

## 列级与应用层加密

随机化加密同一明文产生不同密文，泄露模式较少，但难以建立等值索引；确定性加密支持等值匹配，却会暴露相同值和频率，低基数字段尤其容易被推断。范围查询、排序、模糊搜索通常无法直接作用于密文。

必要查询可保存单独的受密钥保护 Hash/Blind Index，但要评估字典攻击并使用合适的 Keyed Hash。密码不能可逆加密，应使用专门的慢密码 Hash；Token 只需比对时也优先保存 Hash。

## Envelope Encryption 与轮换

常见结构是用 Data Encryption Key（DEK）加密数据，再由 KMS 中的 Key Encryption Key（KEK）包装 DEK。数据库只保存密文、Key ID 和被包装的 DEK，主密钥不进入代码仓库或普通配置。

轮换分两类：轮换 KEK 可重新包装 DEK，通常无需重写所有数据；轮换 DEK 需要按批次重加密数据。读取端在过渡期识别 Key Version，写入只使用新 Key，后台迁移旧密文；旧 Key 在备份保留期和回滚窗口结束前不能销毁。

## Secret 生命周期

密码、连接串、证书和 KMS 权限由 Secret Manager 托管，运行时按身份获取，不写入源码、镜像、日志或长期环境文件。轮换流程必须同时覆盖连接池、定时任务、灾备环境和恢复工具，并验证旧 Secret 已失效。

密钥与密文放在同一备份且由同一管理员控制，会抵消分权价值；反之，密钥丢失会使所有备份永久不可恢复。密钥恢复也应纳入 [[后端/数据库/9. 高可用、备份与数据可靠性/3. 备份、PITR与恢复演练|恢复演练]]。
