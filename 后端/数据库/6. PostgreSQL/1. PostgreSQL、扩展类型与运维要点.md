# PostgreSQL、扩展类型与运维要点

PostgreSQL 是功能完整的关系型数据库，适合复杂 SQL、事务、扩展类型和丰富索引。它的能力不等于无需建模或运维。

## 核心能力

PostgreSQL 提供 CTE、窗口函数、递归查询、`RETURNING`、物化视图和丰富类型。`jsonb`、数组、范围、网络地址与全文检索适合特定场景；高频过滤、关联和约束字段仍优先结构化列。

索引除 B-tree 外还有 GIN、GiST、BRIN 等。GIN 常用于 JSONB 或全文检索，BRIN 适合与物理顺序高度相关的大规模时间数据。选择应由查询条件和数据分布决定。

## MVCC 与维护

PostgreSQL 通过 MVCC 维护多版本，WAL 支持恢复与复制。`VACUUM`/Autovacuum 回收旧元组并维护统计信息；长事务会阻碍清理、造成表和索引膨胀。使用 `EXPLAIN (ANALYZE, BUFFERS)` 观察实际行数与缓冲区访问。

## 可靠性

流复制提供副本，逻辑复制适合选择性同步与变更数据捕获；WAL 归档与基础备份可支持 PITR。故障切换要处理健康判断、旧主隔离、连接重建和异步复制丢失窗口。

## 扩展边界

PostGIS、TimescaleDB、pgvector 等扩展能增强空间、时序或向量能力，但带来版本、备份、升级和托管兼容性约束。选用前要验证运维路径。

## 面试自测

1. JSONB 适合替代所有关系列吗？

不适合。它适合半结构化扩展，频繁过滤、排序、Join 和约束的数据仍应使用列和合适索引。

2. Autovacuum 为什么重要？

它清理过期行版本并更新统计；失效会导致膨胀、查询变慢和事务 ID 风险。
