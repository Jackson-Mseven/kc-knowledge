# SQL 基础

SQL（Structured Query Language）是关系数据库的声明式语言：描述要得到或修改的数据，具体访问路径由数据库决定。关系模型把数据表示为表；列定义属性，行表示事实，主键唯一标识一行，外键连接不同表。关系理论按集合处理元组，而 SQL 查询默认允许重复行，只有使用 `DISTINCT` 才会去重。

## 表、数据类型与约束

表结构同时定义数据形态和不可违反的规则。下面两张表覆盖后续示例所需字段：

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY,
  email VARCHAR(255) NOT NULL UNIQUE,
  display_name VARCHAR(80) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE orders (
  id BIGINT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  status VARCHAR(20) NOT NULL,
  amount DECIMAL(12, 2) NOT NULL,
  note VARCHAR(255),
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_orders_user
    FOREIGN KEY (user_id) REFERENCES users(id),
  CONSTRAINT ck_orders_status
    CHECK (status IN ('pending', 'paid', 'cancelled')),
  CONSTRAINT ck_orders_amount
    CHECK (amount >= 0)
);
```

常用类型及选择边界：

| 类型 | 适合的数据 | 关键边界 |
| --- | --- | --- |
| `INTEGER`、`BIGINT` | 计数、整数 ID | 按数值范围选择，避免无意义地使用字符串 ID |
| `DECIMAL(p, s)` | 金额、精确定点数 | `FLOAT`、`DOUBLE` 存在二进制浮点误差 |
| `VARCHAR(n)`、`TEXT` | 文本 | 长度、字符集与排序规则会影响比较和唯一性 |
| `DATE` | 生日、账期等自然日期 | 不包含时间和时区 |
| `TIMESTAMP` | 创建时间等时间点 | 各产品的时区语义不同，应统一存储约定 |
| `BOOLEAN` | 真/假状态 | 部分数据库使用整数或别名实现 |

约束比应用层“先查询再写入”更可靠：`PRIMARY KEY` 保证行身份，`UNIQUE` 保证候选键唯一，`NOT NULL` 排除缺失值，`CHECK` 限定合法范围，`FOREIGN KEY` 保证引用存在，`DEFAULT` 只为未提供的列生成默认值。自增列、枚举、JSON 和时间类型的具体语法存在方言差异。

`NULL` 表示未知或不适用，不等于 `0`、空字符串或 `false`。涉及 `NULL` 的比较可能得到 `UNKNOWN`，而 `WHERE` 只保留结果为 `TRUE` 的行。

## SQL 分类

下表是常见的教学分类；标准和产品文档有时会把 `SELECT` 也归入 DML。

| 分类 | 作用 | 主要命令 |
| --- | --- | --- |
| DDL（Data Definition Language） | 定义数据库对象 | `CREATE`、`ALTER`、`DROP`、`TRUNCATE` |
| DML（Data Manipulation Language） | 新增、修改和删除行 | `INSERT`、`UPDATE`、`DELETE` |
| DQL（Data Query Language） | 查询数据 | `SELECT` |
| DCL（Data Control Language） | 授予或撤销权限 | `GRANT`、`REVOKE` |

### DDL：定义结构

```sql
-- 创建表
CREATE TABLE tags (
  id BIGINT PRIMARY KEY,
  name VARCHAR(50) NOT NULL UNIQUE
);

-- 修改表结构
ALTER TABLE tags ADD COLUMN description VARCHAR(255);

-- 清空全部行，不能使用 WHERE
TRUNCATE TABLE tags;

-- 删除表及其定义
DROP TABLE tags;
```

`DELETE` 删除符合条件的行，`TRUNCATE` 清空整张表，`DROP` 连表定义一起删除。`ALTER`、`TRUNCATE` 是否重写表、能否回滚、是否重置自增值都取决于数据库产品，不能把一种方言的行为直接套到另一种。

### DML：修改数据

```sql
INSERT INTO users (id, email, display_name)
VALUES (1, 'alice@example.com', 'Alice');

INSERT INTO orders (id, user_id, status, amount, note)
VALUES (101, 1, 'pending', 299.00, NULL);

UPDATE orders
SET status = 'paid'
WHERE id = 101 AND status = 'pending';

DELETE FROM orders
WHERE id = 101;
```

`INSERT` 应显式列出目标列，避免表结构变化导致值错位。执行 `UPDATE` 或 `DELETE` 前必须确认 `WHERE` 和预期影响行数；省略 `WHERE` 会影响全部行。

### DCL：控制权限

```sql
GRANT SELECT, INSERT, UPDATE ON orders TO app_writer;
REVOKE DELETE ON orders FROM app_writer;
```

应用账号只应拥有运行所需的最小权限，结构迁移与业务读写使用不同账号。角色、对象范围和授权语法因产品而异。

## SELECT 基础查询

```sql
SELECT id, user_id, status, amount, created_at
FROM orders
WHERE status = 'paid' AND amount >= 100
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

- `SELECT` 指定返回列；避免无条件使用 `SELECT *`，以减少无用数据和 Schema 耦合。
- `FROM` 指定数据来源。
- `WHERE` 逐行筛选，只保留条件为 `TRUE` 的行。
- `ORDER BY` 用 `ASC` 升序或 `DESC` 降序；加入唯一列可消除并列顺序的不确定性。
- `LIMIT` 限制结果数量；没有 `ORDER BY` 时，“前 20 行”没有稳定含义。
- `DISTINCT` 对 `SELECT` 返回的整组列去重，而不是只对某一列生效。

```sql
SELECT DISTINCT status
FROM orders
ORDER BY status;
```

查询的简化逻辑顺序是 `FROM` -> `WHERE` -> `SELECT` -> `DISTINCT` -> `ORDER BY` -> `LIMIT`，因此 `WHERE` 通常不能直接引用同层 `SELECT` 才定义的别名。`LIMIT` 常见于 MySQL、PostgreSQL 和 SQLite；标准 SQL 使用 `FETCH FIRST`，SQL Server 还支持 `TOP` 或 `OFFSET`/`FETCH`。

## 条件查询

### 比较与逻辑运算

标准比较运算符包括 `=`、`<>`、`>`、`>=`、`<`、`<=`；`!=` 很常见，但 `<>` 的可移植性更好。逻辑优先级通常为 `NOT`、`AND`、`OR`，复杂条件应使用括号明确意图。

```sql
SELECT id, status, amount
FROM orders
WHERE (status = 'paid' OR status = 'pending')
  AND NOT amount < 100;
```

### LIKE 模糊匹配

`%` 匹配任意长度字符，`_` 匹配单个字符：

```sql
SELECT id, email
FROM users
WHERE email LIKE '%@example.com';
```

大小写是否敏感取决于数据库和排序规则。需要匹配字面量 `%` 或 `_` 时应使用产品支持的转义语法；用户输入不能未经处理直接拼成模式。

### IN 与 BETWEEN

`IN` 判断值是否属于集合，`BETWEEN` 的两个边界都包含在内：

```sql
SELECT id, status, amount
FROM orders
WHERE status IN ('pending', 'paid')
  AND amount BETWEEN 100 AND 500;
```

时间范围通常使用左闭右开区间，避免一天末尾的精度和时区问题：

```sql
SELECT id, created_at
FROM orders
WHERE created_at >= '2026-08-01 00:00:00'
  AND created_at <  '2026-08-02 00:00:00';
```

### NULL 判断

判断空值必须使用 `IS NULL` 或 `IS NOT NULL`，不能写 `= NULL` 或 `<> NULL`：

```sql
SELECT id, note
FROM orders
WHERE note IS NULL;
```

`NOT IN` 的集合只要包含 `NULL`，比较就可能得到 `UNKNOWN`，导致结果与直觉不符；应先排除集合中的 `NULL`，或在需要表达存在性时改用 `NOT EXISTS`。

## 参数化查询

值必须通过数据库驱动绑定，不能拼接进 SQL：

```sql
SELECT id, status, amount
FROM orders
WHERE user_id = ? AND status = ?
ORDER BY created_at DESC, id DESC
LIMIT ?;
```

占位符可能是 `?`、`$1` 或命名参数，以驱动 API 为准。参数只能绑定值；表名、列名和 `ASC`/`DESC` 等 SQL 结构必须由固定白名单映射生成。参数化负责隔离数据与语法，输入校验则负责业务合法性，两者不能互相替代。
