# EXPLAIN、Join 算法与 SQL 改写

## 计划阅读

`EXPLAIN` 展示估计访问路径，`EXPLAIN ANALYZE` 在支持时显示实际时间和行数。重点比较估计与实际、扫描行数、过滤比例、临时排序、回表、内存/磁盘溢出与锁等待。

## Join 算法

Nested Loop 适合外层少且内层有索引；Hash Join 适合较大等值集合但依赖内存；Merge Join 适合已排序输入。优化方向是缩小驱动集、为关联列建索引、避免错误基数估计，而非强行指定算法。

## SQL 改写

将列函数改为范围条件，避免隐式类型转换，提前过滤和投影，按需使用 `EXISTS`。`IN`、Join、子查询的最优形式依数据库和数据分布而变，应看计划而非背结论。

## 统计信息

数据倾斜、相关列、过期统计和参数差异会让优化器选错计划。更新统计、建立扩展统计或按业务拆分查询前，应先确认估计错误的来源。

## 面试自测

1. 小表全表扫描一定是坏事吗？

不是。索引定位和回表也有成本，扫描少量页可能更快；判断依据是实际成本而非是否出现索引名。
