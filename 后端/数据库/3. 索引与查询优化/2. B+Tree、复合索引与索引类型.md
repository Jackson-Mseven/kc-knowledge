# B+Tree、复合索引与索引类型

## B+Tree

B+Tree 内部节点保存范围与指针，叶子按键有序，适合等值、范围和排序访问。InnoDB 二级索引叶子包含主键，未覆盖字段需回表；PostgreSQL 的索引与堆表可见性模型不同，但仍需评估访问成本。

## 复合索引

索引 `(a, b, c)` 按字典序组织。前导等值条件、后续范围、排序和返回列共同决定顺序。选择性高并非唯一准则：若查询必须按时间排序，排序列位置也很关键。

## 其他索引

Hash 适合特定等值场景；位图适合低基数分析；GIN/GiST 适合 PostgreSQL JSONB、全文或空间查询；倒排索引适合文本包含。索引类型必须与谓词匹配。

## 索引代价

索引占用磁盘和缓存，增加写入、复制、备份和统计维护成本。定期识别重复、无用索引，但删除前检查所有线上查询和约束依赖。

## 面试自测

1. 覆盖索引为什么能加速查询？

所需列直接在索引中，无需访问主表/聚簇索引，减少随机页访问；但覆盖列越多，索引维护成本越高。
