# MySQL 架构与执行原理

MySQL 采用“Server 层 + 可插拔存储引擎”架构：Server 层负责连接、解析、优化和执行框架，InnoDB 等存储引擎负责数据组织、索引、事务、锁与恢复。定位问题时，先判断耗时发生在连接排队、执行计划还是存储访问。

## 体系架构

| 层次 | 核心组件 | 职责 |
| --- | --- | --- |
| 客户端与连接 | MySQL Protocol、Connection Manager、认证与会话 | 建立连接，维护权限、事务、字符集、时区等会话状态 |
| Server 层 | Parser、Resolver、Optimizer、Executor | 解析 SQL，解析对象与权限，生成并执行计划 |
| 公共服务 | Binlog、Performance Schema、数据字典 | 复制与 CDC、运行时观测、元数据管理 |
| 存储引擎 | InnoDB、MyISAM 等 | 实现表和索引访问；事务、锁、日志能力取决于引擎 |
| 持久化层 | 表空间、Redo/Undo、Binlog、临时文件 | 保存数据、恢复信息和中间结果 |

Server 通过 Handler API 调用表所属的存储引擎，所以同一条 SQL 的解析和优化发生在 Server 层，实际记录读取和修改由引擎完成。MySQL 8.0 已移除 Query Cache；热点查询不会由 Server 自动缓存结果，应从索引、Buffer Pool 或应用缓存解决。

## SQL 执行流程

以一条 `SELECT` 为例：

1. **连接与认证**：服务端完成握手和身份验证，并为新连接创建独立会话；客户端连接池复用已有连接时，才会继续沿用该连接的会话状态。
2. **解析**：Parser 检查语法并构建解析树；随后解析库、表、列、函数和别名，检查访问权限。
3. **查询改写**：展开视图、化简常量条件，并尝试把子查询转换为 Semi-join 等等价形式。
4. **成本优化**：根据索引、统计信息和代价模型选择访问路径、Join 顺序与算法。
5. **执行**：Executor 从执行计划算子拉取记录，经 Handler API 请求存储引擎。
6. **读取数据**：InnoDB 先查 Buffer Pool，未命中时从表空间读取页；条件可在引擎或 Server 层继续过滤。
7. **返回结果**：结果按协议分批发送给客户端；大结果集仍会占用网络、内存和连接时间。

```sql
EXPLAIN FORMAT=TREE
SELECT id, created_at
FROM orders
WHERE tenant_id = 42 AND status = 'paid'
ORDER BY created_at DESC
LIMIT 20;
```

SQL 的书写顺序不等于物理执行顺序，表的先后次序也不强制 Join 顺序。优化器只能依据统计信息估算成本；数据倾斜、过期统计或参数差异会让估算偏离实际，具体分析见 [[后端/数据库/2. 关系型数据库/Mysql/2. MySQL索引原理与优化|MySQL 索引与执行计划]]。

写操作还涉及事务提交：InnoDB 先在内存页上修改记录并产生 Undo、Redo，提交时再与 Server 层 Binlog 协调。数据页可以晚于提交刷盘，持久性依赖日志而不是每次提交都立即写回整页，详见 [[后端/数据库/2. 关系型数据库/Mysql/3. 事务与隔离级别|事务与隔离级别]]。

## InnoDB 与 MyISAM

存储引擎按表选择，可用 `SHOW ENGINES` 和 `SHOW TABLE STATUS` 查看。

| 维度 | InnoDB | MyISAM |
| --- | --- | --- |
| 事务与恢复 | 支持 ACID、Redo/Undo 和崩溃恢复 | 不支持事务；异常后可能需要检查或修复表 |
| 并发控制 | MVCC、行级与范围锁 | 主要使用表级锁 |
| 数据完整性 | 支持外键；约束与修改属于同一事务 | 不支持外键和事务回滚 |
| 索引组织 | 主键聚簇，二级索引叶子保存主键 | 数据文件与索引分离，索引叶子指向记录位置 |
| 典型用途 | OLTP、并发读写和绝大多数业务表 | 兼容遗留系统或极少更新的特殊表 |

```sql
CREATE TABLE accounts (
  id BIGINT PRIMARY KEY,
  balance DECIMAL(15, 2) NOT NULL
) ENGINE = InnoDB;

SHOW TABLE STATUS LIKE 'accounts';
```

新业务默认使用 InnoDB。MyISAM 的简单结构不等于查询必然更快；缺少事务、行级并发控制和可靠崩溃恢复，通常比潜在的局部收益更重要。

## 会话与资源边界

- 每个连接都有内存、事务和会话状态。连接池应限制活跃并发，设置连接获取、语句和锁等待超时，并在归还连接前结束事务。
- `sql_mode` 会影响分组、非法值和隐式转换；字符集、Collation、时区和隔离级别也属于会话语义，各环境必须一致。
- 新系统通常使用 `utf8mb4`，并明确 Collation；它会改变比较、排序及唯一索引判定。
- `TIMESTAMP` 按会话时区转换，`DATETIME` 保存字面日期时间。业务应先区分“时间点”和“日历时间”，再确定存储约定。

函数、存储过程、触发器等数据库程序对象见 [[后端/数据库/1. SQL/2. SQL 进阶|SQL 进阶]]。
