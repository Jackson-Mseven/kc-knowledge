# MySQL 运维

MySQL 运维围绕权限、安全、备份恢复、复制和容量演进展开。任何线上变更都要同时考虑数据丢失窗口（RPO）、恢复时长（RTO）、复制延迟、锁和回滚路径。

## 权限控制

采用账号分离和最小权限：

- 应用读写账号只访问所需 Schema 和表；
- 迁移账号单独管理，禁止应用账号执行任意 DDL 或授权；
- 只读报表、备份、监控和运维使用不同角色；
- 权限变更可审计，定期回收离职、临时和过期账号。

```sql
CREATE USER 'app_reader'@'10.0.0.0/255.0.0.0'
  IDENTIFIED BY RANDOM PASSWORD;
GRANT SELECT ON shop.* TO 'app_reader'@'10.0.0.0/255.0.0.0';
```

生产凭据应由 Secret Manager 注入并轮换，不写入仓库、镜像或日志。网络层限制来源，连接启用 TLS；权限控制不能替代应用层租户授权和参数化查询。

## 安全管理

- 传输使用 TLS，校验证书和服务器身份；
- 静态备份、Binlog 和临时导出文件加密，并分离密钥权限；
- 敏感字段按数据分级决定列级或应用层加密，密钥轮换要有旧密钥解密窗口；
- 审计记录主体、来源、操作、对象、结果和关联 ID，避免把 SQL 参数原文写入日志；
- 生产数据下发测试环境前优先使用合成数据，必要时做一致替换和不可逆脱敏；
- 数据库版本、插件、权限和暴露端口纳入补丁与漏洞管理。

SQL 注入防护仍需使用参数绑定；表名、列名和排序方向只能从固定白名单映射，不能把用户输入拼进 SQL。

## 数据备份和恢复

| 备份 | 特点 | 适用 |
| --- | --- | --- |
| 全量物理备份 | 恢复快，依赖版本和实例布局 | 大库基线、灾备 |
| 逻辑备份 | 可迁移、可审查，恢复和导出较慢 | 小库、部分表、跨版本 |
| Binlog | 记录增量逻辑变更 | 时间点恢复（PITR） |

复制不是备份：误删和错误 DDL 会同步到副本。PITR 的基本流程是恢复最近全量备份，再按时间顺序重放目标时间前的 Binlog。备份必须异地保存、加密、设置保留策略，并定期在隔离环境实际恢复，不能只检查“文件生成成功”。

恢复演练至少记录：目标时间、备份版本、Binlog 起止位置、恢复耗时、数据校验结果、应用切换步骤和失败回退方式。恢复期间要防止误把临时实例接入生产拓扑。

## 主从复制

MySQL 复制链路为 Source 写 Binlog，Replica 接收 Relay Log，再由 Applier 应用。异步复制中，Source 已提交不代表 Replica 已接收或已应用。

- GTID 简化位点管理、重建和故障切换，但不自动保证副本完整；
- 半同步复制要求提交路径等待副本确认接收，能缩小丢失窗口，但会增加提交延迟，且确认通常不等于副本已应用；
- 监控接收/应用位置、Relay Log 积压、Applier 并行度、长事务和磁盘延迟；
- 自动切换必须隔离旧主（Fencing），否则可能形成双写和数据分叉；
- 误操作会被复制，故障切换仍依赖独立备份和恢复演练。

## 读写分离

读写分离把写请求发往 Source、部分读请求发往 Replica，以换取读吞吐和报表隔离。副本可能陈旧，需要 Read-Your-Writes 的请求采用：

- 写后短时间固定读 Source；
- 会话粘滞到 Source；
- 记录写事务 GTID，等待目标副本追上；
- 明确接受陈旧读取，并在产品层表达状态。

读路由不能只靠简单轮询：要结合复制延迟、健康状态、连接池和故障切换。强一致查询、唯一性判断和刚写入的数据不能盲目发往异步副本。

## 分库分表

只有单库的容量、写入或故障域已成为明确瓶颈，才考虑水平拆分。分片键应满足：

- 高频查询能够路由到少量分片；
- 数据分布均衡，避免热点租户或递增键集中写入；
- 关键事务和唯一约束尽量落在同一分片；
- 具备全局 ID、跨分片分页/聚合和迁移方案。

分片会增加路由、跨片 Join、全局排序、事务和运维复杂度。扩容需要再平衡、双读/双写或迁移窗口，并持续校验数量、校验和、业务聚合和复制延迟。具体分片与迁移边界见 [[后端/数据库/8. 分布式数据库与水平扩展/1. 读写分离、分片与分布式一致性|分布式数据库与水平扩展]]。

## DDL 与生产配置

大表变更遵循 Expand-Migrate-Contract：先新增兼容结构，再分批回填和切换读取，确认旧版本退出后删除旧结构。InnoDB 的 `INSTANT`、`INPLACE`、`COPY` 支持范围随版本和操作变化，任何算法都可能等待 MDL。

上线前检查表大小、磁盘余量、活跃长事务、Redo/Binlog 速率和副本承载能力；回填按索引键分批、限速、可暂停，并监控锁等待和复制延迟。

`utf8mb4`、Collation、时区、`sql_mode`、连接/语句/锁等待超时等配置应纳入版本管理。参数调整必须对应具体瓶颈，记录变更前后指标和回滚方式。
