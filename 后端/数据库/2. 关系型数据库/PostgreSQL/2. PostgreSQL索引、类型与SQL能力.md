# PostgreSQL 索引、类型与 SQL 能力

PostgreSQL 的索引方法通过 Operator Class 与具体操作符匹配。选择索引时应从查询表达式出发：同一个 `jsonb`、数组或范围列，使用不同操作符可能需要不同索引方法或 Operator Class。

## 索引方法

| 索引 | 典型用途 | 主要边界 |
| --- | --- | --- |
| B-tree | 等值、范围、排序、前缀 | 默认通用选择，不适合任意多值包含 |
| Hash | 等值 | 不提供有序扫描，通常不优于 B-tree 的通用性 |
| GIN | `jsonb`、数组、全文等一个值包含多个键项 | 查询快但写入和构建成本较高 |
| GiST | 范围、空间、近邻搜索和可扩展谓词 | 属于通用框架，行为由 Operator Class 决定 |
| SP-GiST | 可递归分区的数据，如前缀、点或网络结构 | 仅适合有对应 Operator Class 的数据 |
| BRIN | 与物理页顺序高度相关的超大表 | 索引很小但只能排除页范围，不适合随机分布 |

Expression Index 支持 `lower(email)` 等派生条件；Partial Index 只包含满足谓词的行；`INCLUDE` 添加非键列以支持覆盖读取。查询表达式必须与索引定义匹配，且 Partial Index 只有在优化器能证明查询条件蕴含索引谓词时才可用。

PostgreSQL 的 Index Only Scan 仍受 MVCC 可见性约束。若 Visibility Map 未标记页面 All-Visible，执行器仍需访问 Heap 确认可见性；因此“覆盖所有列”不保证完全不访问表。

```sql
CREATE INDEX idx_open_orders
ON orders (tenant_id, created_at DESC)
INCLUDE (total_amount)
WHERE status = 'open';
```

## JSONB、数组、范围与全文

- `jsonb` 适合结构可能变化的扩展属性。经常过滤、Join、排序或要求约束的字段应提升为普通列；
- GIN 默认 `jsonb_ops` 支持的操作符更广，`jsonb_path_ops` 通常更小并偏向包含查询，选择前确认实际谓词；
- 数组适合自然的小集合语义，不应取代需要外键、独立生命周期和频繁关联的子表；
- Range Type 能准确表达 `[start, end)` 等区间，并可配合 GiST 做重叠查询或排他约束；
- 全文检索将文本规范化为 `tsvector`，查询表示为 `tsquery`。分词配置、权重和排序决定语义，复杂搜索仍需评估专项搜索系统。

## 常用 SQL 能力

`RETURNING` 能在写入时返回数据库生成值，避免额外查询：

```sql
INSERT INTO users(email, display_name)
VALUES ($1, $2)
ON CONFLICT (email)
DO UPDATE SET display_name = EXCLUDED.display_name
RETURNING id, email, display_name;
```

- Window Function 在保留明细行的同时计算排名、累计和分组前后值；
- Recursive CTE 适合层级和图遍历，但必须控制终止条件与重复路径；
- 当前 PostgreSQL 可内联部分无副作用的非递归 CTE，`MATERIALIZED`/`NOT MATERIALIZED` 可影响优化边界；
- Materialized View 保存查询结果，需要显式刷新；`REFRESH ... CONCURRENTLY` 通常要求合适的唯一索引，且刷新仍有计算和存储成本；
- `DISTINCT ON` 可配合明确 `ORDER BY` 获取每组第一行，但这是 PostgreSQL 扩展语法。

复杂 SQL 仍需用 `EXPLAIN (ANALYZE, BUFFERS)` 验证中间行数、排序、Hash 内存和临时文件。事务与锁见 [[后端/数据库/2. 关系型数据库/PostgreSQL/3. PostgreSQL事务、锁与并发控制|PostgreSQL 事务与并发控制]]。
