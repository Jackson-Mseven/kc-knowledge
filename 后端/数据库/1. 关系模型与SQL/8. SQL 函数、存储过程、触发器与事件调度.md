# SQL 函数、存储过程、触发器与事件调度

数据库可承载一部分靠近数据的逻辑，但并不意味着应把完整业务系统迁入数据库。选择时要权衡一致性、可测试性、可部署性和跨数据库可移植性。

## 数据库函数

内置函数适合日期处理、字符串转换、聚合和数值计算。对索引列套函数可能让谓词无法有效使用普通索引：

```sql
SELECT id
FROM orders
WHERE created_at >= '2026-07-01 00:00:00'
  AND created_at < '2026-08-01 00:00:00';
```

比 `DATE(created_at) = '2026-07-01'` 更容易利用 `created_at` 上的范围索引。若确有表达式查询需求，可评估函数索引或生成列，具体能力依数据库而定。

## 存储过程与用户函数

存储过程可以把多步数据操作放在数据库侧，降低往返并集中部分数据规则；代价是调试、版本化、测试和跨产品迁移更复杂。适合稳定、数据密集且明确归属数据库的操作，不适合混入 HTTP 调用、复杂领域编排或难以审计的隐式副作用。

## 触发器

触发器可在 `INSERT`、`UPDATE`、`DELETE` 前后自动执行，例如维护审计记录。它的风险是写入路径隐式增加工作和锁，错误传播不直观，批处理可能产生大量副作用。使用时应记录目的、执行顺序、性能预算和禁用/修复方案。

## 事件调度

数据库事件调度适合小型、与数据紧密相关的维护任务，例如过期临时数据清理。跨服务任务通常更适合由应用调度器或任务平台执行，以获得版本控制、重试、告警和统一可观测性。

## 面试自测

1. 触发器为什么容易造成线上问题？

它把额外读写隐藏在普通 DML 后面，可能延长事务、扩大锁范围并让排查者遗漏副作用。对高频表尤其需要谨慎。

2. 何时应避免把逻辑写入存储过程？

当逻辑需要频繁迭代、调用外部服务、跨多个服务协调，或团队缺少数据库端测试与发布能力时，应用层通常更可维护。
