# 高级 SQL：CTE、递归查询与窗口函数

高级 SQL 能把分组排名、层级查询和多阶段变换交给数据库完成，减少应用层全量拉取和循环计算。使用前仍要理解执行计划与中间结果规模。

## CTE

Common Table Expression（CTE）用 `WITH` 为中间结果命名，提高复杂查询可读性：

```sql
WITH recent_paid_orders AS (
  SELECT user_id, total_amount
  FROM orders
  WHERE status = 'paid'
    AND created_at >= ?
)
SELECT user_id, SUM(total_amount) AS total_amount
FROM recent_paid_orders
GROUP BY user_id;
```

不同数据库和版本对 CTE 的内联、物化与优化策略不同。不要因为 CTE 更易读就假设性能恒定；对热点查询用 `EXPLAIN ANALYZE` 验证。

## 窗口函数

窗口函数保留原始行，同时基于一个窗口计算排名、累计值或相邻行：

```sql
SELECT
  user_id,
  id,
  created_at,
  total_amount,
  ROW_NUMBER() OVER (
    PARTITION BY user_id
    ORDER BY created_at DESC, id DESC
  ) AS order_rank,
  SUM(total_amount) OVER (
    PARTITION BY user_id
    ORDER BY created_at, id
  ) AS cumulative_amount
FROM orders
WHERE status = 'paid';
```

常用函数包括 `ROW_NUMBER`、`RANK`、`DENSE_RANK`、`LAG`、`LEAD` 与窗口聚合。`ROW_NUMBER` 不并列，`RANK` 会为并列项留下名次间隔，选择时要符合产品规则。

## 递归 CTE

递归 CTE 适合树与层级结构，例如组织关系：

```sql
WITH RECURSIVE organization AS (
  SELECT id, manager_id, display_name, 0 AS depth
  FROM employees
  WHERE id = ?
  UNION ALL
  SELECT e.id, e.manager_id, e.display_name, o.depth + 1
  FROM employees AS e
  JOIN organization AS o ON e.manager_id = o.id
)
SELECT id, manager_id, display_name, depth
FROM organization;
```

生产使用需防止循环引用和无限层级；可通过约束、最大深度、路径检测和查询超时限制风险。

## 面试自测

1. 窗口函数与 `GROUP BY` 的区别是什么？

`GROUP BY` 将多行压缩为一组结果；窗口函数保留每行，同时计算该行所在窗口的派生值，因此适合排名和累计。

2. CTE 一定比子查询快吗？

不一定。两者常可表达同类逻辑，实际性能取决于数据库版本、优化器与中间结果；可读性和计划验证同样重要。
