# 向量数据库

向量检索把文本、图片或其他对象编码为固定维度的 Embedding，再按距离找相似对象。它解决语义召回，不保证事实正确、业务授权或事务一致性。

## 距离与索引

Cosine Similarity 比较方向，Dot Product 同时受方向和模长影响，L2 Distance 比较欧氏距离。索引和查询必须使用与模型训练、向量归一化一致的度量；更换模型、维度或预处理通常需要重建全部向量。

精确 KNN 扫描全部向量，结果准确但成本随数据量线性增长。Approximate Nearest Neighbor（ANN）以少量召回损失换取低延迟：

- HNSW 构建多层邻接图，查询快、召回高，但索引占用内存且写入成本较高；`M`、`efConstruction`、`efSearch` 控制内存、构建时间、延迟与召回率。
- IVF 先把向量分桶，查询部分簇；`nprobe` 越高通常召回越高、扫描越多。
- Product Quantization（PQ）压缩向量以节省内存和 I/O，也会损失精度。

参数不能只用随机数据调优，应在真实查询集上同时测 Recall@K、端到端延迟、内存和吞吐。

## 检索链路

典型 RAG/语义搜索链路是：内容切分 -> Embedding -> Metadata 过滤 -> ANN 召回 -> 关键词或模型重排 -> 权限校验 -> 返回原文。关键边界包括：

- 切分过小会丢失上下文，过大会稀释主题并提高推理成本；保存文档、分块和来源版本。
- Pre-Filter 更安全且减少候选，但高选择性过滤可能影响 ANN 召回；Post-Filter 可能不足 K 条，且不能作为唯一授权措施。
- 混合检索结合 BM25 的精确词项能力与向量的语义能力，通常比单一路径更稳。
- 删除、权限变化和模型升级都要传播到向量索引；旧模型与新模型的距离不可直接比较。

向量结果只返回候选。答案是否可信还取决于原文质量、重排、引用和生成模型，必须用领域查询集评估 MRR/NDCG、Recall@K 与最终任务正确率。
