# 连接池、超时与请求生命周期

数据库驱动负责协议、认证、类型编解码和参数绑定；连接池复用已建立连接，并用有限并发保护数据库。连接池不是性能缓存，池越大不代表吞吐越高。

## 连接预算

数据库连接会占用内存、会话状态和调度资源。应用总池容量必须在数据库连接上限内统一预算：

```text
应用可用连接 = max_connections - 运维/迁移/复制等预留
单进程池上限 <= 应用可用连接 / 最大应用进程数
```

自动扩容时按“最大进程数”计算，而不是当前实例数。事务会独占一个连接直到提交或回滚；连接池代理可减少空闲后端连接，但无法让一个事务跨多个数据库连接执行。

池需要观测活跃、空闲、排队、获取超时、创建失败和连接最长占用时间。连接等待升高而数据库 CPU 不高，常见原因是连接泄漏、长事务、网络或单个慢查询占住连接；先定位占用者，不应直接扩大池。

## 超时与取消

不同超时控制不同阶段，不能只设一个“数据库超时”：

| 超时 | 限制的阶段 |
| --- | --- |
| Connect | TCP/TLS/认证建立连接 |
| Acquire | 在连接池等待可用连接 |
| Statement/Query | SQL 在数据库中的执行时间 |
| Transaction | 整个事务允许持续的时间 |
| Socket/Request deadline | 网络读写或上游请求总截止时间 |

应用截止时间应向数据库查询传播取消。取消通常是尽力而为：客户端收到超时不代表数据库已停止，连接也可能需要先读取剩余协议消息或直接废弃。查询在事务中失败后，应按数据库语义回滚事务，不能继续复用未知状态。

事务中不要等待 HTTP、文件、消息或用户输入；这会延长持锁和连接占用时间。所有异常路径都必须在 `finally` 中回滚/归还连接。

## 重试边界

只有连接瞬断、死锁、序列化失败等明确瞬时错误才可能重试。重试前必须确认：

- 操作幂等，或有唯一业务键/幂等记录阻止重复副作用；
- 整个事务从头重放，而不是从失败 SQL 中间继续；
- 次数有限，使用指数退避和抖动，并受请求总截止时间约束；
- 不重试约束冲突、语法错误、权限错误和确定性业务失败。

具体错误应按 SQLSTATE 或驱动错误类型分类，不能匹配错误字符串。

## 优雅关闭

服务先停止接收新流量，再等待有界时间让进行中的请求结束，随后关闭池。超时后取消剩余查询并回滚事务；关闭顺序反过来会让仍在处理的请求获得“连接池已关闭”错误。进程退出前不得留下未提交事务。
