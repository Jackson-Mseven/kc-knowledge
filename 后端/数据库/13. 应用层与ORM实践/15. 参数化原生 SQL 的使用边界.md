# 参数化原生 SQL 的使用边界

参数化原生 SQL 的使用边界是应用层与ORM实践中的独立学习主题。学习时应同时回答：它解决什么问题、底层机制或数据语义是什么、在生产中如何验证成本与失败边界。

## 核心理解

复杂 CTE、窗口、批处理和特性查询可使用原生 SQL；值仍参数化，标识符白名单，返回结构和计划进入测试。

- 把该主题放回完整请求/事务/数据链路中，区分权威数据、派生数据、短暂状态和可重建结果；
- 用最小数据集、正常路径、并发路径和失败路径验证结论，记录 SQL、日志、计划或指标。

## 实践要点

- 连接池是资源预算和背压边界，不是无限并发开关。
- ORM 生成 SQL、事务边界、迁移和关联加载必须可观察。
- 集成测试运行真实迁移并覆盖错误、并发和回滚路径。

## 验证清单

1. 为该主题准备最小可复现数据、正常路径和失败路径；
2. 记录 SQL、执行计划、日志或指标，以确认实现行为而不是依赖直觉；
3. 将性能、权限、幂等、回滚和数据恢复要求写入发布或运维清单。

## 面试自测

### 如何说明“参数化原生 SQL 的使用边界”的工程价值？

应从业务约束和访问模式出发，说明它解决的正确性、性能或可靠性问题，再给出实现成本、边界条件和可观测性方法；只罗列定义不能支撑选型或设计结论。
