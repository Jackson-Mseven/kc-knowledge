# Repository、原生 SQL、发布与测试策略

## 抽象边界

Repository 应封装业务所需的查询与事务边界，而不是机械暴露每张表。避免为简单查询叠加过深抽象，也不要让领域逻辑依赖某个 ORM 的隐式懒加载。

## 原生 SQL

窗口函数、递归 CTE、批量操作和数据库特性可使用参数化原生 SQL。将 SQL、参数类型、返回模型和计划验证纳入代码审查；动态标识符仍使用白名单。

## 发布和测试

先部署兼容 Schema，再部署新代码；回滚前确认旧代码能读取新数据。集成测试跑真实迁移，覆盖约束、死锁、超时、回填和权限；对热点 SQL 保留计划或性能基线。

## 面试自测

1. 何时应绕开 ORM？

当 ORM 生成的 SQL 无法满足复杂查询、批处理或产品特性，且团队能维护参数化 SQL、测试和计划验证时。
