# 连接池、ORM、迁移与数据库测试

应用层决定数据库能力是否被正确使用。ORM 能降低映射样板，但不能替代 Schema、索引、事务语义和执行计划。

## 连接与事务

连接池复用连接并控制总并发。池上限应由数据库承载能力除以所有应用实例预算得出，留出迁移、监控和管理余量。请求结束归还连接；事务只包围必要读写，不在事务中等待 HTTP、文件或消息。

设置连接获取、查询和事务超时，区分可重试的连接中断、死锁和序列化失败。服务关闭时先停止接流量，再等待或释放连接。

## ORM 的边界

Prisma、Drizzle、TypeORM、Sequelize 等提供模型映射、迁移和参数化接口，但仍需检查生成 SQL、预加载和 N+1。窗口函数、复杂 CTE、数据库特性可使用参数化原生 SQL；迁移必须进入版本控制并经过预生产验证。

## 数据库测试

集成测试应使用隔离数据库或容器，执行真实迁移，准备最小数据，并在测试后清理或回滚事务。覆盖约束冲突、并发更新、迁移兼容性和失败恢复；仅 Mock Repository 无法证明 SQL 和索引正确。

## 面试自测

1. ORM 为什么会造成 N+1？

访问关联对象时可能逐条触发延迟加载。用 Join、批量加载或预加载，并从日志确认 SQL 数量和结果规模。

2. 为什么不能把连接池设为无限大？

连接消耗数据库内存和调度资源，过多并发会放大锁与 IO 竞争；池的排队本身是需要诊断的背压信号。
