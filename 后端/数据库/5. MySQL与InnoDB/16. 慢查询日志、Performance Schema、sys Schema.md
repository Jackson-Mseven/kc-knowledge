# 慢查询日志、Performance Schema、sys Schema

慢查询日志、Performance Schema、sys Schema是MySQL与InnoDB中的独立学习主题。学习时应同时回答：它解决什么问题、底层机制或数据语义是什么、在生产中如何验证成本与失败边界。

## 核心理解

慢查询日志定位热点语句，Performance Schema 观察等待、锁和资源，sys Schema 提供可读视图；诊断需控制开销并脱敏。

- 把该主题放回完整请求/事务/数据链路中，区分权威数据、派生数据、短暂状态和可重建结果；
- 用最小数据集、正常路径、并发路径和失败路径验证结论，记录 SQL、日志、计划或指标。

## 实践要点

- 所有参数与诊断结论都要结合版本、硬件、数据量和 RPO。
- 排查从 SQL、计划、锁等待、连接、Buffer Pool 和 IO 共同入手。
- 大表 DDL、回填与复制变更先在预生产演练。

## 验证清单

1. 为该主题准备最小可复现数据、正常路径和失败路径；
2. 记录 SQL、执行计划、日志或指标，以确认实现行为而不是依赖直觉；
3. 将性能、权限、幂等、回滚和数据恢复要求写入发布或运维清单。

## 面试自测

### 如何说明“慢查询日志、Performance Schema、sys Schema”的工程价值？

应从业务约束和访问模式出发，说明它解决的正确性、性能或可靠性问题，再给出实现成本、边界条件和可观测性方法；只罗列定义不能支撑选型或设计结论。
