# InnoDB 页、索引、Redo、Undo 与 Binlog

## 页与行

InnoDB 以页管理数据和索引。聚簇索引叶子保存整行，二级索引保存二级键和主键；随机长主键会增大二级索引和页分裂风险。行格式、大字段溢出页和页填充会影响空间与 IO。

## Redo 与 Undo

Redo 记录用于崩溃恢复的变更，遵循先日志后数据页；Undo 保存旧版本，支持回滚与一致性读。长事务导致历史版本难以清理，影响 Purge 和存储。

## Binlog 两阶段提交

InnoDB 的提交需要协调 Redo 与 Server 层 Binlog，减少崩溃时两类日志不一致。Binlog 用于复制和 PITR；刷盘与同步参数影响持久性、吞吐和可接受的数据丢失窗口。

## 面试自测

1. Redo 与 Binlog 的区别？

Redo 面向 InnoDB 崩溃恢复，Binlog 是 MySQL Server 层逻辑变更日志，主要用于复制和时间点恢复。
