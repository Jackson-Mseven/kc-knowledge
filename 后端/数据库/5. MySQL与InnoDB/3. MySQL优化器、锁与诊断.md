# MySQL 优化器、锁与诊断

## 优化器

优化器基于统计信息估计成本，决定索引、Join 顺序和访问方式。`EXPLAIN` 看预估，`EXPLAIN ANALYZE` 在支持版本中看实际；参数极端值和数据倾斜可能导致计划不稳定。

## 锁与等待

记录锁、间隙锁、Next-Key Lock 与意向锁会受隔离级别、索引和谓词影响。缺失索引的范围更新可能扩大锁范围；排查应收集事务、锁等待、死锁日志和 SQL 形态。

## 工具

慢查询日志找热点，Performance Schema 与 sys Schema 观察等待和语句，`SHOW ENGINE INNODB STATUS` 提供 InnoDB 状态。生产诊断需控制开销并脱敏。

## 面试自测

1. 为什么更新语句缺索引会造成并发问题？

它可能扫描并锁定更多记录/范围，延长事务并增加等待和死锁概率。
