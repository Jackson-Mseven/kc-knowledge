# 压测、性能基线与过载保护

压测用于验证特定工作负载下的吞吐、延迟和失效拐点。脱离真实数据分布的最高 QPS 没有容量意义。

## 工作负载模型

压测前固定以下变量：

- 读写比例、SQL 组合、事务长度和结果集大小；
- 数据量、基数、热点倾斜、冷热比例和索引状态；
- 并发或到达率、峰值持续时间、连接池和超时；
- 副本、备份、Checkpoint、Vacuum/Purge 等后台负载；
- 预热方式、测试时长、清理方法和通过标准。

闭环模型由固定用户在收到响应后继续请求，系统变慢时到达率会自动下降；开环模型按既定速率发请求，更接近外部流量并能暴露排队。测量工具若在阻塞期间停止发请求，会产生 coordinated omission，低估尾延迟。

Little's Law 可用于检查结果是否自洽：稳定系统中 `并发数 L ≈ 到达率 λ × 平均响应时间 W`。延迟上升而吞吐不再增长通常表示已经进入饱和区。

## 测试类型与基线

| 类型 | 回答的问题 |
| --- | --- |
| Load | 目标峰值下是否满足 SLO |
| Stress | 吞吐拐点和失败方式在哪里 |
| Spike | 突发流量下排队、限流与恢复是否正常 |
| Soak | 长时间运行是否出现连接泄漏、膨胀或积压 |

基线应保存数据库版本、Schema、数据快照、配置、硬件、查询指纹和结果。比较优化方案时一次只改变可解释变量，并同时报告吞吐与 p95/p99；“缓存已热”的结果不能代表冷启动或故障切换。

## 过载保护

保护顺序是减少无效工作并限制进入数据库的并发：

1. 连接池设置有界队列和短获取超时，避免请求无限堆积；
2. 查询/事务设置截止时间并传播取消，释放连接和锁；
3. 在入口按租户或接口限流，避免单一热点耗尽共享资源；
4. 对可选查询熔断或降级为缓存、陈旧读、简化结果；
5. 写能力不足时拒绝非关键写或进入受控只读模式，不能静默丢写。

重试必须只针对明确的瞬时错误，并要求操作幂等、次数有限、指数退避加抖动；数据库过载时同步重试会形成重试风暴。熔断不能用于掩盖数据正确性错误，读缓存也要明确最大可接受陈旧时间。恢复时逐步放量，防止积压同时回灌。
