# 数据库系统设计与故障案例

系统设计题考察的是从业务不变量推导数据模型、一致性、扩展和恢复策略的能力，而不是堆砌中间件名词。

## 订单与库存

订单、支付、库存以关系型主库为权威来源。库存扣减使用条件更新或短事务锁，订单创建用唯一业务键防重，跨服务通知用 Outbox。缓存只加速可容忍陈旧的读，搜索索引异步更新，用户支付后的关键读取走主库或读己之写策略。

## 多租户 SaaS

根据隔离等级与规模选择独立库、Schema 或共享表。共享表的每张租户表应包含 `tenant_id`，主查询索引和唯一约束也应带租户维度。权限校验在应用层执行，数据库角色限制服务权限；审计和数据删除覆盖备份与下游。

## 常见故障推演

- 慢列表：检查 SQL 参数、索引、排序、深分页和连接池等待；
- 死锁：分析锁图，统一加锁顺序，缩短事务，有限重试；
- 副本延迟：关键读切主、摘除落后副本，评估复制和容量；
- 误删：停止扩散，按 Runbook 做 PITR 或隔离恢复，对账后受控回写；
- 缓存不一致：以主库为准，删除或重建缓存，补充失效与对账机制。

## 设计回答模板

```text
业务不变量 -> 数据模型/约束 -> 读写路径 -> 一致性等级
-> 索引与容量 -> 缓存/异步同步 -> 监控告警 -> 故障恢复与演练
```

## 面试自测

1. 如何回答“设计一个高并发秒杀库存系统”？

先定义不超卖与订单幂等，再设计限流、排队或预扣减；最终扣减以数据库条件更新或可靠账本为准，缓存和队列用于削峰而非绕过正确性。
