# Context与并发模式

`context.Context` 用于在调用链传播取消信号、截止时间和少量请求级数据。服务端请求结束后，派生 context 会被取消，子任务必须及时响应 `<-ctx.Done()`。

常见模式包括 worker pool、pipeline、扇出和扇入。每个模式都要设计背压、错误传播和关闭顺序；并发数量应受限，不能把 goroutine 数量当作吞吐量保证。

不要把 context 存入结构体或传递业务参数，通常将其作为函数第一个参数。不要使用 context value 传递必需配置或大型对象。
