# 内存模型、逃逸分析与垃圾回收

编译器会根据生命周期决定变量留在栈上还是逃逸到堆上；可用 `go build -gcflags=-m` 查看逃逸提示。逃逸不是错误，但会增加分配和 GC 压力。

Go GC 以并发标记清扫为主，目标是在可接受停顿下回收不可达对象。性能优化应先用基准测试和 `pprof` 证明分配热点，再考虑复用对象或调整数据布局。

内存模型规定 goroutine 间何时能观察到写入。channel 操作、锁和原子操作提供同步关系；普通共享变量不能靠“通常能读到”来保证可见性。
