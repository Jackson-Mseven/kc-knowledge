# Web基础与HTTP协议

Gin、Echo 等框架都建立在 HTTP 之上。理解请求方法、状态码、Header、Cookie、缓存和连接生命周期，才能正确设计 Handler 和中间件。

## 请求与响应

HTTP 请求由方法、目标 URI、Header 和可选 body 组成；响应由状态码、Header 和 body 组成。`GET` 应保持安全且幂等，`PUT` 通常表示整体替换，`PATCH` 表示部分更新，`POST` 用于创建或触发动作。

状态码表达机器可判断的结果：`4xx` 表示请求或权限问题，`5xx` 表示服务端或依赖故障。不要把所有业务失败都返回 `200`，否则监控、重试和客户端处理都会失真。

## 连接与超时

HTTP/1.1 默认支持持久连接；HTTP/2 在单连接上复用多个流。服务端必须设置 Header、读、写和空闲超时，防止慢客户端耗尽连接。客户端应复用 `http.Client`，并根据幂等性决定是否重试。

## API设计

资源路径应稳定、名词化，分页、排序和过滤参数应有上限。幂等创建可使用 `Idempotency-Key`，避免网络重试造成重复写入。开放 API 需明确兼容策略、错误码和速率限制。

## 安全边界

校验 `Content-Type`、请求体大小和上传文件类型；Cookie 需要 `Secure`、`HttpOnly`、`SameSite` 属性。CORS 只允许明确的来源、方法和 Header，不能在携带凭证时使用通配来源。
