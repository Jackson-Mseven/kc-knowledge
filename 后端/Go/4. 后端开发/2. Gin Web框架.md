# Gin Web框架

Gin 是基于 Go `net/http` 的轻量 Web 框架，提供路由树、参数绑定、中间件和 JSON 响应能力。它解决的是 HTTP 服务的路由与请求编排问题，不替代数据库、鉴权或业务领域设计。

## 最小示例

```go
package main

import "github.com/gin-gonic/gin"

func main() {
    r := gin.New()
    r.Use(gin.Logger(), gin.Recovery())
    r.GET("/healthz", func(c *gin.Context) { c.JSON(200, gin.H{"status": "ok"}) })
    _ = r.Run(":8080")
}
```

路由组可表达版本和鉴权边界；中间件按注册顺序执行，必须明确是否调用 `c.Next()` 或提前返回。请求参数绑定后仍需服务端校验，统一错误响应应避免泄露内部堆栈。

生产环境应显式配置 `http.Server` 的读写超时和优雅停机，而不是直接依赖 `Run`。Gin 与 [[后端/Go/4. 后端开发/1. 标准库与网络编程|net/http]] 共用底层 HTTP 模型，可逐步下沉到标准库。

## 请求处理链

一次请求通常经过路由匹配、中间件链、业务 Handler、依赖访问和响应编码。中间件适合处理横切逻辑，例如请求 ID、访问日志、鉴权、限流和恢复 panic；业务规则应留在 service 层，避免把 Handler 变成巨型函数。

```go
func Auth() gin.HandlerFunc {
    return func(c *gin.Context) {
        token := c.GetHeader("Authorization")
        if token == "" {
            c.AbortWithStatusJSON(401, gin.H{"error": "missing authorization"})
            return
        }
        c.Set("subject", token)
        c.Next()
    }
}
```

`Abort` 只停止后续 Handler，已经写入的响应不会自动回滚。因此错误中间件要尽早判断状态，并确保所有失败路径 `return`。同一中间件既要能独立测试，也要能明确说明它依赖的上下文键。

## 参数绑定与校验

路径参数、查询参数、Header 和 JSON body 的来源不同，不能只依靠字段名判断可信度。绑定只负责解析，校验负责业务约束；例如 `page` 必须是正整数，邮箱格式必须符合业务要求，资源 ID 必须检查当前用户权限。

```go
type CreateUserRequest struct {
    Name  string `json:"name" binding:"required,min=1,max=64"`
    Email string `json:"email" binding:"required,email"`
}

func createUser(c *gin.Context) {
    var req CreateUserRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(400, gin.H{"error": "invalid request"})
        return
    }
    c.JSON(201, gin.H{"name": req.Name, "email": req.Email})
}
```

不要把数据库模型直接作为请求输入或响应输出。单独定义 DTO 可以避免客户端修改内部字段，也能在数据库迁移时保持 API 兼容。

## 路由与版本

推荐使用 `/api/v1` 这样的显式版本组，并按资源拆分路由文件。版本升级时优先增加字段或新路径，删除和改变字段语义需要兼容窗口。路由注册顺序应固定，避免通配路由遮蔽具体路径。

## 响应与错误

团队应统一状态码、错误码和响应结构，例如 `{code,message,request_id}`。对外返回稳定错误码，对内日志保留根因；不要把 SQL、堆栈和上游响应原文直接返回给客户端。创建资源通常返回 `201`，异步接受返回 `202`，无内容删除返回 `204`。

## 测试与部署

使用 `httptest.NewRecorder` 和 `gin.CreateTestContext` 测试路由、中间件与 Handler。测试应覆盖参数错误、认证失败、依赖超时和重复请求，而不只验证成功响应。

生产部署时使用 `http.Server`：配置 `ReadHeaderTimeout`、`ReadTimeout`、`WriteTimeout` 和 `IdleTimeout`，监听 SIGTERM 后先停止接收流量，再等待在途请求。开发环境可使用 `gin.Default()`，生产环境应明确日志格式、代理信任范围和运行模式。

## 选型边界

Gin 的优势是 API 简洁、生态成熟、迁移成本低；限制是它只覆盖 HTTP 层，依赖注入、配置、ORM、鉴权和服务治理仍需自行组合。若项目极度追求极简或特定性能模型，可比较 Echo、Fiber，但应以团队熟悉度、生态和运维能力为主要决策依据。
