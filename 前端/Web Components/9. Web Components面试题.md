# Web Components 面试题

## 1. Web Components 包含哪些核心技术？

主要包括 Custom Elements、Shadow DOM、HTML Template、Slot 和 ES Modules。Custom Elements 定义标签与生命周期，Shadow DOM 提供 DOM/样式边界，Template/Slot 负责结构复用和内容组合。它们可以独立使用。

## 2. Web Components 与 React/Vue 组件有什么区别？

Web Components 是浏览器标准和跨框架 DOM 协议，不提供完整响应式渲染、状态、路由和数据生态；React/Vue 组件依赖框架运行时但开发体验和应用生态更完整。Web Component 内部也可以使用 Lit 等库实现响应式渲染。

## 3. 自定义元素名称为什么必须包含连字符？

用于与当前和未来原生 HTML 标签保留区分，使解析器和平台注册表能够确定这是自定义元素，例如 `acme-button`。

## 4. 元素定义前出现在 DOM 会怎样？

浏览器先把它当未知 HTMLElement 解析。调用 `customElements.define()` 后，已有匹配节点被 upgrade 并执行构造与相应生命周期。组件必须处理 Attribute/子节点早已存在、脚本延迟或失败的情况。

## 5. constructor 与 connectedCallback 分别做什么？

constructor 只初始化内部字段、创建 Shadow Root 等不依赖外部 DOM 的工作；connectedCallback 在元素连接 Document 后渲染、订阅和启动观察器。连接回调可能执行多次，必须幂等。

## 6. disconnectedCallback 为什么不能简单等同于永久销毁？

节点排序、框架重排、缓存和跨容器移动都可能短暂断开再连接。应释放连接相关资源，但用户状态是否销毁要按所有权设计，不能假设断开后永不回来。

## 7. Attribute 和 Property 如何选择？

Attribute 是字符串、可声明和可序列化，适合 String/Number/Boolean/枚举配置；Property 可承载对象、函数和实例。复杂对象不应频繁 JSON 化进 Attribute。状态变化通常通过 Event 通知。

## 8. 为什么 `disabled="false"` 仍表示禁用？

HTML Boolean Attribute 只判断是否存在。`disabled="false"` 仍然存在，因此为 true；关闭应移除 Attribute 或设置对应 Property 为 false。

## 9. open 和 closed Shadow Root 有什么区别？

open 可由 `element.shadowRoot` 访问，closed 返回 null。closed 只减少普通使用者对内部 DOM 的依赖，不是安全边界，不能阻止同页面代码、调试器或扩展观察行为。

## 10. Shadow DOM 隔离了什么，没有隔离什么？

它隔离普通 CSS 选择器和 DOM 查询边界，并对事件 target 做 retargeting；可继承样式、CSS 变量、部分事件仍跨边界。它不隔离 JavaScript Realm、网络、Cookie、Storage 和权限。

## 11. 如何给 Shadow DOM 组件做主题？

用 CSS Custom Properties 暴露语义 token，用 `::part()` 暴露有限内部节点，使用 Host Attribute 表达变体。不要让消费者依赖私有 Shadow DOM 和类名。还要支持继承字体、color-scheme、RTL 和 Forced Colors。

## 12. `::slotted()` 有什么限制？

只匹配直接分配到 Slot 的元素，不能选择其任意后代，也不能直接匹配文本节点。Slotted 内容仍在 Light DOM 中并受页面 CSS 影响。

## 13. slotchange 能观察哪些变化？

它在 Slot 分配节点集合发生变化时触发。分配元素内部的文本或后代改变不一定触发；需要时对具体分配节点使用 MutationObserver，并做好重绑定和清理。

## 14. 事件的 bubbles 和 composed 有什么区别？

`bubbles` 决定事件是否沿当前 DOM 树向祖先冒泡；`composed` 决定是否能穿过 Shadow DOM 边界。公共自定义事件通常需要显式决定两者，不能把它们当成同一个开关。

## 15. 为什么外部监听到的 event.target 不是内部按钮？

Shadow DOM Event Retargeting 会把外部观察到的 target 重定向为宿主，保护内部结构。可用 `composedPath()` 调试真实路径，但消费者不应依赖私有节点。

## 16. 如何让自定义元素参与原生表单？

设置静态 `formAssociated = true`，构造时调用 `attachInternals()`，用 `setFormValue()` 提交值、`setValidity()` 设置约束校验，并实现 reset、disabled、state restore 等表单生命周期回调。

## 17. ElementInternals 解决了什么？

它让自主自定义元素访问表单关联、Constraint Validation、默认可访问性语义和自定义状态等平台能力，从而更接近原生控件。但键盘、视觉、焦点和业务校验仍需实现。

## 18. Declarative Shadow DOM 的价值是什么？

服务端可用 `<template shadowrootmode="open">` 随 HTML 输出 Shadow Tree，使浏览器解析阶段就获得结构和样式，改善 SSR 首屏和 FOUC。它不自动解决客户端 Hydration、响应式状态和事件恢复。

## 19. Lit 解决了哪些原生开发问题？

Lit 提供声明式安全模板、响应式 Property、批量更新、样式复用、Directive 和 Reactive Controller，同时最终产物仍是标准 Custom Element。它是实现层，不应泄漏为消费者协议。

## 20. Lit 中 Attribute、Property 和 Boolean 绑定怎么写？

`name=${value}` 设置 Attribute，`.user=${object}` 设置 Property，`?disabled=${bool}` 控制 Boolean Attribute，`@click=${handler}` 注册事件。对象应通过 Property 传递。

## 21. Web Components 如何与 React 集成？

React 19 已改善 Custom Element Property 和事件互操作，但仍需验证事件命名、对象 Property、SSR 和类型。复杂组件库可提供 React Wrapper，统一 ref、受控值、自定义事件 detail 和 JSX 类型。

## 22. Web Components 如何与 Vue 集成？

构建配置用 `compilerOptions.isCustomElement` 识别标签；简单值可 Attribute 绑定，对象通常用 Property 绑定；监听自定义事件时读取原始 CustomEvent 协议。还要做真实跨框架契约测试。

## 23. 为什么同一标签的多版本是难题？

CustomElementRegistry 中同名标签只能定义一次，且不能重新定义。同页两个不兼容版本可能先到先得。应统一依赖、使用组织前缀和版本治理，真正不可信/独立系统可用 iframe 隔离。

## 24. 如何避免 Web Component 内存泄漏？

在断开时移除 Window/Document 监听，断开 Observer，清除定时器，取消请求和释放第三方实例。connectedCallback 可多次执行，订阅要幂等。还要处理异步回调在断开后继续写 DOM。

## 25. Shadow DOM 一定能避免 CSS 冲突吗？

能阻止普通选择器穿透，但继承属性、CSS Custom Properties、字体和环境仍进入组件；Slotted 内容仍受外部 CSS。组件还要显式 reset 内部控件并设计主题边界。

## 26. Web Component 的性能一定比框架组件好吗？

不一定。平台标准减少了部分适配层，但性能仍取决于 DOM 数量、渲染算法、样式复杂度、Observer、监听器和内部运行时。Shadow Root 本身不会让大列表自动变快，必须基于真实实例测量。

## 27. 如何设计跨框架组件的公共 API？

简单配置使用 Attribute，复杂数据用 Property，命令用 Method，变化用 Event，消费者内容用 Slot，主题用 Token/Part。API 要稳定、可类型化、符合原生 HTML 心智，并在原生、React、Vue 中做契约测试。

## 28. Web Components 与微前端是什么关系？

Web Components 可作为微前端的组件边界和样式封装方案，但不自动解决路由、资源加载、应用生命周期、状态通信、鉴权、部署和多版本依赖。应用级强隔离仍可能需要 iframe 或专用微前端框架。

## 29. 什么场景不适合 Web Components？

单一框架内部的一次性业务组件、强依赖框架 Context/Server Components 的 UI，或需要运行不可信代码的场景。后者应使用 sandbox iframe/独立 Origin，而不是误把 Shadow DOM 当安全沙箱。

## 30. 如何测试一个 Web Component？

在真实浏览器中测试 Attribute/Property、生命周期、Event、Slot、表单、焦点和可访问语义；E2E 覆盖 Chromium/Firefox/WebKit 及 React/Vue 集成；补充键盘、读屏、视觉、SSR/升级前和断开重连场景。
