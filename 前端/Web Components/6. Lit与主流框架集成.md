# Lit 与主流框架集成

原生 Web Components API 不提供响应式状态、声明式模板和更新调度。Lit 是轻量的 Web Components 开发库，在保留标准 Custom Element 接口的同时提供这些能力。

## Lit 基础示例

```ts
import { LitElement, css, html } from 'lit'
import { customElement, property, state } from 'lit/decorators.js'

@customElement('acme-counter')
export class AcmeCounter extends LitElement {
  static styles = css`
    :host { display: inline-flex; gap: 8px; align-items: center; }
    button { font: inherit; }
  `

  @property({ type: Number, reflect: true })
  count = 0

  @state()
  private busy = false

  render() {
    return html`
      <output aria-live="polite">${this.count}</output>
      <button ?disabled=${this.busy} @click=${this.increment}>增加</button>
    `
  }

  private increment() {
    this.count += 1
    this.dispatchEvent(new CustomEvent('count-change', {
      detail: { count: this.count },
      bubbles: true,
      composed: true,
    }))
  }
}

declare global {
  interface HTMLElementTagNameMap {
    'acme-counter': AcmeCounter
  }
}
```

Lit 模板不是字符串拼接。表达式按位置区分文本、Attribute、Property、Boolean Attribute 和事件绑定，动态值默认经过安全处理。

## 模板绑定

```ts
html`
  <user-card
    name=${this.name}
    .user=${this.user}
    ?selected=${this.selected}
    @user-open=${this.handleOpen}
  ></user-card>
`
```

| 语法 | 含义 |
| --- | --- |
| `name=${value}` | 设置 Attribute |
| `.user=${object}` | 设置 Property |
| `?selected=${bool}` | 按布尔值添加/移除 Attribute |
| `@event=${handler}` | 添加事件监听 |
| `${value}` | 文本/子模板表达式 |

数组可直接映射模板；需要稳定 DOM 身份和重排性能时使用 `repeat` directive 和稳定 key。不要把服务端字符串交给 `unsafeHTML`，除非已建立可信类型和严格净化边界。

## 响应式 Property

`@property` 定义公共响应式 Property，可配置 Attribute 名、类型转换、反射和变化判断。`@state` 用于私有响应式状态，不形成 Attribute API。

对象内部原地修改不会改变引用，因此通常不会触发更新：

```ts
// 不推荐：this.user 引用没变
this.user.name = 'Grace'

// 推荐：不可变更新
this.user = { ...this.user, name: 'Grace' }
```

如确实由外部系统原地修改，可调用 `requestUpdate()`，但长期应明确数据所有权，避免隐式共享可变对象。

## 更新生命周期

Lit 将同步 Property 变化批量合并到微任务更新。常用钩子：

- `willUpdate(changedProperties)`：渲染前派生计算；
- `render()`：返回纯模板；
- `firstUpdated()`：首次 DOM 更新后访问节点或启动一次性逻辑；
- `updated(changedProperties)`：每次更新后执行必要副作用；
- `updateComplete`：等待当前更新完成；
- `shouldUpdate()`：按条件跳过本轮渲染。

不要在 `updated` 无条件修改响应式 Property，否则可能产生更新循环。请求应与输入版本/AbortController 绑定，组件断开时取消。

## Query 与 Ref

简单场景可用 `@query` 获取内部节点，动态列表或复用模板更适合 `ref` directive。不要在 `render()` 中查询 DOM，因为此时新模板尚未提交。

```ts
@query('input')
private input!: HTMLInputElement

focus(options?: FocusOptions) {
  this.input?.focus(options)
}
```

## Reactive Controller

Controller 把可复用状态和生命周期逻辑组合到多个 LitElement，例如响应式媒体查询、ResizeObserver、本地化和异步任务。

Controller 不是全局 Store；它跟随 Host 连接、断开和更新。公共 Controller 应清楚释放外部资源，并避免在每个组件实例重复创建昂贵服务。

## React 集成

React 19 改善了 Custom Element 的 Property、Attribute 和自定义事件互操作，但团队仍应验证 SSR、事件命名、类型和受控表单语义。

```tsx
import { useEffect, useRef } from 'react'

export function RatingField() {
  const ref = useRef<HTMLElement & { value: string }>(null)

  useEffect(() => {
    const node = ref.current
    if (!node) return

    const onChange = (event: Event) => {
      const value = (event as CustomEvent<{ value: string }>).detail.value
      console.log(value)
    }

    node.addEventListener('value-change', onChange)
    return () => node.removeEventListener('value-change', onChange)
  }, [])

  return <acme-rating ref={ref} name="score" />
}
```

事件若不能直接按 JSX 预期绑定，使用 ref + `addEventListener` 或为组件库生成 React Wrapper。Wrapper 还能统一类型、事件 payload、受控值和 React ref。

React JSX 类型可在组件包中声明：

```ts
import type { DetailedHTMLProps, HTMLAttributes } from 'react'

type AcmeRatingElement = HTMLElement & {
  name: string
  value: string
}

declare module 'react' {
  namespace JSX {
    interface IntrinsicElements {
      'acme-rating': DetailedHTMLProps<
        HTMLAttributes<AcmeRatingElement>,
        AcmeRatingElement
      > & { name?: string; value?: string }
    }
  }
}
```

声明方式需与组件包支持的 React/TypeScript 版本验证，避免污染或覆盖消费者已有 JSX 类型。

## Vue 集成

Vue 需要在编译器配置中识别自定义元素，避免把它解析为未注册 Vue 组件：

```ts
// vite.config.ts
import vue from '@vitejs/plugin-vue'

export default {
  plugins: [
    vue({
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith('acme-'),
        },
      },
    }),
  ],
}
```

```vue
<script setup lang="ts">
import { ref } from 'vue'

const user = ref({ id: 1, name: 'Ada' })
</script>

<template>
  <acme-user-card
    :user.prop="user"
    @user-open="handleOpen"
  />
</template>
```

对象应通过 DOM Property 而非字符串 Attribute 传入。自定义事件 detail 与 Vue emit 参数并不完全相同，事件处理器要读取实际 Event 协议。

## Angular、Svelte 与原生 HTML

- Angular 消费 Custom Element 时配置对应 schema，并为 Property/Event 提供类型或 Wrapper；
- Svelte 对自定义元素有直接 DOM 互操作，但仍要核对对象 Property 和事件；
- 原生 HTML 可用 `querySelector`、Property 和 `addEventListener`，是最小兼容基线；
- 任何框架都不能替组件自动补全无障碍、表单和生命周期语义。

不同框架对“值应该成为 Attribute 还是 Property”的策略、SSR 序列化和事件名转换不同。组件库应维护一个跨框架契约测试页，而不是只在 Storybook 单环境验证。

## 是否需要 Lit

适合使用 Lit：

- 组件有多个响应式状态和条件模板；
- 需要高效局部更新、Directive、Controller 和样式管理；
- 希望交付标准 Custom Element，而不自行维护渲染器。

原生 API 已足够：

- 元素只增强很小一段既有 HTML；
- 几乎没有状态和重渲染；
- 组件对零运行时和极小体积有严格要求。

Lit 是实现细节，不应泄漏到公共 DOM 协议。消费者只依赖标签、Property、Attribute、Event、Slot、Part 和 Method，未来才有机会更换内部实现。
