# 组件设计、性能与安全实践

生产级 Web Component 的价值来自稳定的浏览器协议和跨项目一致行为，而不只是把现有 DOM 包进 Shadow Root。

## 公共 API 分层

| API | 适合内容 | 示例 |
| --- | --- | --- |
| Attribute | 可声明简单配置 | `disabled`、`variant="danger"` |
| Property | 对象、函数、实时状态 | `dialog.data = order` |
| Method | 明确命令 | `showModal()`、`validate()` |
| Event | 状态变化/请求协作 | `value-change`、`request-close` |
| Slot | 消费者拥有的复杂内容 | `title`、`actions` |
| CSS Custom Property | 主题 token | `--acme-color-primary` |
| CSS Part | 有限内部样式入口 | `::part(trigger)` |

先写 API 表再写组件实现。每项说明类型、默认值、反射、事件时机、错误语义和可访问性影响。

## 设计原则

### 遵循原生 HTML 心智

- Boolean Attribute 按存在性判断；
- `disabled` 阻止交互、从适当焦点顺序移除并更新语义；
- 输入区分初始值和当前 value；
- 交互控件支持 `focus()` 和键盘；
- 变更事件时机尽量与相似原生控件一致；
- 表单控件参与 FormData、Reset 和 Constraint Validation。

### 保持实现可替换

消费者不能依赖 `shadowRoot.querySelector('.internal-x')`。公开定制通过 Part/Token/Slot，公开行为通过 Property/Method/Event。内部类名、DOM 层级和渲染库都不应成为契约。

### 组合优于巨型配置

简单外观用枚举 Attribute，复杂内容用 Slot，领域数据用 Property。不要创建几十个互相影响的 Boolean Attribute；状态组合爆炸时拆组件或提供更清晰的子元素协议。

## 受控与非受控状态

非受控组件管理自身状态，外部监听变化；受控组件由外部持续写入状态。必须明确选择，否则容易出现事件后立即被旧值覆盖。

```text
非受控：default-value -> 内部 value -> value-change
受控：外部 value -> 用户意图事件 -> 外部更新 value
```

可同时支持时，参考原生 `value/defaultValue`，并规定从受控切换到非受控是否允许。不要在组件内部无条件把外部 Property 复制成另一份长期状态。

## 错误与异步状态

异步组件至少区分 idle、loading、success、empty、error 和 canceled。新请求开始时取消旧请求或使用递增版本忽略过期结果：

```ts
class UserLookup extends HTMLElement {
  #request?: AbortController
  user: unknown = null

  async load(userId: string) {
    this.#request?.abort()
    const request = new AbortController()
    this.#request = request

    try {
      const response = await fetch(`/api/users/${encodeURIComponent(userId)}`, {
        signal: request.signal,
      })
      if (!response.ok) throw new Error(`HTTP ${response.status}`)
      const user = await response.json()
      if (this.#request === request) this.user = user
    } catch (error) {
      if (!request.signal.aborted) this.showError(error)
    }
  }

  disconnectedCallback() {
    this.#request?.abort()
  }

  showError(_error: unknown) {
    this.dispatchEvent(new CustomEvent('load-error', {
      detail: { code: 'USER_LOAD_FAILED' },
      bubbles: true,
      composed: true,
    }))
  }
}
```

错误事件不要泄漏凭证、内部 URL 或完整响应。面向用户的错误信息与监控诊断信息分开。

## 渲染性能

- 更新已有节点，避免每次 `innerHTML` 重建整棵树导致焦点和表单状态丢失；
- 合并同一任务中的多次更新；
- 不在 `attributeChangedCallback` 反复强制布局；
- 读布局和写样式分批，动画写入 rAF；
- 大列表仍需虚拟化，Shadow DOM 不降低节点成本；
- 多实例共享静态模板、Constructable Stylesheet 和只读数据；
- ResizeObserver/IntersectionObserver 回调保持轻量并正确断开；
- 通过 Performance Panel、User Timing 和内存快照测量，不靠猜测。

Shadow Root 数量本身不是唯一瓶颈。实际成本来自实例 DOM 节点、样式复杂度、Observer、监听器、布局和框架运行时。用接近生产数量的实例做基准。

## 加载与定义策略

### 静态注册

入口直接 import 并 define，最简单稳定，适合关键组件。

### 按需加载

```ts
const components: Record<string, () => Promise<unknown>> = {
  'acme-chart': () => import('./chart/define.js'),
  'acme-editor': () => import('./editor/define.js'),
}

const observer = new IntersectionObserver((entries) => {
  for (const entry of entries) {
    if (!entry.isIntersecting) continue
    const tag = entry.target.localName
    components[tag]?.()
    observer.unobserve(entry.target)
  }
})

document.querySelectorAll('acme-chart, acme-editor').forEach((node) => observer.observe(node))
```

只对非关键且体积明显的组件懒加载。要处理加载中样式、模块失败、组件进入视口前被交互，以及预加载时机。不能因为懒加载造成核心按钮点击无响应。

## 标签与版本冲突

Custom Element 标签注册后不能重新定义。同页加载两个不兼容版本可能先到先得，出现静默错误。

治理方式：

- 应用/基座统一依赖版本；
- 组件标签加组织前缀；
- 单例依赖通过包管理器和 Module Federation 等统一；
- 跨组织不可信集成使用 iframe/独立 Origin；
- 确需长期并存时使用不同标签主版本，例如 `acme2-button`，但会增加迁移成本。

不要把“若已注册就跳过”当完整版本兼容方案。

## 安全威胁模型

### XSS

不可信值使用 `textContent` 或 Lit 安全表达式，不直接进入 `innerHTML`。富文本必须经过上下文正确的净化；启用 CSP 和 Trusted Types 的项目中，组件也要遵守统一策略。

Slot 内容来自消费者，组件若移动、克隆或重新序列化它，必须维持信任边界。不要自动执行 Slotted script、事件字符串或不可信 URL。

### URL 与导航

对 href、src、action、Deep Link 等验证协议和目标。阻止 `javascript:`、危险 data URL、Open Redirect 和反向 Tabnabbing；外部新窗口使用正确的 `noopener` 策略。

### Shadow DOM 误区

open/closed 都不能隔离同页面恶意脚本。组件公开 Method 不是权限接口，所有服务端操作仍需鉴权、授权、CSRF/Token 校验和输入验证。

### 第三方组件

第三方 Web Component 与页面处于同一 Origin 权限环境，可以读取 DOM、Cookie 可见信息和 Storage。真正不可信的代码应放在 sandbox iframe、受限 Origin 或其他隔离环境。

## CSP 与资源

- 避免依赖 `eval`/动态 Function；
- 内联 style 是否允许取决于 CSP，构建和部署策略需配合 nonce/hash 或允许的样式方案；
- 动态 import/CDN 资源受 `script-src`、`connect-src`、`img-src` 等限制；
- 第三方 CDN 考虑版本固定、SRI、缓存和不可用回退；
- 组件包不要偷偷注入远程脚本或上报数据，网络行为应可审计。

## 国际化

- 文本由外部 Slot/Property 或统一消息系统提供，内部不硬编码业务文案；
- 使用 `Intl.NumberFormat`、`DateTimeFormat`、`PluralRules`，不手写区域格式；
- 响应 `lang`、`dir` 变化，不能只在构造时读取一次；
- CSS 用逻辑属性 `margin-inline`、`padding-block`；
- RTL 不只是镜像，图标、时间轴、数字和混合文本需单独验证；
- 文案增长 30% 以上仍不截断关键操作。

## 监控与调试

组件错误上报包含组件版本、标签、公共状态和宿主应用标识，但不记录敏感 Property/Slot 文本。关键异步流程可使用 User Timing：

```ts
performance.mark('acme-chart:start')
// render
performance.mark('acme-chart:end')
performance.measure('acme-chart:render', 'acme-chart:start', 'acme-chart:end')
```

组件库不要各自绑定一套不可关闭的监控 SDK。暴露钩子/事件或接入宿主的 Observability adapter，统一采样和隐私策略。

## 评审清单

- 公共 API 是否能仅凭 Attribute/Property/Event/Slot/Part 理解；
- 是否复用原生元素语义，而不是从 div 重造；
- 多次 connect/disconnect、DOM 移动和多个实例是否正确；
- 未定义、慢加载、失败和无 JS 是否可接受；
- 键盘、读屏、RTL、缩放、Reduced Motion 是否可用；
- 更新是否保留焦点、选区、滚动和输入值；
- 不可信文本、HTML、URL 和第三方资源是否有明确边界；
- React/Vue/SSR/表单集成是否有契约测试；
- 标签、Event、Slot、Part 和 Token 变更是否按 SemVer 管理；
- 性能结论是否来自真实浏览器和实际实例规模。
