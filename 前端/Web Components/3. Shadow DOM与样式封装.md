# Shadow DOM 与样式封装

Shadow DOM 把组件内部 DOM 放入独立树中，提供选择器和 DOM 查询边界，同时通过 Slot、CSS Custom Properties、Part 和 Event 与外部协作。

## 创建 Shadow Root

```ts
class UserAvatar extends HTMLElement {
  constructor() {
    super()
    const root = this.attachShadow({
      mode: 'open',
      delegatesFocus: true,
    })
    root.innerHTML = `
      <style>
        :host { display: inline-block; }
        img { display: block; border-radius: 50%; }
      </style>
      <img part="image" alt="">
    `
  }
}
```

- `open`：使用者可通过 `element.shadowRoot` 访问；
- `closed`：`element.shadowRoot` 返回 `null`，但不是安全边界；
- `delegatesFocus`：点击不可聚焦区域时可把焦点委托给内部可聚焦元素，并影响 `:focus` 表现。

通常使用 open，方便调试、测试和平台工具。closed 只表达“不把内部 DOM 当公共 API”，无法阻止同页面恶意代码或浏览器扩展观察实现。

## 封装规则

外部普通选择器不会选中 Shadow Tree 内部节点，内部选择器也不会选中外部 Light DOM。`document.querySelector()` 不会穿透边界，内部用 `shadowRoot.querySelector()`。

仍会跨边界的内容包括：

- 可继承 CSS 属性，如 `color`、`font-family`；
- CSS Custom Properties；
- 文档级环境，如字体、方向、缩放、Forced Colors；
- 由配置决定的 Event；
- JavaScript 全局变量、网络、存储等，Shadow DOM 不隔离它们。

## Host 选择器

```css
:host {
  display: inline-flex;
  color: var(--tag-color, CanvasText);
}

:host([hidden]) {
  display: none;
}

:host([variant='danger']) {
  --tag-color: #b42318;
}

:host(:focus-visible) {
  outline: 2px solid Highlight;
  outline-offset: 2px;
}
```

`:host` 选择宿主元素，`:host(...)` 根据宿主状态选择。宿主的页面作者样式与组件默认样式存在层叠关系；组件应提供合理默认值，但允许消费者控制布局位置、margin 和尺寸。

`:host-context()` 可基于外部祖先匹配，但会增加对页面结构的依赖。主题优先使用 Custom Properties、属性或 `color-scheme`，不要依赖深层祖先类名。

## CSS Custom Properties 作为主题 Token

```css
:host {
  --_background: var(--acme-button-background, #1769e0);
  --_foreground: var(--acme-button-foreground, white);
}

button {
  background: var(--_background);
  color: var(--_foreground);
}
```

```css
acme-button {
  --acme-button-background: rebeccapurple;
}
```

公共 Token 使用稳定前缀；以下划线命名的内部变量不要写入文档。Token 过多会使内部实现被外部耦合，优先暴露语义级颜色、间距和尺寸，而不是每个像素。

Custom Property 继承进入 Shadow Tree，因此不应把未经约束的字符串直接拼到危险的 URL/内容上下文。为关键属性提供 fallback，并测试无 Token、非法 Token、深色和高对比模式。

## CSS Shadow Parts

组件用 `part` 暴露可定制内部节点：

```html
<button part="button">
  <span part="label"><slot></slot></span>
</button>
```

消费者通过 `::part()` 样式化：

```css
acme-button::part(button) {
  border-radius: 999px;
}
```

Part 是明确的样式 API，比穿透 Shadow DOM 稳定。Part 名一旦公开就要进行版本治理；它只允许选择已暴露节点，不能用 `::part(button) span` 任意深入内部树。

嵌套组件可用 `exportparts` 转发内部 Part：

```html
<acme-icon exportparts="svg: leading-icon"></acme-icon>
```

## Slotted 内容样式

```css
::slotted(img) {
  max-inline-size: 100%;
}
```

`::slotted()` 只匹配直接分配到 Slot 的元素，不能深入其后代；文本节点也不能直接选中。需要更强控制时，要求消费者提供特定自定义元素/类，或用包装层和公共 Part 设计协议。

Slotted 节点仍属于 Light DOM，外部页面 CSS 继续作用于它。Shadow DOM 不会替消费者内容建立完整样式隔离。

## 样式加载策略

### 内联 style

简单、无额外请求，适合小组件；每个实例都包含 style 节点，但现代浏览器可能共享内部样式数据，仍应通过 Profile 判断影响。

### Constructable Stylesheet

```ts
const sheet = new CSSStyleSheet()
sheet.replaceSync(`
  :host { display: inline-block; }
  button { font: inherit; }
`)

class AcmeButton extends HTMLElement {
  constructor() {
    super()
    const root = this.attachShadow({ mode: 'open' })
    root.adoptedStyleSheets = [sheet]
    root.innerHTML = '<button part="button"><slot></slot></button>'
  }
}
```

多个实例共享同一个 `CSSStyleSheet`，更新 sheet 会影响所有采用者。使用前确认目标浏览器范围；需要 SSR 或更广兼容时准备内联 `<style>` 路径。

### 外部 link

Shadow Root 可放 `<link rel="stylesheet">`，但加载有异步闪烁和大量实例请求协调问题。组件库通常将关键样式随模块打包或使用共享 stylesheet。

## Reset 与页面适配

Shadow Tree 不继承页面的所有 reset，因此内部显式设置：

```css
:host {
  box-sizing: border-box;
  font: inherit;
  color: inherit;
}

*, *::before, *::after {
  box-sizing: inherit;
}

button, input, textarea, select {
  font: inherit;
}
```

不要全局重置宿主的 margin、position 或宽度，组件的外部布局应由使用者控制。组件内部支持 `dir="rtl"`、`writing-mode`、系统字体缩放、`prefers-reduced-motion`、`forced-colors` 和 `color-scheme`。

## Shadow DOM 不等于安全

- closed Root 可以被浏览器调试工具看到；
- XSS 与组件处于同一 Origin/JavaScript Realm，仍可调用公共方法和修改输入；
- Slot 可接收不可信节点，渲染 HTML 仍要净化；
- Shadow DOM 不限制 Fetch、Cookie、Storage 和全局事件；
- 需要运行不可信第三方代码时应考虑 CSP、Sandbox iframe 和不同 Origin。

## 常见问题

- 页面主题进不去：检查 CSS Custom Property、继承属性和 `color-scheme`；
- 外部样式改不到内部：应通过 Token/Part，不要依赖私有 DOM；
- `::slotted(.x span)` 不生效：只能匹配直接分配节点；
- Portal 弹层丢失主题：弹层被挂到 Document 后不再处于原 Shadow Root，需要容器/Token 转发策略；
- 事件 target 变成宿主：这是事件 retargeting，使用 `composedPath()` 理解真实路径；
- 测试查不到节点：测试工具默认不穿透 Shadow Root，应显式进入 shadowRoot 或以公共行为断言。
