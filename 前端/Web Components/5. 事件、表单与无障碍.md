# 事件、表单与无障碍

一个 Web Component 是否真正可复用，取决于它能否像原生 HTML 元素一样通过 Property、Event、表单和无障碍树与宿主页面协作。

## 自定义事件协议

组件通过 `CustomEvent` 通知外部状态变化：

```ts
this.dispatchEvent(new CustomEvent('value-change', {
  detail: { value: this.value },
  bubbles: true,
  composed: true,
}))
```

- `detail`：结构化 payload；
- `bubbles`：是否沿 DOM 祖先冒泡；
- `composed`：是否允许穿过 Shadow DOM 边界；
- `cancelable`：外部能否用 `preventDefault()` 取消默认动作。

事件名建议使用小写 kebab-case 并带稳定语义，例如 `value-change`、`request-close`。避免用内部实现名或与原生事件混淆。

## 可取消默认动作

```ts
const accepted = this.dispatchEvent(new CustomEvent('before-close', {
  detail: { reason: 'escape' },
  bubbles: true,
  composed: true,
  cancelable: true,
}))

if (accepted) this.close()
```

`dispatchEvent()` 在事件被取消时返回 `false`。只为调用方确实需要阻止的同步默认动作提供 cancelable；异步确认更适合显式方法/Promise 协议，事件系统不会等待异步 listener。

## 事件 Retargeting

事件穿过 Shadow 边界时，外部看到的 `event.target` 可能被重定向为宿主元素，以隐藏内部节点。`event.composedPath()` 能查看事件传播路径，但业务方不应依赖组件的私有节点顺序。

并非所有事件都穿透 Shadow Root。例如某些事件不冒泡或不 composed。自定义公共事件要显式决定行为，不能依赖默认值。

监听公共事件：

```js
document.addEventListener('value-change', (event) => {
  const source = event.target
  console.log(source, event.detail.value)
})
```

对于高频拖动，不要每帧发巨大 detail；事件协议同样需要考虑频率、对象所有权和取消订阅。

## Property、Method 与 Event 分工

- Property：读取/设置组件当前状态或配置；
- Method：显式执行命令，如 `open()`、`focus()`、`validate()`；
- Event：组件已经发生或请求外部参与的变化；
- Attribute：HTML 中可声明、可序列化的简单配置。

避免把命令设计成瞬时 Attribute，例如反复设置 `action="save"`。避免要求消费者写入只读状态 Property；只读状态用 Event + Getter 表达。

## Form-associated Custom Element

ElementInternals 允许自主自定义元素参与原生表单提交、校验和状态恢复。

```ts
class AcmeRating extends HTMLElement {
  static formAssociated = true
  static observedAttributes = ['disabled', 'required']

  #internals: ElementInternals
  #value = ''

  constructor() {
    super()
    this.#internals = this.attachInternals()
  }

  get form() {
    return this.#internals.form
  }

  get name() {
    return this.getAttribute('name') ?? ''
  }

  get type() {
    return this.localName
  }

  get value() {
    return this.#value
  }

  set value(value: string) {
    this.#value = value
    this.#internals.setFormValue(value)
    this.#validate()
  }

  get disabled() {
    return this.hasAttribute('disabled')
  }

  formResetCallback() {
    this.value = this.getAttribute('value') ?? ''
  }

  formDisabledCallback(disabled: boolean) {
    this.toggleAttribute('data-form-disabled', disabled)
  }

  formStateRestoreCallback(state: string) {
    this.value = state
  }

  #validate() {
    const missing = this.hasAttribute('required') && !this.value
    this.#internals.setValidity(
      missing ? { valueMissing: true } : {},
      missing ? '请选择评分' : '',
    )
  }
}
```

`setFormValue(value, state?)` 的第一个参数参与提交，第二个参数可用于状态恢复。复杂值可传 FormData；禁用元素不应提交。

## 表单校验

ElementInternals 提供 `validity`、`validationMessage`、`willValidate`、`checkValidity()` 和 `reportValidity()` 等与原生控件接近的能力。

组件应同时提供：

- 可见错误文本；
- `aria-invalid`/描述关系等读屏信息；
- 聚焦到真实可操作位置；
- 浏览器原生表单阻止提交能力；
- 服务端再次校验，客户端校验不能作为安全边界。

不要只调用 `setValidity` 而不给用户说明。测试原生 `<form>.reset()`、fieldset disabled、Enter 提交、FormData、自动填充和历史状态恢复。

## ElementInternals 与无障碍语义

可为宿主提供默认语义，而不强制写成外部 Attribute：

```ts
class AcmeSwitch extends HTMLElement {
  #internals = this.attachInternals()

  constructor() {
    super()
    this.#internals.role = 'switch'
    this.#syncA11y()
  }

  #syncA11y() {
    this.#internals.ariaChecked = String(this.checked)
    this.#internals.ariaDisabled = String(this.disabled)
  }
}
```

实际 ElementInternals 可访问性 API 支持应按目标浏览器测试，并提供必要 Attribute 回退。内部语义不会自动实现键盘操作和视觉状态。

## 键盘与焦点

复合组件应遵循 WAI-ARIA Authoring Practices 的成熟交互模式，而不是自行发明：

- Button：Enter/Space 激活；
- Dialog：打开后合理聚焦，Tab 限制在模态区域，Esc 关闭，关闭后恢复焦点；
- Tabs：方向键移动，Home/End 跳转，选中与焦点策略一致；
- Listbox/Menu：Roving tabindex、方向键和字符搜索；
- Combobox：输入、弹层、选项和 `aria-activedescendant` 协同。

宿主 `tabindex="0"` 与内部真实按钮的取舍要明确，避免一个组件出现重复 Tab Stop。`delegatesFocus` 可以改善部分行为，但不能替代完整焦点管理。

## Label 与名称

所有交互组件必须有 Accessible Name。优先让使用者提供可见文本或明确 `label`/`aria-label` API。图标按钮不能只靠 `title`。

Shadow 边界可能影响跨树 IDREF 关系，`<label for>`、`aria-labelledby` 和 `aria-describedby` 必须在 Safari、Chromium、Firefox 及实际读屏软件验证。表单关联组件可以使用 `ElementInternals.labels` 获取关联 Label。

## 状态与样式

原生状态可用 `:disabled`、`:invalid` 等选择器的支持取决于组件和浏览器能力；宿主 Attribute 也是可预测的公共样式入口。ElementInternals 的 CustomStateSet 可表达内部布尔状态，并通过 `:state()` 选择，但需要结合目标浏览器支持策略。

```ts
if (this.loading) {
  this.#internals.states.add('loading')
} else {
  this.#internals.states.delete('loading')
}
```

```css
:host(:state(loading)) {
  cursor: progress;
}
```

即便使用自定义状态，也要向无障碍树暴露对应 busy、expanded、checked 等标准语义。

## 无障碍测试

- 键盘完整走通，不使用鼠标；
- Chrome/Firefox Accessibility Tree 检查名称、角色和值；
- VoiceOver + Safari、NVDA/JAWS + Chromium/Firefox 做关键流程；
- 字体放大、页面缩放、Forced Colors、深色和 Reduced Motion；
- 自动化 axe 可发现基础问题，但不能验证完整键盘语义和读屏体验；
- 测试未定义、自定义元素升级前后的内容是否仍可理解。

## 常见错误

- 事件默认 `composed: false`，外部监听不到；
- 所有内部事件都直接穿透，泄漏实现细节；
- 用 change/input 名称却不遵循原生触发时机和 payload 心智；
- 组件看起来像按钮，却没有键盘、焦点和 Disabled 行为；
- 自定义输入只更新 UI，没有加入 FormData 或原生校验；
- `aria-*` 写在 Shadow 内部错误节点，宿主在辅助技术中仍无名称；
- 弹层关闭后焦点丢到 body；
- 只通过颜色表达 invalid、selected 或 disabled。
