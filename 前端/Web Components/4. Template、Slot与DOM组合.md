# Template、Slot 与 DOM 组合

`<template>` 提供惰性的 DOM 蓝图，Slot 把 Light DOM 内容投影到 Shadow Tree。它们共同解决组件内部结构复用和外部内容组合，但不会自动提供数据绑定。

## HTML Template

Template 内容位于 `template.content` 的 `DocumentFragment` 中，页面解析时不会正常渲染，内部图片、脚本等资源行为也与直接放入 Document 不同，克隆并插入后才成为活动 DOM。

```html
<template id="user-row-template">
  <li class="user-row">
    <strong data-name></strong>
    <button type="button">查看</button>
  </li>
</template>

<ul id="users"></ul>
```

```js
const template = document.querySelector('#user-row-template')
const list = document.querySelector('#users')

for (const user of users) {
  const fragment = template.content.cloneNode(true)
  fragment.querySelector('[data-name]').textContent = user.name
  fragment.querySelector('button').addEventListener('click', () => openUser(user.id))
  list.append(fragment)
}
```

使用 `textContent` 写入不可信文本。不要为了模板便利直接拼接 `innerHTML`；确需富文本时使用可信模板或经过审计的 Sanitizer。

## 在自定义元素中使用 Template

```html
<template id="alert-template">
  <style>
    :host { display: block; }
    [part='panel'] { padding: 12px; border: 1px solid; }
  </style>
  <section part="panel" role="status">
    <slot name="icon"></slot>
    <slot></slot>
  </section>
</template>
```

```ts
const alertTemplate = document.querySelector<HTMLTemplateElement>('#alert-template')!

class AcmeAlert extends HTMLElement {
  constructor() {
    super()
    const root = this.attachShadow({ mode: 'open' })
    root.append(alertTemplate.content.cloneNode(true))
  }
}
```

Template 节点若来自业务页面，会让组件定义依赖加载顺序和外部 ID。可发布组件通常把模板放在模块内，或由构建器导入；页面级组件可以复用文档 Template。

## 默认 Slot 与命名 Slot

```html
<!-- 组件内部 -->
<article>
  <header><slot name="title">默认标题</slot></header>
  <div><slot></slot></div>
  <footer><slot name="actions"></slot></footer>
</article>
```

```html
<!-- 使用组件 -->
<acme-card>
  <h2 slot="title">订单 #1024</h2>
  <p>订单已经发货。</p>
  <button slot="actions">查看物流</button>
</acme-card>
```

没有 `slot` 属性的 Light DOM 子节点进入默认 Slot。找不到匹配 Slot 的节点不会显示。Slot 自身的回退内容只在没有分配节点时展示。

## Slot 分配与查询

```ts
class AcmeTabs extends HTMLElement {
  #slot!: HTMLSlotElement

  constructor() {
    super()
    const root = this.attachShadow({ mode: 'open' })
    root.innerHTML = '<div role="tablist"><slot name="tab"></slot></div><slot></slot>'
    this.#slot = root.querySelector('slot[name="tab"]')!
  }

  connectedCallback() {
    this.#slot.addEventListener('slotchange', this.#onSlotChange)
    this.#syncTabs()
  }

  disconnectedCallback() {
    this.#slot.removeEventListener('slotchange', this.#onSlotChange)
  }

  #onSlotChange = () => this.#syncTabs()

  #syncTabs() {
    const tabs = this.#slot.assignedElements({ flatten: true })
    tabs.forEach((tab, index) => {
      tab.setAttribute('role', 'tab')
      tab.setAttribute('tabindex', index === 0 ? '0' : '-1')
    })
  }
}
```

- `assignedNodes()` 返回文本和元素节点；
- `assignedElements()` 只返回元素；
- `{ flatten: true }` 展开嵌套 Slot 的最终分配结果；
- `slotchange` 在分配节点集合变化时触发，不会因为分配节点内部文本/后代变化而必然触发。

需要观察 Slotted 节点内部变化时，可再对具体节点使用 MutationObserver，但应限定范围并在节点替换时重新绑定。

## Light DOM 与 Shadow DOM 的职责

Light DOM 适合使用者拥有的内容：标题、正文、操作按钮、列表项。Shadow DOM 适合组件拥有的结构：布局容器、内部控制器、状态图标和实现细节。

好的 Slot API 描述语义而不是位置：`title`、`actions`、`media` 比 `left`、`right`、`top` 更适应 RTL 和布局重构。

不要为每个内部小节点都开放 Slot，否则消费者会依赖实现细节。固定文本可优先 Attribute/Property，复杂可交互内容再用 Slot。

## Slot 与可访问性

内容投影不自动产生正确组件语义。Tabs、Menu、Dialog 等复合组件仍要管理 role、ARIA 状态、焦点顺序和键盘交互。

尽量让消费者提供原生语义节点，例如要求 action Slot 放 `<button>`，而不是接收任意 `<div>` 后偷偷模拟按钮。组件在运行时可以校验 Slot 内容，并在开发环境给出明确警告。

跨 Shadow 边界的 `aria-labelledby`、`aria-describedby` 和 ID 引用存在平台与浏览器差异，设计时不要只依赖一个跨树 ID。可使用 ElementInternals、宿主标签、可见文本和实际辅助技术测试验证。

## Declarative Shadow DOM

服务端输出可声明 Shadow Root：

```html
<acme-card>
  <template shadowrootmode="open">
    <style>:host { display: block; }</style>
    <article><slot></slot></article>
  </template>
  服务端已经输出的内容
</acme-card>
```

支持的浏览器在解析 HTML 时直接建立 Shadow Root，无需等待 JavaScript，因此适合 SSR、首屏和无闪烁样式。组件构造函数必须复用已有 Shadow Root：

```ts
class AcmeCard extends HTMLElement {
  constructor() {
    super()
    const root = this.shadowRoot ?? this.attachShadow({ mode: 'open' })
    // 如果服务端已提供结构，在此绑定行为而不是重复覆盖。
  }
}
```

Declarative Shadow DOM 解决声明和首屏问题，不自动完成响应式 Hydration、事件恢复和状态同步。服务端与客户端仍要共享模板契约并处理版本不一致。

## DOM 组合模式

### Container + Item

`acme-tabs` 管理多个 `acme-tab`，父级负责选择和键盘导航，子级封装单项。这种协议需定义注册、移动、禁用和动态删除行为。

### Headless controller

自定义元素只提供状态和行为，使用者通过 Slot 提供 UI。灵活但更难保证语义、样式和交互一致。

### Compound element

一个元素内部固定实现全部结构，只暴露少量 Attribute/Event。API 稳定、易使用，但定制空间较小，适合按钮、Badge 等原子组件。

## 常见错误

- 把 Slot 名按视觉方向命名，阻碍 RTL 和响应式改版；
- 假设 `slotchange` 能观察分配内容的所有后代变化；
- 修改消费者 Slotted DOM 后不在销毁时恢复，造成所有权混乱；
- Slot 太多，使内部 DOM 结构事实上成为公共 API；
- Template 每次更新整棵 clone，丢失焦点、选区和输入状态；
- 客户端无条件 `attachShadow()`，与 Declarative Shadow DOM 冲突；
- 只验证视觉投影，没有验证读屏顺序和键盘操作。
