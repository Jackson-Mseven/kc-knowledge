# Vue 基础

> 依据 [Vue 3 官方指南](https://cn.vuejs.org/guide/introduction.html) 整理。Vue 是构建用户界面的渐进式 JavaScript 框架：使用声明式模板描述 UI，通过响应式系统自动追踪状态变化并高效更新 DOM。

## 1. Vue 的核心模型

- Vue 建立在标准 HTML、CSS 与 JavaScript 之上，采用组件化与声明式渲染模型。
- Vue 的两项核心能力是**声明式渲染**和**响应式**：模板表达 UI 与状态的关系，状态变化后 Vue 更新受影响的 DOM。
- “渐进式”表示可只在静态页面的局部使用 Vue，也可扩展到 SPA、SSR、SSG、桌面或移动端应用。
- Vue 3 的组件有 Options API 和 Composition API 两种写法；官方文档默认偏向 Composition API。两者能解决相同问题，项目应保持一致的团队约定。

## 2. 单文件组件与模板

在具备构建工具的 Vue 项目中，推荐使用单文件组件（SFC，`.vue`）组织模板、逻辑和样式：

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
const increment = () => count.value++
</script>

<template>
  <button @click="increment">Count: {{ count }}</button>
</template>

<style scoped>
button { font-weight: 700; }
</style>
```

- `<script setup>` 是 Composition API 在 SFC 中的编译期语法糖，顶层变量、函数与导入可以直接在模板中使用。
- 模板支持文本插值 `{{ value }}`、指令和 JavaScript 表达式；表达式应保持简单，复杂逻辑放在 `computed` 或函数中。
- `v-bind`（简写 `:`）绑定属性，`v-on`（简写 `@`）监听事件，`v-if`/`v-else` 条件渲染，`v-for` 渲染列表。
- `v-for` 的同级节点必须使用稳定的 `:key`。优先使用业务 ID，避免用会变化的数组下标或随机值。
- `v-html` 会直接插入 HTML，只能用于可信内容；渲染不可信 HTML 会造成 XSS 风险。

## 3. 响应式状态

### `ref` 与 `reactive`

```ts
import { computed, reactive, ref } from 'vue'

const count = ref(0)
const user = reactive({ name: 'Ada', roles: [] as string[] })
const label = computed(() => `${user.name}: ${count.value}`)
```

- `ref()` 用于包装任意值。JavaScript 中读写通过 `.value`，模板中会自动解包。
- `reactive()` 为对象、数组、Map、Set 等创建深层响应式 Proxy；它返回的代理应保持引用稳定，直接整体替换会丢失原有响应式连接。
- 解构 `reactive` 对象的普通属性会丢失响应式连接；需要解构时使用 `toRefs`/`toRef`，或优先将独立值定义为 `ref`。
- 响应式更新会被批处理并在下一个 DOM 更新周期提交；若必须在更新后的 DOM 上操作，可使用 `await nextTick()`。

### `computed` 与 `watch`

- `computed` 用于从响应式状态派生值，会按依赖缓存；它应保持无副作用。可写计算属性通过 `get`/`set` 处理双向映射。
- `watch` 明确观察一个或多个来源，适合请求、写入本地存储、与第三方系统同步等副作用；回调可通过清理函数取消过期任务。
- `watchEffect` 自动收集同步执行期间读取到的依赖，适合依赖较多且无需精确声明来源的副作用。异步 `await` 之后读取的值不会被本轮自动追踪。
- 能直接由已有状态计算的值不应再存一份响应式 state；优先使用 `computed`，避免状态不一致。

## 4. 事件、表单与生命周期

- 使用 `@click`、`@submit.prevent` 等事件指令绑定方法；修饰符如 `.prevent`、`.stop`、`.once` 用于常见 DOM 事件行为，但复杂逻辑仍应写在函数中。
- `v-model` 是表单值绑定的语法糖，本质上组合了值绑定和更新事件；不同表单控件对应不同属性与事件。
- 组件生命周期中常用 `onMounted`、`onUpdated`、`onUnmounted`、`onBeforeMount` 等组合式 API Hook。订阅、定时器、事件监听和第三方实例应在卸载时清理。
- 不要在 `onUpdated` 中无条件修改响应式状态，否则可能造成更新循环；DOM 读取或与外部系统同步需要有清晰条件。

## 5. 组件通信与复用

| 方式 | 适用场景 | 要点 |
| --- | --- | --- |
| Props | 父向子传递数据和配置 | 单向、只读；子组件不能直接修改 prop |
| `emit` | 子向父通知事件 | 使用 `defineEmits` 声明事件，事件描述发生了什么 |
| 组件 `v-model` | 受控值的双向协作 | 默认对应 `modelValue` 与 `update:modelValue`；可使用具名 model |
| Slots | 父组件向子组件传入 UI 结构 | 默认、具名和作用域插槽支持组合式组件设计 |
| `provide` / `inject` | 跨越深层组件树传值 | 适合主题、服务等依赖；避免把它当作任意全局状态 |
| Composables | 复用有状态逻辑 | 函数通常以 `use` 开头，接收 ref 或普通值并返回状态/方法 |

- Props 应尽量保持单向数据流。子组件要修改父数据时发出事件，由父组件更新状态后再向下传递。
- `defineProps`、`defineEmits` 是 `<script setup>` 的编译宏，可结合 TypeScript 声明组件接口。
- 多个互不相关的状态不必急于提升或全局化；优先放在最接近使用它的组件中。

## 6. 内置能力与工程生态

- `<Transition>` / `<TransitionGroup>` 处理进入、离开和列表动画；动画应避免导致大量布局抖动。
- `<KeepAlive>` 缓存动态组件实例。被缓存组件不会卸载，而会经历 activated/deactivated；需管理缓存数量与数据刷新时机。
- `<Teleport>` 将渲染内容移动到指定 DOM 位置，常用于 Modal、Popover；逻辑归属仍在原组件树中。
- 异步组件使用 `defineAsyncComponent` 按需加载，可配合 `<Suspense>` 处理异步依赖边界。
- 路由使用 Vue Router；全局/跨页面状态优先考虑 Pinia。它们是 Vue 官方生态推荐方案，但局部状态仍应留在组件内。

## 7. 性能与安全要点

- 避免在模板中执行昂贵计算；使用 `computed` 缓存，并用稳定 `key` 保持列表身份。
- 大列表使用虚拟列表；大组件可结合异步组件与路由级代码分割；生产环境检查构建产物、网络瀑布和实际性能指标。
- 默认 Mustache 插值与属性绑定会转义内容；不要将用户输入交给 `v-html`、动态模板或不受控 URL。
- Vue 的响应式和虚拟 DOM 优化不替代业务层的请求缓存、状态建模与权限校验。

## 8. 常见问题

### `ref` 和 `reactive` 如何选择？

独立基本值、可整体替换的对象或需要作为参数传递的状态，通常使用 `ref` 更稳妥；需要以对象形式管理一组关联字段时可用 `reactive`。关键不是“对象一定用 reactive”，而是理解 `ref.value`、代理引用稳定性和解构行为。

### `computed` 和 `watch` 有什么区别？

`computed` 计算并缓存派生值，不应执行副作用；`watch` 在指定状态变化后执行副作用，例如请求、日志、同步外部系统。能直接在模板或逻辑中得到的值优先使用 `computed`。

### 为什么不能直接修改 prop？

Prop 的所有权在父组件。子组件直接修改会破坏单向数据流，也会在父组件重新渲染时被覆盖。应通过 emit 请求父组件更新，或以 prop 创建独立的局部初始 state。

### `v-if` 和 `v-show` 如何选择？

`v-if` 会真实创建和销毁条件块，初始渲染成本低、切换成本高；`v-show` 始终渲染，只切换 CSS `display`，初始成本高、频繁切换更合适。两者都不应用于没有明确条件的性能“优化”。
