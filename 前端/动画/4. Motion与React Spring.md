# Motion 与 React Spring

## Motion

Motion（React 生态中常由 Framer Motion 演进而来）以声明式组件、手势、布局动画和 presence 为核心，适合 React UI 动画。

```tsx
<motion.button whileHover={{ scale: 1.04 }} whileTap={{ scale: .96 }} />
<AnimatePresence>{open && <motion.div initial={{opacity:0}} animate={{opacity:1}} exit={{opacity:0}} />}</AnimatePresence>
```

优点：与 React 状态组合自然、layout/shared layout、拖拽和退出动画易用。缺点：依赖 React 渲染模型；复杂精确时间线不如 GSAP；大量 motion 节点需关注包体和渲染。

## React Spring

React Spring 以弹簧物理和 animated value 为核心，适合拖拽、自然跟随、数值连续变化：

```tsx
const styles = useSpring({ opacity: open ? 1 : 0, y: open ? 0 : 16 })
return <animated.div style={styles} />
```

优点：运动自然、可中断、适合手势和数据驱动。缺点：物理参数心智模型有学习成本；确定时长/精确编排不直观。

## 选择

React 常规 UI、路由和布局过渡优先 Motion；强调物理跟随选 React Spring；复杂全局时间线和滚动叙事选 GSAP。三者可以组合，但应明确属性所有权，避免互相覆盖。
