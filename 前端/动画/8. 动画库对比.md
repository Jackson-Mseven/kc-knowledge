# 前端动画库对比

| 方案 | 核心优势 | 适合场景 | 主要代价 |
| --- | --- | --- | --- |
| CSS/WAAPI | 原生、体积零、简单高效 | 状态过渡、基础关键帧 | 复杂编排有限 |
| GSAP | Timeline、插件、复杂动画 | 品牌站、SVG、滚动叙事 | 学习/包体/授权评估 |
| Motion | React 声明式、布局和手势 | React UI、路由、退出动画 | 框架绑定、精确时间线较弱 |
| React Spring | 弹簧物理、可中断 | 拖拽、自然跟随 | 参数和编排学习成本 |
| Anime.js | 轻量通用补间 | 中等复杂 DOM/SVG | 高级生态较少 |
| AutoAnimate | 零配置布局动画 | 列表、表单、折叠 | 控制能力有限 |
| Lottie | 设计师线性矢量动画 | 品牌、空状态、图标 | 资源/CPU、交互有限 |
| Rive | 状态机与交互动画 | 角色、游戏化 UI | 专用工作流 |
| Three.js | 3D/WebGL 完整引擎 | 3D 产品、沉浸体验 | 资源与性能复杂 |

## 选型顺序

1. CSS/WAAPI 能完成就使用原生；
2. React 常规 UI 选 Motion，物理交互选 React Spring；
3. 复杂时间线、SVG、滚动叙事选 GSAP；
4. 简单列表布局选 AutoAnimate，中等通用补间选 Anime.js；
5. 设计资源播放选 Lottie/Rive；3D 选 Three.js。

## 通用检查

包体和按需加载、SSR/框架生命周期、reduced motion、动画中断、移动端性能、内存清理、授权许可、浏览器兼容和团队设计工作流。不要在同一元素上让多个库同时控制同一属性。
