# JavaScript 框架与性能 SEO

## CSR、SSR、SSG

- CSR：HTML 内容少，依赖 JS/API；搜索引擎可能渲染，但发现延迟和失败面更大；
- SSR：每次请求生成 HTML，适合动态和个性化页面；
- SSG：构建期生成，CDN 性能好，适合内容稳定页面；
- ISR：静态性能和增量更新折中。

按页面选择模式。登录后后台通常无需公开索引，营销、商品和文章页优先确保服务器返回完整核心内容。

## Hydration 注意事项

- 服务端 HTML 与客户端初始渲染一致；
- title、canonical、robots、结构化数据在初始 HTML 中正确；
- 路由返回真实状态码，不把所有未知 URL 都返回 200 SPA Shell；
- 链接使用真实 `<a href>`，不能只有 onclick；
- 懒加载不能让核心内容必须滚动/交互后才出现。

## Core Web Vitals

- LCP：优化 TTFB、主图发现/尺寸/格式和阻塞资源；
- INP：减少长任务、第三方脚本和大范围渲染；
- CLS：图片、广告和嵌入预留尺寸，字体和动态内容稳定。

性能是体验和排名信号之一，优先真实用户数据，不只看 Lighthouse。

## 图片与视频

描述性文件名、alt、响应式图片和周边文本；视频提供标题、描述、缩略图、字幕/文本稿和结构化数据。不要用 robots 或鉴权阻止搜索引擎访问需要展示的媒体。

## 动态渲染

为爬虫单独返回不同内容的动态渲染增加维护和 cloaking 风险，一般优先 SSR/SSG。搜索引擎与用户看到的核心内容必须一致。
