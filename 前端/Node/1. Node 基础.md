# Node 基础

Node.js 是基于 V8 的 JavaScript 运行时，提供事件驱动、非阻塞 I/O 和跨平台系统 API。它适合 I/O 密集型 Web 服务、BFF、CLI、构建工具和实时应用；CPU 密集型任务需要 Worker Threads、子进程或独立计算服务分担。

## 1. 运行时与模块

- Node 在单个 JavaScript 主线程上执行用户代码，但 I/O 可交给操作系统、libuv 线程池或底层网络能力处理，完成后再调度回调。
- CommonJS 使用 `require`/`module.exports`；ESM 使用 `import`/`export`。新项目应根据 `package.json` 的 `type`、文件扩展名和运行环境统一模块策略，避免混用造成解析错误。
- `package.json` 中的 `exports` 定义包的公开入口，优先于历史 `main` 字段；发布库时应同时验证 ESM、CJS 和类型声明入口。
- `process` 提供进程参数、环境变量、退出码和信号处理；不要把未校验的环境变量直接当成可信配置。

```js
// ESM
import { readFile } from 'node:fs/promises'

const text = await readFile(new URL('./config.json', import.meta.url), 'utf8')
```

## 2. 事件循环与异步

Node 的事件循环负责在同步代码、定时器、I/O 回调和关闭回调之间调度工作。理解重点：**同步 CPU 计算会阻塞整个事件循环**，而 Promise 回调和 `process.nextTick` 的执行优先级高于后续事件循环阶段。

- `Promise.then`、`queueMicrotask` 属于微任务；`process.nextTick` 是 Node 特有的高优先级队列，应谨慎递归使用，否则会饿死 I/O。
- `setTimeout` 表示“至少在该延迟后执行”，不是精确计时；`setImmediate` 常用于当前 I/O 轮询后安排任务。
- I/O API 优先使用 Promise 或回调异步版本，避免 `readFileSync`、大 JSON 同步解析等阻塞服务主线程。
- 未处理的 Promise rejection 与未捕获异常都应记录并触发有序退出策略；继续运行在未知状态的进程通常不可靠。

## 3. Buffer、Stream 与文件

- `Buffer` 是 Node 用于二进制数据的字节序列，常见于文件、网络包、加密和编码转换。字符串与 Buffer 转换时必须明确编码。
- Stream 以分块方式处理数据，避免把大文件或大响应一次性读入内存。
- Readable、Writable、Duplex、Transform 是四类基础流；`pipeline()` 能处理背压和错误传播，优先于手写多次 `.pipe()`。

```js
import { createReadStream, createWriteStream } from 'node:fs'
import { pipeline } from 'node:stream/promises'
import { createGzip } from 'node:zlib'

await pipeline(
  createReadStream('app.log'),
  createGzip(),
  createWriteStream('app.log.gz'),
)
```

**背压（backpressure）**指生产速度超过消费者处理能力。忽略 Writable 的返回值或不使用 `pipeline`，会导致内存不断积压。

## 4. HTTP 与 Web 服务

- Node 内置 `http`/`https` 可创建底层服务器；Express、Koa、Fastify 等框架在其上提供路由、中间件和生态。
- 请求处理需要设置超时、请求体大小限制、错误响应、日志和优雅关闭；不能默认所有请求都可信或快速完成。
- HTTP keep-alive 可复用连接降低握手成本，但要协调服务器超时与上游负载均衡超时。
- `fetch` 在现代 Node 中可用，但调用外部服务仍需设置超时、取消信号、重试策略与响应校验。

## 5. 常用内置模块

| 模块 | 用途 |
| --- | --- |
| `node:fs` / `node:fs/promises` | 文件与目录操作 |
| `node:path` | 跨平台路径拼接、解析 |
| `node:url` | URL、文件 URL 处理 |
| `node:events` | 发布订阅 `EventEmitter` |
| `node:crypto` | 哈希、随机数、签名和加密 |
| `node:child_process` | 启动外部命令或子进程 |
| `node:worker_threads` | 多线程执行 CPU 密集任务 |
| `node:util` | 工具函数与 promisify |

路径不要自行拼接字符串，使用 `path.join`/`resolve`；处理用户传入路径时要规范化并验证其仍位于允许目录，防止路径遍历。

## 6. 安全与稳定性

- 输入校验、身份认证、权限校验必须在服务端完成；TypeScript 类型和前端校验不能替代它们。
- 使用参数化查询或 ORM 防止 SQL 注入；避免将用户输入传入 shell 命令、`eval` 或动态 `require`。
- 设置 CORS、Cookie、CSRF、防爆破/限流、请求体限制和安全响应头时，应按实际业务与部署拓扑设计。
- 密钥放在安全的配置系统或环境变量中，不能提交到仓库、写入日志或暴露给客户端。

## 7. 高频问题

### Node 是单线程的吗？

JavaScript 代码通常在一个主线程运行，但 Node 可借助操作系统异步 I/O、libuv 线程池、Worker Threads 和子进程并发完成工作。单线程不意味着所有任务串行完成；同步 CPU 任务仍会阻塞主线程。

### `process.nextTick`、Promise 与 `setTimeout` 如何选择？

普通异步流程优先 Promise/`async`。`process.nextTick` 只用于必须在当前调用栈后、事件循环继续前处理的短任务；定时或让出事件循环使用 `setTimeout`/`setImmediate`。不要递归排入 `nextTick`。

### 为什么大文件要用 Stream？

Stream 分块读取和写入，受背压控制，内存使用更稳定；一次性 `readFile` 会占用与文件大小接近的内存，并可能阻塞后续处理。

## 8. 使用示例：原生 HTTP 服务

```js
import { createServer } from 'node:http'

const server = createServer((req, res) => {
  if (req.method === 'GET' && req.url === '/health') {
    res.writeHead(200, { 'content-type': 'application/json; charset=utf-8' })
    return res.end(JSON.stringify({ ok: true }))
  }

  res.writeHead(404, { 'content-type': 'application/json; charset=utf-8' })
  res.end(JSON.stringify({ code: 'NOT_FOUND' }))
})

server.listen(3000, () => console.log('http://localhost:3000'))
```

这个示例展示了 Node HTTP 的最低层接口。实际 API 服务还需要路由解析、请求体大小限制、输入校验、统一错误处理、认证、日志和超时控制，因此通常会使用 Web 框架。

### 使用 `fetch` 调用下游服务

```js
async function getProfile(id) {
  const signal = AbortSignal.timeout(3_000)
  const response = await fetch(`https://api.example.com/users/${encodeURIComponent(id)}`, { signal })

  if (!response.ok) throw new Error(`Upstream status: ${response.status}`)
  return response.json()
}
```

## 9. 开发注意事项

1. **不要阻塞事件循环**：避免同步文件 API、巨大 `JSON.parse`、复杂正则和长循环出现在请求路径；CPU 密集工作交给 Worker 或队列。
2. **始终设定边界**：外部请求设置超时，请求体设置最大长度，分页设置上限，连接池和并发任务设置容量。
3. **错误不要只 `console.error`**：保留堆栈与请求上下文，返回稳定错误码；未捕获异常后应准备由进程管理器重启。
4. **不要信任运行时类型**：`req.body`、环境变量和外部 API 都是 `unknown`，必须校验后才能进入业务逻辑。
5. **避免资源泄漏**：`finally` 中关闭文件、连接、定时器和订阅；长期服务应持续监控 FD、连接数和堆内存。
