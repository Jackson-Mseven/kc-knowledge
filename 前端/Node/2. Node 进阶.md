# Node 进阶

## 1. 并发、并行与进程模型

- **并发**指交错处理多个任务；Node 通过事件循环擅长 I/O 并发。**并行**指多个 CPU 核同时计算，需要 Worker Threads、子进程或多实例。
- `worker_threads` 适合 CPU 密集任务，可通过 `postMessage` 通信；传输大数据时评估结构化克隆和 `Transferable` 的成本。
- `child_process` 适合隔离外部程序、不同运行时或独立故障域。`spawn` 适合持续流式输出，`exec` 会缓冲输出，不适合大输出。
- 多进程/多容器水平扩展通常比依赖单机 cluster 更易与容器编排、负载均衡和观测体系协作。

## 2. 性能排查

性能优化先测量。关注事件循环延迟、CPU、RSS/heap、GC、请求延迟分位数、外部依赖耗时、数据库连接池与队列长度。

- CPU 高：定位热函数、同步计算、大 JSON 编解码、正则灾难回溯；必要时下放 Worker/任务队列。
- 内存高：区分正常缓存、堆增长和泄漏；用 heap snapshot 与分配采样寻找持续被引用的对象。
- 延迟高：区分应用计算、数据库、网络、锁/队列和下游超时；用 trace ID 串联日志和链路追踪。
- 使用 `node --inspect`、CPU profile、heap snapshot、诊断报告等工具时注意生产安全，调试端口不可暴露公网。

## 3. 可靠性设计

- **超时**是外部调用的默认配置；没有超时就没有有效的失败边界。
- **重试**仅用于可重试错误，使用指数退避和抖动，并结合幂等键避免重复写入。
- **熔断、限流、隔离和降级**用于避免下游故障放大。限流应按用户、IP、接口或租户等业务维度设计。
- 优雅关闭流程：停止接收新流量，等待/限制在途请求，关闭连接池与消费者，超过截止时间后退出。容器编排的终止信号和探针需与之配合。

## 4. 缓存与任务队列

- 缓存要定义 key、TTL、失效策略、一致性边界和穿透/击穿/雪崩处理。缓存不是数据库的透明替代。
- 缓存旁路（Cache Aside）是常见模式：先读缓存，未命中读数据库并回填；更新时更新数据库并删除/更新缓存。
- 异步任务适合邮件、转码、批处理、重试型工作等。消息必须携带唯一标识，并使消费者幂等；处理重复投递、失败重试、死信和可观测性。

## 5. 观测与日志

- 日志采用结构化 JSON，包含时间、级别、请求/追踪 ID、用户或租户上下文（避免敏感信息）和错误堆栈。
- 指标涵盖 RED（Rate、Errors、Duration）或 USE（Utilization、Saturation、Errors）模型；使用 p50/p95/p99，而不是只看平均值。
- 链路追踪让一次请求跨越网关、服务、数据库和消息队列时仍可定位瓶颈。
- 错误处理应保留原因链并返回稳定、无敏感信息的客户端错误格式。

## 6. 数据库与资源池

- 数据库连接池大小不是越大越好。它受数据库最大连接数、实例数量、事务时长和查询效率共同约束。
- 所有事务要短小并确保提交/回滚；连接、文件句柄、stream、定时器和订阅都必须在完成后释放。
- N+1 查询、缺失索引和无界分页常比 Node 框架本身更容易成为性能瓶颈。

## 7. 发布与供应链

- 使用 lockfile 固定可复现依赖；区分生产依赖与开发依赖，定期审计高风险依赖。
- CI 至少包含 lint、类型检查、单元测试、构建和关键集成测试；部署后用健康检查和监控确认真实可用性。
- 配置按环境分离，使用 schema 校验启动配置；密钥轮换、最小权限和镜像扫描应纳入流程。

## 8. 高频问题

### 何时使用 Worker Threads？

当任务主要消耗 CPU 且会阻塞事件循环时，例如图片处理、复杂压缩、密码学计算或大规模解析。纯 I/O 请求通常不需要 Worker；先通过 profiling 确认瓶颈。

### 如何防止重复提交或消息重复消费？

为写操作提供幂等键或业务唯一约束，在服务端持久化处理结果；消费者按消息 ID 去重或保证处理可重复执行。不能只依赖客户端按钮禁用。

### 什么是优雅关闭？

收到终止信号后，实例停止接收新请求，等待有限时间让在途请求、任务和连接池有序完成，再退出。它可减少部署或扩缩容时的请求中断，但必须设置超时上限。

## 9. 使用示例：Worker 与优雅关闭

### 将 CPU 任务移出事件循环

```js
// worker.js
import { parentPort, workerData } from 'node:worker_threads'

const result = expensiveCalculation(workerData)
parentPort.postMessage(result)
```

```js
// main.js
import { Worker } from 'node:worker_threads'

function calculate(input) {
  return new Promise((resolve, reject) => {
    const worker = new Worker(new URL('./worker.js', import.meta.url), { workerData: input })
    worker.once('message', resolve)
    worker.once('error', reject)
    worker.once('exit', (code) => code !== 0 && reject(new Error(`Worker exited: ${code}`)))
  })
}
```

Worker 创建和数据复制也有成本。短小或低频任务不一定更快；应在 profiling 确认主线程被 CPU 占用后再使用，并使用可复用 Worker 池控制并发数。

### 优雅关闭 HTTP 服务

```js
let closing = false

async function shutdown(signal) {
  if (closing) return
  closing = true
  console.info(`received ${signal}, shutting down`)

  server.close() // 停止接受新连接，等待现有请求完成
  const forceExit = setTimeout(() => process.exit(1), 10_000).unref()

  try {
    await database.close()
    await queue.close()
    process.exitCode = 0
  } finally {
    clearTimeout(forceExit)
  }
}

process.on('SIGTERM', () => shutdown('SIGTERM'))
process.on('SIGINT', () => shutdown('SIGINT'))
```

## 10. 生产注意事项

1. **重试必须幂等**：为写操作传递幂等键或使用唯一约束；对 4xx、参数错误和不可恢复错误不要盲目重试。
2. **连接池按实例总量计算**：`单实例池大小 × 实例数` 不能超过数据库可承受连接数，还要为迁移和运维预留容量。
3. **缓存失效优先保证正确性**：先明确数据源、TTL 与更新顺序；缓存删除失败、并发回填和热点 key 都要有应对方案。
4. **日志必须可查询但不泄密**：记录 trace ID、错误码和耗时，脱敏 token、密码、Cookie、身份证件及完整隐私数据。
5. **健康检查不等于服务可用**：存活探针只回答进程是否活着；就绪探针还应反映能否安全接流量，但不要让每个探针都重度查询数据库。
