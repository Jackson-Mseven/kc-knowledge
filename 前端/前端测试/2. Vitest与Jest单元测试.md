# Vitest 与 Jest 单元测试

Vitest 与 Jest 都提供测试运行器、断言、Mock、覆盖率和监听模式。Vite 项目通常优先 Vitest；既有 Jest 工程可继续使用 Jest。选型应考虑构建配置复用、生态、运行环境和迁移成本。

## 1. 基本结构

```ts
import { describe, expect, it } from 'vitest'
import { calculateTotal } from './cart'

describe('calculateTotal', () => {
  it('applies percentage discount after summing items', () => {
    const total = calculateTotal([{ price: 100, quantity: 2 }], 0.1)
    expect(total).toBe(180)
  })
})
```

- `describe` 组织行为域；`it/test` 描述具体情形；
- `beforeEach/afterEach` 管理每个测试的独立环境；
- 避免在 `beforeAll` 创建会被测试修改的共享状态。

## 2. 常用断言

- `toBe`：`Object.is` 语义，适合原始值和相同引用；
- `toEqual`：递归比较结构；
- `toMatchObject`：只匹配对象部分字段；
- `toThrow`/`rejects`：异常和 Promise rejection；
- DOM 断言使用 `@testing-library/jest-dom`，如 `toBeVisible`、`toHaveAccessibleName`。

断言应明确关键业务结果，避免只写 `expect(result).toBeTruthy()`。

## 3. Mock 函数与模块

```ts
const send = vi.fn().mockResolvedValue({ id: '1' })
await submitOrder(send, order)
expect(send).toHaveBeenCalledWith(order)
```

- Spy 观察真实对象方法；Stub 提供预设结果；Fake 是简化但可工作的实现；Mock 常同时表达预期调用。
- 模块 Mock 会增加与实现结构的耦合，优先在网络、时间、随机数、存储等系统边界使用。
- 每个测试清理调用记录和替换实现，区分 `clearAllMocks`、`resetAllMocks`、`restoreAllMocks` 语义。

## 4. 时间与随机数

```ts
vi.useFakeTimers()
const callback = vi.fn()
debounce(callback, 300)()
await vi.advanceTimersByTimeAsync(300)
expect(callback).toHaveBeenCalledOnce()
vi.useRealTimers()
```

固定系统时间和随机源，让测试可重复。Fake Timer 与 Promise/动画调度组合时要显式推进并清理，避免测试永久挂起。

## 5. 参数化与属性测试

```ts
it.each([
  ['', false],
  ['a@b.com', true],
])('validates %j as %j', (input, expected) => {
  expect(isEmail(input)).toBe(expected)
})
```

参数化适合规则表；属性测试通过生成大量输入验证不变量，适合解析、序列化、排序和数学逻辑，但失败时需保留最小反例。

## 6. 环境与注意事项

- `node` 环境适合纯逻辑，`jsdom`/`happy-dom` 模拟 DOM，但不具备完整布局、绘制和浏览器行为；
- 模块路径、CSS、资源和环境变量应与应用构建配置一致；
- 测试隔离依赖清理 DOM、Mock、计时器、存储和全局变量；
- 不要用单元测试证明浏览器兼容、真实布局或下载行为。
