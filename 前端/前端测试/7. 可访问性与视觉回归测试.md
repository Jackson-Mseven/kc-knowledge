# 可访问性与视觉回归测试

可访问性和视觉回归分别验证语义/操作能力与像素呈现。自动化能发现一部分问题，人工键盘与辅助技术检查仍不可替代。

## 1. 可访问性测试层级

- 静态 lint：标签、ARIA 属性和 JSX/Vue 模板规则；
- 组件测试：role、accessible name、label、错误关联和焦点；
- axe 等规则扫描：常见对比度、ARIA 和结构问题；
- E2E：键盘顺序、Modal 焦点陷阱、路由焦点恢复；
- 人工：屏幕阅读器、缩放、语音、认知负担和真实内容。

```ts
const results = await axe(container)
expect(results).toHaveNoViolations()
```

扫描无违规不代表页面完全无障碍，因为工具无法判断文案是否准确、焦点是否符合任务逻辑。

## 2. 关键断言

- 表单控件有可访问名称；
- 错误通过 `aria-describedby` 等与控件关联；
- 键盘可完成全部功能；
- Modal 打开后聚焦内部，关闭后焦点返回触发器；
- 动态通知使用合理 live region，不重复播报；
- 自定义控件具备正确 role、状态和键盘行为。

## 3. 视觉回归

截图测试适合布局、主题、响应式、图表和设计系统组件。稳定措施：

- 固定视口、DPR、字体、浏览器版本、时区和 locale；
- 禁用动画、随机内容和时间变化；
- 使用固定 fixture 和本地资源；
- 等待字体、图片和稳定 UI 状态；
- 对动态区域 mask，不扩大全局像素容差掩盖问题。

## 4. 组件级与页面级

组件 Story/隔离环境覆盖 variants、states、themes 和 breakpoints；页面截图覆盖少量关键路由和真实组合。不要为每个页面每个像素建立难以维护的基线。

## 5. 基线审查

截图差异是评审材料，不是机械失败。更新基线时应确认：变化是否预期、其他断点是否受影响、字体/环境是否漂移、是否出现内容遮挡和 CLS。

## 6. 跨浏览器

文字抗锯齿会产生像素差异。关键布局可跨 Chromium/WebKit/Firefox 跑语义和尺寸断言，像素基线按浏览器分别维护或只在标准环境执行。
