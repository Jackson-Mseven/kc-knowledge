# 性能与安全测试

性能与安全不能靠功能测试间接保证，需要独立预算、扫描和攻击面验证。

## 1. 性能测试

- Lighthouse CI：LCP、CLS、TBT、资源和审计预算；
- Bundle Budget：入口/chunk gzip 体积、重复依赖；
- E2E Timing：关键业务动作耗时，但 CI 环境噪声较大；
- RUM：发布后观察真实用户 p75/p95；
- API Load Test：并发、吞吐、p95/p99、错误率和资源饱和。

性能测试使用固定环境、多次运行和统计分布。CI 适合发现明显回退，真实用户数据用于最终判断。

## 2. Web Vitals 回归

固定页面数据和网络/CPU 条件，记录 LCP 元素、Long Task 和请求瀑布。不要只设总分阈值；对核心指标和资源预算分别设置门禁。

## 3. 静态安全检查

- 依赖漏洞与 lockfile 审计；
- Secret 扫描；
- ESLint 安全规则、危险 DOM API 检查；
- CSP、Cookie、CORS 和响应头配置测试；
- SAST 结果需要人工确认上下文，避免只追求零告警。

## 4. 动态安全测试

- XSS：不同输出上下文、富文本、URL 和 DOM sink；
- CSRF：无 Token、错误 Origin、SameSite 行为；
- 权限：不同角色、直接对象引用和越权 API；
- 上传：类型伪装、大小、文件名和恶意内容；
- 重定向、CORS 白名单、点击劫持和缓存泄露；
- 自动扫描不能替代威胁建模和渗透测试。

## 5. 测试环境安全

测试账号和数据不得复用生产凭证；sandbox 第三方能力；CI 日志脱敏；测试报告、trace、视频可能包含 Token 和个人信息，必须限制访问和保留时间。

## 6. 混沌与降级

通过 Mock/测试环境注入超时、断网、500、慢响应、缓存失效和第三方失败，验证加载、重试、取消、错误提示和核心功能降级。重试必须有限且幂等。
