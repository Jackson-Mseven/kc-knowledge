# 前端测试面试题

## 1. 单元、集成和 E2E 如何划分？

单元验证小逻辑并隔离外部边界；集成验证多个模块真实协作；E2E 在浏览器验证完整用户链。按风险选择最低成本且能提供足够信心的层级，关键流程通常需要多层互补。

## 2. 什么是测试金字塔？

底层快速测试多、上层慢测试少。现代前端常采用测试奖杯，增加组件/集成测试比重，因为只测纯函数无法覆盖 UI 协作。它们都是成本模型，不是固定比例。

## 3. 为什么不推荐测试实现细节？

内部 state、私有方法和 DOM 层级改变时，用户行为可能未变。此类测试会阻碍重构并产生噪声。应通过可访问语义、交互、输出、网络和公开契约验证行为。

## 4. Mock 越多测试越独立吗？

隔离更强但真实性更低。过度 Mock 会复制实现并漏掉集成问题。只在不可预测或昂贵边界 Mock，核心模块尽可能真实协作，并用契约测试约束替身。

## 5. `getBy`、`queryBy`、`findBy` 区别？

getBy 立即查找，找不到抛错；queryBy 找不到返回 null，适合断言不存在；findBy 异步等待元素出现。查询优先 role、label 等用户语义。

## 6. 如何测试异步 UI？

触发用户动作，等待 loading、内容、错误或按钮状态等可观察结果。使用 findBy/waitFor 和网络 Mock，不用固定 sleep；覆盖竞态、取消、失败和组件卸载清理。

## 7. Snapshot 测试有什么问题？

大型 Snapshot 可读性低、变化频繁，团队容易无脑更新。适合小而稳定的序列化结构；关键 UI 使用语义断言或视觉回归。

## 8. 如何处理 E2E flaky？

消除固定等待、共享数据、外网依赖和不稳定选择器；使用自动等待和可观察状态；固定时间/随机数据；保留 trace。重试只能识别和暂时隔离问题，必须修复根因。

## 9. 覆盖率越高越好吗？

覆盖率只表示执行过，不能保证断言有效。核心分支需要较高覆盖，但追求 100% 会产生低价值测试。结合风险、diff coverage、代码评审和 mutation testing 判断质量。

## 10. 组件测试和 E2E 的 DOM 环境有何区别？

jsdom 模拟 DOM API，但没有完整布局、绘制、导航和浏览器安全模型；E2E 使用真实浏览器，可验证焦点、尺寸、下载和跨页面流程，但更慢。布局和浏览器兼容问题不能只靠 jsdom。

## 11. 如何测试 API 契约？

通过 OpenAPI/JSON Schema、运行时解析或 consumer-driven contract，让前端期望由后端 CI 验证。TypeScript 类型被擦除，不能证明真实响应符合类型。

## 12. 可访问性自动化能覆盖全部问题吗？

不能。axe/lint 可发现缺少 label、错误 ARIA、部分对比度等；无法完全判断交互顺序、文案质量和屏幕阅读器体验。还需键盘和辅助技术人工测试。

## 13. 如何在 CI 中组织测试？

静态检查和快速单测先行，构建/集成随后，临时环境执行 E2E、视觉和性能预算。并行、分片和缓存缩短反馈，失败保留 trace，并以风险设置门禁。

## 14. Vitest 和 Jest 如何选择？

Vite 项目通常选择 Vitest以复用解析和配置、获得快速开发反馈；成熟 Jest 工程可保留其生态和稳定配置。选型看项目构建、插件、环境与迁移成本，不只看 benchmark。

## 15. 如何测试时间、随机数和网络？

使用 fake timer/固定系统时间、可注入随机源和 MSW 网络边界；每个测试后恢复。最终仍用少量 E2E 连接真实测试服务验证整条链路。
