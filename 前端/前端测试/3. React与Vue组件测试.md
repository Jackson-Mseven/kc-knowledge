# React 与 Vue 组件测试

组件测试应从用户视角查询元素并触发交互。优先 Accessible Role、Label、文本，再使用 test id；CSS 类名和 DOM 层级不是稳定契约。

## 1. React Testing Library

```tsx
render(<LoginForm onSubmit={onSubmit} />)
await user.type(screen.getByLabelText('邮箱'), 'a@example.com')
await user.type(screen.getByLabelText('密码'), 'secret')
await user.click(screen.getByRole('button', { name: '登录' }))

await waitFor(() => expect(onSubmit).toHaveBeenCalledWith({
  email: 'a@example.com', password: 'secret',
}))
```

- 使用 `userEvent` 模拟更接近用户的输入序列；
- `getBy*` 适合立即存在，`queryBy*` 断言不存在，`findBy*` 等待异步出现；
- 不直接调用组件实例方法或读取 Hook 内部 state；
- Provider、Router、Query Client 用自定义 `render` wrapper 统一创建，并为每个测试使用新实例。

## 2. Vue Test Utils + Testing Library

```ts
const wrapper = mount(Counter)
await wrapper.get('button').trigger('click')
expect(wrapper.text()).toContain('1')
```

- Vue DOM 更新是异步批处理，交互后 `await trigger/setValue` 或 `nextTick`；
- 异步 Promise 使用 `flushPromises`，不要靠固定 sleep；
- Props 输入、emit 输出和 DOM 行为是稳定契约；避免读取组件私有 data；
- `shallowMount` 会隐藏真实子组件协作问题，只有隔离重型依赖时谨慎使用。

## 3. 异步数据组件

使用 MSW 在网络层 Mock，而不是 Mock 组件内部请求函数：

```ts
server.use(http.get('/api/users', () => HttpResponse.json([{ id: 1, name: 'Ada' }])))
render(<UserList />)
expect(await screen.findByText('Ada')).toBeVisible()
```

至少覆盖 loading、成功、空数据、错误、重试、过期响应和取消。测试不应依赖外网。

## 4. 表单

- 使用 label 查询控件，覆盖键盘操作和错误可访问关联；
- 测试必填、格式、服务端错误、重复提交、提交中禁用与成功状态；
- 不必遍历第三方校验库全部规则，重点覆盖业务组合和集成；
- 文件上传可构造 File，但真实文件选择器和下载流程由 E2E 覆盖。

## 5. Snapshot

Snapshot 适合稳定序列化结果、小型 SVG 或协议结构。大型组件 Snapshot 变化噪声大，容易被无脑更新。关键 UI 用语义断言和视觉回归更可靠。

## 6. 常见错误

- 使用 `container.querySelector('.btn-primary')` 测样式实现；
- 到处加 `data-testid` 而忽略语义和可访问性；
- 固定等待 1 秒；
- Mock 所有子组件，使测试只验证空壳；
- 一个测试覆盖整个应用所有路径，失败难定位。
