# 生命周期、路由与加载

## 子应用契约

```ts
export async function bootstrap(props) {}
export async function mount(props) {}
export async function unmount(props) {}
```

- bootstrap：一次性初始化，不绑定页面 DOM；
- mount：创建实例、订阅事件并渲染；
- unmount：卸载组件、监听器、定时器、Observer、请求与全局副作用；
- 可选 update：基座属性变化时更新。

Unmount 不彻底会导致重复监听、内存泄漏和返回页面后行为叠加，应有自动化重复挂载测试。

## 路由所有权

- 基座负责顶层业务域路由；
- 子应用负责域内路由；
- 定义 URL base、404、登录回跳和 query/hash 所有权；
- BrowserRouter basename、资源 publicPath 和部署路径保持一致；
- 防止基座和子应用同时拦截同一次 history 变化。

## 加载流程

1. 匹配激活规则；
2. 获取 manifest/entry/remote；
3. 加载 JS/CSS 与共享依赖；
4. 执行 bootstrap/mount；
5. 展示内容并记录性能；
6. 切换时 unmount 或按策略缓存。

## Loading 与错误边界

基座提供统一 skeleton、超时、重试和错误页。子应用加载失败不应让全站白屏；保留导航和退出路径。错误应包含 appName、版本、route、trace ID，方便归因。

## 预加载

可在登录后、空闲时或用户 hover 时预加载高概率子应用。预加载必须受网络、设备、数据节省模式和资源预算限制，不能一次下载全部应用。

## 本地开发

支持基座连接本地子应用、其他应用连接测试环境；通过 manifest/env override 切换 URL。避免要求开发者同时启动全部仓库。契约 Mock 和独立 Story/Preview 降低联调成本。
