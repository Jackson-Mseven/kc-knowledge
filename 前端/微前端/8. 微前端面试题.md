# 微前端面试题

## 1. 什么是微前端？

按业务域把大型前端拆为可独立开发、测试、部署的应用，并在运行时或导航层组合。核心价值是组织与交付自治，代价是集成和治理复杂度。

## 2. 微前端与组件化、Monorepo 区别？

组件化是代码复用，Monorepo 是源码组织，微前端强调应用边界和独立部署。三者可组合，但互不等价。

## 3. iframe 的优缺点？

隔离最强、适合第三方和遗留系统；但路由、通信、尺寸、主题、SEO、弹层和用户体验复杂。postMessage 必须校验来源。

## 4. qiankun/single-spa 的核心原理？

根据路由激活子应用，调用 bootstrap/mount/unmount 生命周期；qiankun 增加 HTML Entry、沙箱、样式等能力。正确卸载和资源路径是关键。

## 5. Module Federation 如何工作？

Host 运行时加载 Remote 容器暴露模块，并通过共享作用域协商依赖。它支持独立部署，但引入远程可用性、公共 API 和版本兼容问题。

## 6. 如何解决样式隔离？

CSS Modules/命名空间、Shadow DOM、运行时 scoped 等。基座管理 reset 和层级协议；没有一种方案同时完美兼容主题、Portal 和第三方样式。

## 7. 如何通信？

稳定 props、事件协议、URL、postMessage 或后端事实。避免共享一个巨大 store；事件 schema 和版本要治理并清理订阅。

## 8. 如何避免重复依赖？

构建 external/shared、Module Federation singleton 或平台依赖。但共享会增加版本耦合；只有体积大且语义要求单例的稳定依赖值得共享。

## 9. 子应用如何独立部署又保证兼容？

公共契约版本化、向后兼容窗口、契约测试、动态 manifest、灰度和可回滚旧版本；记录真实 shell/remote 版本矩阵。

## 10. 如何处理加载失败？

设置超时、有限重试、局部 fallback、错误边界和旧版本回退；保留全局导航，并记录应用名、版本和资源 URL。

## 11. 微前端一定适合大型项目吗？

不一定。若团队发布节奏一致、技术栈统一且模块化已足够，微前端会增加无收益复杂度。只有组织自治和渐进迁移等收益超过成本才采用。

## 12. 如何迁移遗留系统？

先按路由做粗粒度切分，建立基座和统一认证；选择一个低风险领域试点；定义生命周期/通信/监控；逐步迁移，不同时重写所有系统；每一步保持可回滚。
