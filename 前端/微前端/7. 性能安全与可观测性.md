# 性能、安全与可观测性

## 性能

- 基座控制首屏预算，子应用声明 JS/CSS/字体和第三方预算；
- 避免重复 React、组件库、polyfill 和 locale；共享依赖要权衡缓存与版本耦合；
- 按路由加载，预测性预取高概率应用；
- 记录应用发现、entry 下载、mount 和可交互耗时；
- 子应用卸载后检查监听器、DOM、Worker 和内存是否释放。

## 安全

运行时加载 Remote 等同于执行对方代码，不能视为安全沙箱。可信发布、HTTPS、CSP、SRI/签名、允许域名单和依赖供应链都要治理。

- iframe 用 sandbox 和 Permissions-Policy；
- postMessage 校验 origin/source/schema；
- 子应用最小化 Token 和用户数据权限；
- 基座不可把高权限服务对象无条件传给 Remote；
- CSP 动态脚本策略与 nonce 要兼容加载机制，不能简单放开 `script-src *`。

## 可观测性

统一日志字段：appName、appVersion、shellVersion、route、traceId、release、userSession（脱敏）。错误监控上传各自 Source Map，并按 Remote 版本还原。

指标：加载成功率、mount p75/p95、chunk 失败、运行错误、内存、Web Vitals、跨应用事件失败和 API 延迟。

## 故障隔离

- Error Boundary/全局错误钩子只能捕获部分错误，Promise 和资源加载要单独处理；
- 子应用故障展示局部 fallback，保留全局导航；
- Remote 超时后允许重试、切换旧版本或关闭 feature flag；
- 子应用不能修改全局错误处理器后不恢复。

## 测试

重点测试重复 mount/unmount、路由快速切换、Remote 404/超时、共享依赖冲突、鉴权过期、跨应用事件版本不兼容和灰度回滚。
