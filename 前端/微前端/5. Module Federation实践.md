# Module Federation 实践

Module Federation 允许运行时从 Remote 加载模块。Host 与 Remote 独立构建部署，通过远程入口和共享作用域协商依赖。

## 基本概念

- `name`：容器名称；
- `remotes`：Host 可加载的远程容器；
- `exposes`：Remote 对外模块；
- `shared`：共享依赖及版本要求；
- Remote Entry/Manifest：远程模块定位与元数据。

```js
new ModuleFederationPlugin({
  name: 'catalog',
  filename: 'remoteEntry.js',
  exposes: { './ProductCard': './src/ProductCard' },
  shared: { react: { singleton: true, requiredVersion: '^19.0.0' } },
})
```

## 共享依赖

React/Vue 等运行时通常要求 singleton，避免多实例导致 Hook/Context 或响应式异常。但强行共享不兼容版本可能让 Remote 运行失败。明确 requiredVersion、fallback 和兼容测试。

## 公共 API

Remote 暴露模块就是公共 API：

- 只暴露稳定入口，不暴露内部目录；
- Props/事件/类型和样式契约版本化；
- Breaking Change 保留兼容版本或协调发布；
- TypeScript 类型可通过发布类型包、生成声明或契约流程同步，但运行时仍需验证兼容。

## 动态 Remote

通过运行时 manifest 将 app/version 映射到 URL，支持环境、灰度和回滚。Manifest 需要签名/可信来源、缓存策略、超时和 fallback。不要让任意 URL 注入脚本。

## 故障处理

- Remote Entry 加载失败：超时、重试、fallback UI；
- chunk 404：保留旧版本资源、原子发布；
- 共享版本不兼容：发布前契约测试；
- Remote 运行错误：Error Boundary 隔离；
- 监控记录 host/remote 版本组合。

## 适用边界

适合真正需要运行时独立发布的模块。设计系统等稳定库若能同步升级，npm package/Monorepo 更简单。不要把每个按钮都变成 Remote。
