# JavaScript 运行时与事件循环

浏览器中的 JavaScript 通常在渲染进程主线程执行。事件循环协调脚本、用户输入、网络回调、定时器、微任务和渲染机会，让单线程能够处理异步工作。

## 1. 执行栈与执行上下文

- 调用函数时创建执行上下文并压入调用栈，函数返回后弹出。
- 执行上下文包含词法环境、变量环境、`this` 等信息；闭包使函数能继续访问创建时的词法环境。
- 递归过深会造成调用栈溢出；长时间不返回的同步函数会阻塞事件循环。
- JavaScript 的“单线程”主要指同一 Realm/主线程上的代码不能同时执行两个调用栈；Worker 可在其他线程独立运行。

## 2. Event Loop 基本模型

1. 从某个任务队列取出一个 task 执行，例如脚本、点击、定时器或消息事件。
2. 调用栈清空后执行 microtask checkpoint，持续清空微任务队列。
3. 浏览器在合适时机执行渲染步骤，如样式、布局、`requestAnimationFrame`、绘制。
4. 进入下一轮任务。

不同类型的任务来自不同 task source，浏览器可按规范与调度策略选择。不能简单理解为所有宏任务都存在一个严格 FIFO 总队列。

## 3. 宏任务与微任务

常见 task（俗称宏任务）：初始脚本、`setTimeout`、`setInterval`、用户交互、MessageChannel、部分网络事件。

常见微任务：Promise reaction、`queueMicrotask`、MutationObserver。

```js
console.log('A')
setTimeout(() => console.log('B'), 0)
Promise.resolve().then(() => console.log('C'))
queueMicrotask(() => console.log('D'))
console.log('E')
// A E C D B
```

微任务会在当前 task 结束后、下一 task 前清空。微任务中继续添加微任务，会在本轮继续执行，可能造成微任务饥饿并推迟渲染和输入响应。

## 4. Promise 与 async/await

- Promise 构造器的 executor 同步执行，`.then/.catch/.finally` 回调以微任务运行。
- `await expression` 会暂停当前 async 函数，其后续逻辑通过 Promise reaction 恢复。
- `try/catch` 能捕获 `await` 的 rejection；没有 `await` 或 return 的异步 Promise 不会被同步 `try/catch` 捕获。
- 使用 `Promise.all` 并发执行相互独立任务；串行 `await` 会增加总耗时，但对存在依赖或需要限流的任务是正确选择。

```js
const [user, permissions] = await Promise.all([
  fetchUser(),
  fetchPermissions(),
])
```

并发不等于无界并行。对大量请求、文件和图片处理应使用并发池，避免耗尽连接、内存或下游容量。

## 5. 定时器

- `setTimeout(fn, 0)` 只表示达到最小延迟后进入可调度状态，不保证立即运行。
- 嵌套定时器、后台标签页和节能策略会触发延迟钳制。
- `setInterval` 不会等待异步回调完成，慢任务可能重叠。轮询通常用递归 `setTimeout`，在上一次完成后再安排下一次。
- 精确计时使用 `performance.now()`；业务时间使用 `Date`，并处理时区与系统时间变化。

## 6. requestAnimationFrame 与 requestIdleCallback

- `requestAnimationFrame` 在下一次绘制前调用，适合视觉更新。回调中的时间戳来自高精度时间轴。
- `requestIdleCallback` 仅在浏览器有空闲预算时运行，支持度和触发时机有限，不能用于关键任务。
- 可把长计算拆为小块，通过 Scheduler API、MessageChannel、定时器或 Worker 让出主线程；选择要结合兼容性。

## 7. Web Worker

Web Worker 在独立线程运行 JavaScript，不能直接访问 DOM。主线程与 Worker 使用 `postMessage` 通信：

```js
// main.js
const worker = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' })
worker.postMessage({ values: largeArray })
worker.onmessage = ({ data }) => render(data)
```

- 消息通常经过结构化克隆；ArrayBuffer 可作为 Transferable 转移所有权，减少复制。
- Worker 适合计算、解析、图像处理等 CPU 工作，不适合把所有业务状态随意搬过去。
- Worker 也需要下载、启动、通信和内存，短任务未必获益。

## 8. 内存与垃圾回收

- 可达对象不会被回收。全局变量、闭包、DOM 引用、监听器、定时器和缓存都可能让无用对象保持可达。
- 现代引擎通常使用分代、标记清除、增量/并发等 GC 策略，具体算法会变化。
- 大量短命对象会增加分配和 GC 压力，但不要在没有 profile 的情况下过早进行对象复用优化。
- Detached DOM Tree 常表示 DOM 已移除但仍被 JavaScript 引用；用 Heap Snapshot 查看引用链。

## 9. Long Task 与响应性

主线程连续执行超过约 50 ms 的任务通常会被记录为 Long Task。它会推迟用户输入和渲染，是 INP 变差的常见原因。

改善方法：减少工作、拆分任务、按需加载、避免大范围同步状态更新、使用 Worker、缓存计算结果，并把非关键工作延后。

## 10. 常见误区

- Promise 不是多线程，它只提供异步结果和微任务调度。
- `async` 函数不会自动避免阻塞；其中的同步循环仍运行在主线程。
- `setTimeout(..., 0)` 不能保证在 Promise 前执行。
- 微任务优先级高不意味着应把所有任务都放进微任务。
