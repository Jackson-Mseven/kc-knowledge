# 浏览器面试常考题

## 1. 输入 URL 后发生了什么？

浏览器解析并规范化 URL，检查缓存、HSTS、Service Worker 和代理；通过 DNS 得到 IP，建立 TCP/TLS 或 QUIC 连接，发送 HTTP 请求；收到 HTML 后创建/复用渲染进程，解析 DOM/CSSOM，执行脚本，完成样式、布局、绘制和合成，并继续加载子资源。缓存、连接复用、预加载和 bfcache 会改变实际链路。

## 2. 浏览器为什么采用多进程？

隔离页面崩溃、提高安全性并让不同站点互相限制；代价是内存占用和 IPC 成本增加。实际不一定一个标签页一个进程，进程复用与 Site Isolation 会影响划分。

## 3. 从 HTML 到像素经历哪些阶段？

字节解码、HTML 解析生成 DOM；CSS 解析生成 CSSOM；结合二者计算样式并构建渲染树；布局计算几何位置；绘制指令；图层光栅化；合成线程组合图层到屏幕。JavaScript、资源加载和动画可能在阶段间触发重新计算。

## 4. `defer` 和 `async` 区别？

二者都并行下载。`defer` 在 HTML 解析完成后执行，并保持脚本顺序，通常在 `DOMContentLoaded` 前；`async` 下载完成就执行，可能打断解析且不保证顺序，适合相互独立脚本。Module 脚本默认具有 defer 类似行为。

## 5. `DOMContentLoaded` 与 `load` 区别？

`DOMContentLoaded` 表示 DOM 解析完成且 defer/module 脚本处理完，不等待普通图片等资源；`load` 通常等待页面及依赖资源完成。两者都不等于页面已经完全可交互或性能良好。

## 6. 重排、重绘、合成有什么区别？

重排重新计算几何，影响通常最大；重绘重新生成视觉绘制；合成把已有图层组合。改变宽高通常可能三者都触发，背景色通常 paint，独立层上的 transform/opacity 常只需 composite。具体失效范围由浏览器决定。

## 7. 什么是强制同步布局？

浏览器本可批量延迟样式和布局，但脚本在刚写样式后读取 `offsetWidth`、`getBoundingClientRect` 等几何属性，可能迫使浏览器立刻完成布局。循环交错读写会形成 layout thrashing；应批量读取再批量写入。

## 8. 为什么 JavaScript 会阻塞页面？

页面主线程通常同时执行 JavaScript、样式、布局和部分绘制。长循环、巨大 JSON、复杂正则和同步 API 会占用调用栈，使输入、渲染和其他回调排队。拆分任务、使用 Worker、延迟非关键工作可以改善。

## 9. Promise、微任务和宏任务执行顺序？

当前任务的同步代码先完成；随后清空微任务（Promise reaction、queueMicrotask）；浏览器在合适时机渲染；再处理下一个任务（定时器、交互、消息等）。微任务递归过多会推迟渲染，不能滥用其高优先级。

## 10. `requestAnimationFrame` 为什么适合动画？

它在浏览器计划下一次绘制前运行，并提供与帧时钟关联的时间戳。回调适合计算下一帧视觉状态；应避免在其中强制布局或执行过长计算。后台页面会降低调用频率。

## 11. Web Worker 和 Service Worker 有什么区别？

Web Worker 主要用于后台计算，生命周期通常由页面控制，不能拦截页面网络请求；Service Worker 由浏览器管理，可拦截受控页面的请求，支持离线、缓存、推送和后台同步，也不能直接访问 DOM。

## 12. 什么是同源策略？

同源要求 scheme、host、port 都相同。它限制脚本读取其他源的 DOM、存储和响应，降低跨站数据泄露风险。跨源资源加载并非全部禁止，但读取和凭证行为需要 CORS、`postMessage` 等明确机制。

## 13. CORS 预检何时发生？

跨源请求使用非简单方法/请求头或非简单 Content-Type 时，浏览器先发 OPTIONS 预检。服务端通过允许 Origin、Methods、Headers 和凭证等响应头授权后才发送实际请求。预检缓存可由 `Access-Control-Max-Age` 控制，但存在浏览器上限。

## 14. XSS 和 CSRF 有什么区别？

XSS 是恶意脚本在目标站点上下文执行，重点防御输出编码、危险 DOM API 和 CSP；CSRF 是借助浏览器自动携带身份凭证诱导状态变更，重点防御 SameSite、CSRF Token 和 Origin 校验。XSS 成功后可能绕过部分 CSRF 防护，因此二者都要处理。

## 15. Cookie、localStorage、sessionStorage、IndexedDB 怎么选？

Cookie 会随匹配请求发送，适合受服务端控制的会话但有网络开销；localStorage/sessionStorage 是同步字符串键值，适合少量非敏感数据；IndexedDB 异步、结构化，适合较大离线数据。高价值凭证不应默认放在可被 XSS 读取的 Web Storage 中。

## 16. 强缓存和协商缓存区别？

强缓存新鲜时直接使用本地响应，不发网络请求；协商缓存需要携带 ETag/Last-Modified 请求服务端，未变化返回 304。`no-cache` 意味着使用前重新验证，不是禁止存储；`no-store` 才是不应存储。

## 17. 为什么图片会造成 CLS？

浏览器在不知道图片尺寸时先按暂时尺寸布局，图片加载后尺寸变化导致内容移动。给图片设置 width/height 或 aspect-ratio、使用固定占位和正确响应式资源可减少偏移。

## 18. 什么是 bfcache？

bfcache 把完整页面状态冻结保存，前进后退时快速恢复，不必重新执行完整导航。页面恢复可能触发 `pageshow`，不能假设初始化只运行一次；连接、数据新鲜度和计时器需要在恢复时重新处理。

## 19. 如何定位页面加载慢？

先用 Network 分解 DNS、连接、TLS、TTFB、下载与解析；再检查重定向、关键资源、缓存、压缩、图片、字体和阻塞脚本；用 Performance 观察主线程长任务、样式、布局和绘制；最后用真实用户指标验证改动收益。

## 20. 如何定位页面内存泄漏？

重复执行同一操作并拍 Heap Snapshot，对比对象数量和保留大小；检查事件监听器、定时器、闭包、全局缓存、订阅、WebSocket 和 Detached DOM 的引用链。确认是持续增长且不可回收后，再修改释放逻辑。

## 21. 为什么不能把所有动画都交给 GPU？

GPU 合成适合特定图层和属性，但创建过多图层会增加显存、纹理上传和合成成本；滤镜、阴影和大面积透明也可能昂贵。应通过 Performance/Layers 验证，而不是给所有元素加 `translateZ(0)` 或 `will-change`。

## 22. 为什么 `setTimeout(fn, 0)` 不会立即执行？

它只是把回调放入定时器任务源，并设置最小延迟。当前同步代码、微任务、已有任务和浏览器调度都会先执行；后台页面还可能受到额外钳制。

## 23. Service Worker 更新为什么容易出问题？

新 Worker 安装后可能处于 waiting，旧页面仍由旧 Worker 控制；缓存又可能被不同版本共享。要设计版本化 cache、原子更新、失败回退和用户刷新提示，谨慎使用 `skipWaiting`/`clientsClaim`。

## 24. 现代前端性能最应该关注什么？

关注真实用户的 LCP、INP、CLS、TTFB、错误率和设备/网络分布。加载快但交互卡顿、页面持续位移或移动端内存溢出都不是良好体验；性能优化应有基线、预算、监控和回归测试。
