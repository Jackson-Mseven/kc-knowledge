# 浏览器性能优化与调试

性能优化应围绕真实用户体验，而不是单一 Lighthouse 分数。先采集、定位和验证，再决定代码、资源或架构改动。

## 1. 核心指标

- **LCP**：最大内容绘制，反映主要内容出现时间。常见瓶颈是 TTFB、关键资源、渲染阻塞和主线程任务。
- **INP**：交互到下一次绘制的延迟，关注点击、键盘和触摸交互中最慢的一批响应。
- **CLS**：累计布局偏移，反映页面内容意外移动。
- **TTFB**：从请求到首字节，受 DNS、连接、服务端、CDN 和缓存影响。
- FCP、TBT、Long Task、资源大小、错误率和 JS 覆盖率可作为诊断指标，但不要与核心体验指标混为一谈。

## 2. 性能预算

为首屏 JS、CSS、字体、图片、总请求数、LCP/INP/CLS 设定预算，放入 CI 或发布监控。预算应按设备、网络、页面类型设定，而不是只看开发机。

## 3. 网络与资源优化

- 使用 CDN、HTTP/2/3、压缩、缓存和连接复用；减少关键路径上的重定向和串行请求。
- JS 按路由/功能拆分，动态 import 非关键模块；避免拆得过碎导致请求和执行开销增加。
- 图片使用正确尺寸、`srcset`、现代格式、压缩和懒加载；首屏最大图片不应盲目 `loading="lazy"`。
- 关键字体设置子集和合理 `font-display`；仅对确实关键且可证明收益的资源使用 preload。
- 预加载 CSS、模块和图片时设置正确的 `as`、类型和跨源属性，定期检查是否抢占带宽。

## 4. JavaScript 与主线程

- 按需加载、删除无用依赖、Tree Shaking、压缩和减少重复 polyfill。
- 将超过 50 ms 的长任务拆分；在循环中让出主线程，或把 CPU 计算迁移到 Worker。
- 避免频繁创建对象、巨大 JSON 解析、同步布局读取和大范围状态更新。
- 使用事件委托时要注意动态节点、`stopPropagation` 和 Shadow DOM 边界；不要为了少几个监听器牺牲可读性。
- 使用 passive wheel/touch listener 允许浏览器更快处理滚动，但需要确保回调不依赖 `preventDefault()`。

## 5. 渲染与布局

- 给图片、广告、嵌入内容预留尺寸；使用 `aspect-ratio` 和占位骨架降低 CLS。
- 批量读布局后批量写样式，避免 read-after-write 触发强制同步布局。
- 动画优先使用 `transform`、`opacity`，但检查图层大小、显存和合成成本。
- 缩小 DOM 和样式失效范围，谨慎使用昂贵滤镜、阴影和大面积透明叠加。
- 虚拟列表适合大量重复行，但要处理键盘可访问性、滚动高度、动态行高和搜索定位。

## 6. 缓存与离线性能

- 内容哈希静态资源使用长期缓存，HTML 采用短缓存/协商缓存。
- Service Worker 应有版本化缓存、失效、失败回退和更新提示；不要让旧缓存永久覆盖线上错误修复。
- 使用内存缓存时设置上限和淘汰策略，避免将浏览器存储或内存当作无限资源。

## 7. DevTools 调试流程

### Network

查看请求瀑布、Initiator、Priority、Timing、Size、Cache、Protocol、Response Headers。重点确认：是否重复请求、是否串行、是否命中缓存、TTFB 是否异常、压缩是否生效。

### Performance

录制真实操作，定位 Long Task、Recalculate Style、Layout、Paint、Composite、Event Handler 和网络等待。点击一段任务查看调用栈与耗时，不要凭火焰图颜色猜原因。

### Memory

- Heap Snapshot：比较快照，寻找增长对象和引用链；
- Allocation instrumentation：观察一段操作期间的对象分配；
- Detached DOM：查找移除后仍被 JS 引用的节点；
- 强制 GC 只用于诊断，不代表真实用户环境。

### Application

查看 Cookie、Storage、IndexedDB、Cache Storage、Service Worker、Manifest 和清除数据行为。

## 8. 线上观测

- RUM 采集真实设备、网络、地区、页面、交互和核心指标分布；避免只看平均值，重点关注 p75/p95。
- 性能数据要与版本、实验组、资源、错误和用户路径关联。
- 采集用户输入、URL 和设备信息时进行隐私评估和脱敏；性能监控本身不能成为数据泄露来源。

## 9. 优化注意事项

1. 不要把所有资源都 preload、所有元素都 `will-change`、所有组件都 memo 化。
2. 不要用本地高速网络与高端设备替代真实用户测试。
3. 不要只优化首次加载而忽略交互、滚动、路由切换和长时间使用后的内存。
4. 每次优化应有基线、可复现脚本、指标对比和回滚方案。
