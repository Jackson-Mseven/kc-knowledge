# 浏览器存储与离线能力

浏览器存储 API 解决的不是同一个问题：Cookie 主要参与 HTTP 请求，Web Storage 适合少量同步键值，IndexedDB 适合异步结构化数据，Cache API 适合请求/响应缓存，Service Worker 负责拦截和后台能力。

## 1. Cookie

Cookie 由服务端 `Set-Cookie` 或受限的 JavaScript 写入，浏览器按 Domain、Path、过期时间和 SameSite 规则在请求中携带。

| 属性 | 作用 |
| --- | --- |
| `HttpOnly` | 禁止页面 JavaScript 读取，降低 XSS 直接窃取风险 |
| `Secure` | 仅通过 HTTPS 发送 |
| `SameSite=Lax/Strict/None` | 控制跨站请求携带行为；`None` 必须配合 Secure |
| `Domain` / `Path` | 限制发送范围 |
| `Max-Age` / `Expires` | 生命周期；不设置通常为会话 Cookie |
| `Partitioned` | 在支持的浏览器中按顶级站点分区，适合特定第三方场景 |

注意：Cookie 会自动随匹配请求发送，过大或过多会增加每次请求的网络成本。Session Cookie 仍需服务端鉴权、撤销和轮换设计。

## 2. Web Storage

`localStorage` 与 `sessionStorage` 都是同步字符串键值 API：

- `localStorage` 通常跨页面和浏览器重启保留，按 origin 隔离；
- `sessionStorage` 按 origin + 顶级浏览上下文隔离，标签页会话结束后清除；
- 容量、隐私模式和异常行为由浏览器决定，不应依赖固定配额；
- 同步读写大数据会阻塞主线程，不适合存大量 JSON；
- 不要在 Web Storage 中保存长期高价值 token，XSS 可以读取它。

## 3. IndexedDB

IndexedDB 是异步、事务型、按 origin 隔离的结构化数据存储，适合离线数据、较大缓存、文件 Blob 和本地索引。

- 数据库有版本号，升级在 `upgradeneeded` 中创建 object store、索引和迁移逻辑。
- 读写必须在事务中完成；事务结束后不能继续使用相关对象。
- 事务失败、版本冲突、用户拒绝和配额不足都要处理。
- 不要把 IndexedDB 当作跨设备数据库；它只是本地副本，必须设计同步冲突和离线队列。

## 4. Cache API

Cache API 以 Request/Response 为键值，常与 Service Worker 配合：

```js
const cache = await caches.open('assets-v1')
await cache.addAll(['/index.html', '/app.css'])

const cached = await cache.match(request)
return cached ?? fetch(request)
```

Cache API 不会自动遵循所有 HTTP 缓存语义。应主动管理版本、失效、响应状态和缓存范围，避免把带用户数据的响应放进共享缓存。

## 5. Service Worker

Service Worker 是独立于页面的 Worker，可拦截受控页面的网络请求，提供离线、缓存更新、推送和后台同步等能力。

生命周期：`install` -> `waiting` -> `activate` -> `activated`。新 Worker 安装完成后不一定立刻控制旧页面；`skipWaiting` 与 `clientsClaim` 会改变更新时机，使用前应考虑旧页面和新缓存是否兼容。

```js
self.addEventListener('fetch', (event) => {
  if (event.request.method !== 'GET') return
  event.respondWith(
    caches.match(event.request).then((cached) => cached || fetch(event.request)),
  )
})
```

常见策略：

- Cache First：静态资源优先缓存，适合带哈希文件；
- Network First：先网络，失败时缓存，适合需要较新内容的页面；
- Stale While Revalidate：先返回旧缓存，同时后台更新；
- Network Only/Cache Only：用于特定数据或离线资源。

## 6. PWA 与离线同步

可靠离线体验通常需要：应用壳缓存、离线页面、IndexedDB 数据、待同步操作队列、冲突解决和更新提示。不能只注册 Service Worker 就称为“支持离线”。

- 写操作离线时生成客户端操作 ID，恢复网络后幂等提交。
- 同步失败需可重试、进入死信或展示给用户；不能静默丢失用户数据。
- 应用更新要兼容旧页面仍在使用的缓存和接口版本。

## 7. 配额、隐私与清理

- 浏览器可能基于磁盘空间、使用频率和站点存储压力淘汰数据；不要把唯一数据只放浏览器本地。
- 无痕模式、用户清理、Storage Partitioning 和第三方 Cookie 限制会改变行为。
- 使用 `navigator.storage.estimate()` 可获得近似使用量与配额，但不是持久性保证。
- 只申请和保存业务所需数据；提供清理、导出和账户注销后的本地数据处理策略。
