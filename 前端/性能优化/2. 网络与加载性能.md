# 网络与加载性能

页面加载性能的关键是缩短关键请求链：更早发现资源、更少等待连接、更少传输字节、更高缓存命中，并让非关键资源不阻塞首屏。

## 1. 请求耗时分解

DevTools Timing 常见阶段：Queueing/Stalled、DNS、Initial Connection、TLS、Request Sent、Waiting for Server Response（TTFB）、Content Download。

- DNS/连接高：域名过多、未复用连接、跨地域、代理或网络质量问题；
- TTFB 高：CDN 未命中、服务端计算、数据库或下游慢；
- 下载高：响应过大、带宽低、未压缩；
- Queueing 高：资源优先级、连接限制或主线程调度问题。

## 2. 协议与连接

- HTTP/2 多路复用减少多连接需求，但 TCP 丢包仍会影响整个连接。
- HTTP/3 基于 QUIC，不同流可独立恢复，并支持连接迁移；实际收益依赖网络和部署。
- 减少无意义域名可降低 DNS/TLS 成本，但 CDN、Cookie 隔离和第三方服务可能需要不同域。
- 保持连接、TLS 会话恢复和 CDN 边缘节点可降低后续请求延迟。

## 3. 资源发现与优先级

```html
<link rel="preconnect" href="https://cdn.example.com" crossorigin>
<link rel="preload" href="/hero.avif" as="image" fetchpriority="high">
<link rel="modulepreload" href="/assets/entry.js">
```

- `preconnect` 只用于确定会请求的关键跨源，过多连接浪费资源；
- `preload` 用于本页面高优先级且浏览器难以及时发现的资源，必须正确设置 `as`、类型和 crossorigin；
- `prefetch` 用于未来可能使用的低优先级资源；
- LCP 图片可使用 `fetchpriority="high"`，但不要给大量图片设置高优先级；
- 预加载后必须实际以匹配的请求属性使用，否则可能下载两次。

## 4. 阻塞资源

- CSS 通常阻塞渲染。提取首屏关键 CSS、拆分非关键样式，但不要内联过多导致 HTML 膨胀和无法独立缓存。
- 普通脚本阻塞 HTML 解析；应用脚本通常使用 module/defer，独立统计脚本可评估 async。
- 第三方脚本可能增加 DNS、JS 执行、布局和隐私成本；延迟到同意或交互后加载，并设置业务负责人和预算。
- 重定向会增加完整往返，入口、图片和 API 应避免重定向链。

## 5. 压缩与传输

- 文本资源使用 Brotli/gzip；已经压缩的 JPEG/AVIF/视频通常不需要再次传输压缩。
- 压缩级别越高 CPU 成本越高，静态资源可离线高压缩，动态响应取平衡。
- 删除未使用字段、避免返回巨大列表、对 API 分页；前端 gzip 后体积小也不代表解析执行成本低。
- Early Hints（103）可让浏览器在最终响应前发现关键资源，但必须验证基础设施支持和实际收益。

## 6. 缓存策略

- HTML：`Cache-Control: no-cache` 或短时缓存；
- 哈希静态资源：`public, max-age=31536000, immutable`；
- 个性化 API：默认 private，并明确数据新鲜度；
- CDN 使用 `s-maxage`、`stale-while-revalidate`，同时确保缓存 key 与用户隔离正确；
- 发布时保留旧哈希文件，避免旧 HTML 找不到资源。

## 7. Service Worker

Service Worker 可提供离线和运行时缓存，但会增加更新状态机：

- 静态哈希资源适合 Cache First；
- 内容列表可用 Stale While Revalidate；
- 强一致数据使用 Network First 或 Network Only；
- 缓存版本化、清理、回滚和新旧页面兼容必须设计；
- 登录态响应不能因错误 cache key 泄露给其他用户。

## 8. 测试方法

在 DevTools 中分别测试 Disable Cache、冷缓存和热缓存；设置移动设备 CPU/网络节流；检查 Initiator、Priority、Protocol、Size、Timing。线上监控 CDN 命中率、回源率、TTFB、传输大小和错误率。
