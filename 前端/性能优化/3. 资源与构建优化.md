# 资源与构建优化

构建优化的目标不是追求最少文件或最高压缩率，而是让每条用户路径只下载、解析和执行必要代码，并维持稳定缓存边界。

## 1. JavaScript 体积

- 使用 bundle analyzer/metafile 检查包组成，而不是只看源代码行数；
- 避免同时引入多个功能重叠库、整个图标包、全部 locale 或大 polyfill；
- 优先选择可 Tree Shake 的 ESM 包，并检查包的 `sideEffects` 声明；
- 检查依赖是否重复安装多个版本；通过 lockfile 和包管理器分析依赖树；
- 比较 raw、gzip/Brotli 与解析执行成本。压缩后体积不是唯一指标。

## 2. 代码分割

常见层级：路由级、功能级、重型组件级和条件依赖级。

```ts
const Editor = lazy(() => import('./Editor'))
```

- 首屏不需要的编辑器、图表、富文本、管理模块适合动态加载；
- 切得太细会增加 chunk 管理、请求与运行时开销；
- 共享 chunk 变化可能使多个页面缓存同时失效；
- 加载失败要提供 Error Boundary、重试和版本发布后的资源 404 处理。

## 3. Tree Shaking

Tree Shaking 依赖静态 ESM 导入导出和正确副作用信息。失效原因包括：CommonJS、不透明动态访问、模块顶层副作用、错误 `sideEffects` 配置、构建目标保留动态行为。

不要随意把整个项目标记 `sideEffects: false`；CSS 导入、polyfill、注册器等副作用可能被错误删除。

## 4. Polyfill 与浏览器目标

- 根据真实用户浏览器设置 Browserslist/target，目标越旧通常产物越大；
- 语法转换不等于 Web API polyfill；
- 差异化构建需权衡缓存、部署和测试成本；
- 避免多个编译阶段重复注入 helpers/polyfill。

## 5. CSS

- 清除未使用 CSS 时要正确扫描动态类名，原子化框架需要 safelist；
- 按路由或组件拆分 CSS，避免所有页面加载完整设计系统样式；
- 压缩、合并重复规则，但不要破坏层叠、顺序和自定义属性语义；
- 关键 CSS 内联应设上限，其余样式保持可缓存资源。

## 6. 图片

- 使用 AVIF/WebP 等现代格式，并保留兼容 fallback；
- `srcset` 与 `sizes` 让浏览器选择合适像素尺寸；
- 非首屏使用 `loading="lazy"`，首屏 LCP 图片不应懒加载；
- 设置 width/height 或 aspect-ratio；
- 图标优先 SVG/图标组件，小图是否内联需权衡缓存和 HTML/JS 体积；
- 图片 CDN 可按设备、DPR、格式和质量动态转换。

## 7. 字体

- 只加载需要的字重、字符集和样式；使用 subset；
- WOFF2 是常见 Web 字体格式；
- `font-display` 在 FOIT、FOUT 和布局稳定间取舍；
- 关键字体可 preload，但过多字体会抢占 LCP 图片和 CSS 带宽；
- 使用相近 fallback、`size-adjust` 等减少字体切换 CLS。

## 8. Source Map

生产 Source Map 有利于错误还原，但可能暴露源码：

- 上传到错误监控平台而不公开部署；
- 版本、commit 与构建产物必须关联；
- 构建后验证 map 可映射真实错误；
- Source Map 生成本身也会增加构建时间和存储。

## 9. 构建性能

- 使用持久缓存、增量编译、并行任务和缩小 loader/plugin 匹配范围；
- TypeScript 转译与类型检查可分离，但 CI 不能省略类型检查；
- Monorepo 使用任务图和输入哈希，只构建受影响包；
- 优化构建时间不能牺牲产物正确性、测试和可复现性。
