# 性能优化面试题

## 1. 如何系统优化首屏？

先用 RUM/Lab 找 LCP 元素和耗时分解；降低 TTFB；让 LCP 资源尽早可发现；压缩图片并设置优先级；减少阻塞 CSS/JS；路由级拆包；缓存哈希资源；最后用相同条件复测并观察真实用户数据。

## 2. LCP、INP、CLS 分别衡量什么？

LCP 衡量主要内容出现，INP 衡量访问期间交互到下一次绘制的响应性，CLS 衡量非预期布局位移。三者分别对应加载、交互和视觉稳定性，不能只优化其中一个。

## 3. 为什么 gzip 后 JS 很小，页面仍可能卡？

下载后还需解压、解析、编译和执行。大量组件初始化、polyfill、JSON 和第三方脚本会占用主线程。应同时看传输体积、Coverage、CPU Profile 和 Long Task。

## 4. Tree Shaking 为什么可能失效？

CommonJS、动态访问、模块顶层副作用、错误 sideEffects 声明或构建配置都可能妨碍静态分析。需要检查最终产物而不是认为使用 ESM 就必然删除未用代码。

## 5. preload、prefetch、preconnect 区别？

preconnect 提前建立到某个 origin 的连接；preload 高优先级加载当前页面必需资源；prefetch 低优先级获取未来可能使用资源。滥用会抢带宽或浪费连接。

## 6. 防抖和节流如何选择？

防抖在停止触发一段时间后执行，适合搜索请求；节流限制持续事件的执行频率，适合滚动/拖动。输入 UI 应立即响应，仅把昂贵副作用防抖。

## 7. 什么是布局抖动？

脚本反复写 DOM/样式并读取几何信息，迫使浏览器多次同步样式和布局。通过批量读、批量写，使用 Observer 和减少布局依赖来解决。

## 8. 为什么 transform 动画通常更流畅？

独立合成层上的 transform 常能跳过布局和绘制，只由合成线程更新。但图层提升不保证，过多图层会占显存；仍需 Performance/Layers 验证。

## 9. React 的 useMemo 是否应该大量使用？

不应该。它有依赖比较、内存和代码复杂度成本，且缓存不是语义保证。只在昂贵计算或稳定引用能阻止已确认的下游渲染时使用，并通过 Profiler 验证。

## 10. Vue 大对象响应式成本如何优化？

避免无意义深度 watch；使用 shallowRef/shallowReactive 管理巨大不可变结构；更新时替换根引用；列表虚拟化；把派生值放 computed。先确认响应式追踪确实是瓶颈。

## 11. SSR 一定比 CSR 快吗？

不一定。SSR 可更早提供 HTML，但增加服务端计算、网络传输和 hydration；慢 TTFB 或巨大客户端 bundle 仍会差。应按页面、缓存、交互和设备选择 CSR/SSR/SSG。

## 12. 如何减少 CLS？

为图片、iframe、广告预留尺寸；使用稳定骨架；避免在已有内容上方异步插入；优化字体 fallback；动画用 transform。区分用户预期位移和非预期位移。

## 13. 如何判断是否存在内存泄漏？

重复相同操作，比较 Heap Snapshot 和 retained size；寻找持续增长且无法 GC 的对象及引用链。仅看到内存瞬时上涨不等于泄漏，缓存和 GC 时机都会影响曲线。

## 14. Service Worker 如何影响性能？

它可缓存资源、离线响应和减少网络等待，也可能因旧缓存、双层缓存、启动和更新问题造成错误。必须版本化缓存、设计更新和回滚，并监控实际命中。

## 15. 如何优化第三方脚本？

先盘点业务价值、体积、执行和数据风险；删除未用脚本；非关键脚本延迟到同意/交互/空闲；使用 facade；设置预算、超时和负责人；在 RUM 中区分第三方任务。

## 16. 性能优化如何证明有效？

建立基线和可复现条件，记录目标指标；灰度或 A/B 发布；同时比较 Lab 与 RUM 分位数；检查错误率和业务指标副作用；覆盖足够样本与时间后得出结论，并设置回归预算。
