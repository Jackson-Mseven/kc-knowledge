# Content Script 与消息通信

Content Script 负责在匹配网页中读取、修改 DOM，并与扩展后台/UI 通信。

## 声明式注入

```json
{
  "content_scripts": [{
    "matches": ["https://*.example.com/*"],
    "js": ["content.js"],
    "css": ["content.css"],
    "run_at": "document_idle",
    "all_frames": false
  }]
}
```

`document_start` 适合必须尽早修改的场景，`document_idle` 更适合普通 DOM 功能。SPA 路由变化不会重新加载 Content Script，需要观察 history/DOM 或由后台导航事件通知。

## 动态注入

```js
await chrome.scripting.executeScript({
  target: { tabId, allFrames: false },
  func: (color) => { document.body.style.outline = `2px solid ${color}` },
  args: ['red'],
})
```

传入函数必须可序列化且不能捕获外部闭包。受保护页面、浏览器内部页和商店页面通常不可注入。

## 通信结构

```ts
type Message =
  | { type: 'PAGE_CHANGED'; url: string }
  | { type: 'SAVE_ITEM'; payload: { id: string; title: string } }
```

使用 discriminated union/schema 维护协议。一次请求使用 sendMessage，持续通道使用 connect/Port；消息体不传巨大 DOM/二进制，可传 ID 或分块。

## 页面世界通信

页面脚本和 Content Script 可通过 DOM CustomEvent、window.postMessage 或注入 MAIN world 桥接。必须校验来源和 payload，并避免把任意页面消息转发为高权限扩展 API。

## DOM 处理

- 使用 MutationObserver 监听动态内容，批处理并避免观察回调自触发；
- 元素加扩展专属 data attribute，防止重复注入；
- 样式使用前缀、Shadow DOM 或 iframe 隔离，避免污染宿主页面；
- 卸载/停用时移除 DOM、监听器、Observer 和 Port；
- iframe 注入需明确 `all_frames`、frameId 和跨源权限。

## 注意事项

网页可能恶意构造 DOM/消息攻击扩展。Content Script 拥有比网页更高的扩展通信能力，但仍不应直接执行页面提供的代码、URL 或命令。
