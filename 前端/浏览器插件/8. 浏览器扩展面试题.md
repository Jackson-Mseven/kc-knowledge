# 浏览器扩展面试题

## 1. Manifest V3 与 V2 主要区别？

MV3 用事件驱动 Service Worker 替代持久后台页，限制远程代码和动态执行，网络阻塞修改更多使用 declarativeNetRequest，并强化权限与 CSP。

## 2. Service Worker 为什么不能保存全局状态？

它会在空闲时终止，再由事件重新启动。全局变量随实例丢失，关键状态使用 storage/IndexedDB，并让事件处理可重入。

## 3. Content Script 能直接访问页面变量吗？

默认不能，因为运行在隔离世界；它与页面共享 DOM。需要桥接时可用 postMessage/DOM 事件或谨慎注入 MAIN world，并严格校验消息。

## 4. activeTab 和 Host Permission 区别？

activeTab 在明确用户操作后临时授权当前标签页；Host Permission 持续覆盖匹配网站。只需当前页面操作时 activeTab 更符合最小权限。

## 5. Popup 关闭后任务会继续吗？

Popup DOM 和脚本会销毁。长任务应交给 Service Worker/其他适合上下文，状态持久化，Popup 重开后查询进度。

## 6. 扩展上下文如何通信？

一次性消息使用 runtime/tabs.sendMessage，持续通信使用 Port；iframe/页面世界用 postMessage。协议应类型化、版本化并验证 sender/payload。

## 7. chrome.storage 和 localStorage 区别？

storage 可在扩展上下文共享，有 local/sync/session/managed 和变更事件；Service Worker 没有 localStorage。两者都不是秘密保险箱。

## 8. MV3 如何拦截网络？

主要用 declarativeNetRequest 声明 block、redirect 和 header 规则。调试观察规则匹配；复杂代理或响应体修改不一定支持。

## 9. 如何处理扩展升级？

onInstalled 运行幂等存储迁移，消息协议兼容旧 Content Script，重新加载时验证 Manifest/资源。不要假设升级后所有标签页立刻注入新脚本。

## 10. 如何保证扩展安全？

最小权限、禁止远程代码、严格 CSP、验证所有网页消息、避免危险 DOM API、保护 Token、审计依赖和发布账号，并披露数据处理。

## 11. 如何测试浏览器扩展？

核心逻辑单测、UI 组件测试、chrome API 集成 Mock，再用加载解压扩展的真实浏览器 E2E 验证注入、权限、Worker 重启和升级。

## 12. 如何支持 Chrome 和 Firefox？

采用 WebExtensions 公共 API和 browser polyfill，把差异封装在 adapter，生成各平台 Manifest，并分别跑真实浏览器 E2E与商店打包流程。
