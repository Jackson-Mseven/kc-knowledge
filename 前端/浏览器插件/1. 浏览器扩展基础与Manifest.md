# 浏览器扩展基础与 Manifest

浏览器插件通常指 Browser Extension。现代 Chromium 扩展以 Manifest V3 为主，通过受权限控制的 API 扩展浏览器 UI、操作标签页、修改页面或处理网络规则。

## 主要上下文

| 上下文 | 作用 | 可访问能力 |
| --- | --- | --- |
| Extension Service Worker | 后台事件、消息、菜单、网络规则 | 扩展 API；没有 DOM，生命周期短 |
| Content Script | 在目标网页中读取/修改 DOM | 页面 DOM、部分扩展 API；默认隔离世界 |
| Popup | 点击工具栏图标后的临时页面 | DOM 和扩展 API；关闭即销毁 |
| Options Page | 持久配置页 | DOM、扩展 API和存储 |
| Side Panel | 浏览器侧边栏 UI | 生命周期比 Popup 更适合持续交互 |
| DevTools Page/Panel | 扩展开发者工具 | DevTools 专用 API |
| Offscreen Document | 后台需要 DOM/媒体等少数场景 | 需声明原因，不能当永久后台页滥用 |

## 最小 Manifest V3

```json
{
  "manifest_version": 3,
  "name": "Page Inspector",
  "version": "1.0.0",
  "description": "Inspect the current page",
  "action": { "default_popup": "popup.html" },
  "background": { "service_worker": "background.js", "type": "module" },
  "permissions": ["storage", "activeTab", "scripting"],
  "host_permissions": ["https://example.com/*"]
}
```

## 常用字段

- `permissions`：扩展 API 权限，如 storage、tabs、scripting；
- `host_permissions`：可访问的网站范围；
- `optional_permissions/optional_host_permissions`：运行时按需请求；
- `content_scripts`：声明式注入脚本和 CSS；
- `web_accessible_resources`：允许网页访问扩展包内资源；
- `commands`：键盘快捷键；
- `content_security_policy`：扩展页面 CSP；
- `icons`：商店、管理页和工具栏图标；
- `minimum_chrome_version`：依赖新 API 时限制版本。

## 开发流程

1. 在扩展管理页面开启开发者模式；
2. 加载已解压的扩展目录；
3. 修改 Manifest/Service Worker 后重新加载扩展；
4. Popup/Content Script 改动通常还需刷新目标页面；
5. 分别检查扩展 Worker、Popup、页面和 DevTools 的控制台。

## MV2 与 MV3 差异

- 持久 Background Page 改为事件驱动 Service Worker；
- 远程托管代码受严格限制，执行代码应随扩展打包；
- 阻塞式 webRequest 修改主要转向 declarativeNetRequest；
- 权限、CSP 和安全边界更严格；
- 不能假设全局变量长期存在，状态必须持久化或按事件重建。

## Chrome 与 Firefox

WebExtensions API 大体兼容，但命名空间、Manifest 字段、MV3 Service Worker、Side Panel 和网络 API 支持可能不同。可使用 `browser.*` Promise API 或兼容 polyfill，并通过构建生成平台特定 Manifest。不能只在 Chromium 测试后声明全浏览器支持。
