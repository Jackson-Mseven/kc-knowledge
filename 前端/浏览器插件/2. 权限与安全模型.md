# 权限与安全模型

扩展权限可能读取全部网页、Cookie、历史或修改网络，因此应遵循最小权限、按需申请和明确用户意图。

## 权限分类

- API 权限：storage、tabs、cookies、bookmarks、history 等；
- Host 权限：匹配指定 Origin，可影响 fetch、注入和页面访问；
- `activeTab`：用户点击扩展后临时访问当前标签页，通常比 `<all_urls>` 更安全；
- Optional 权限：功能启用时调用 permissions.request 请求；
- Site Access：用户可在浏览器中限制扩展对站点的访问。

```js
const granted = await chrome.permissions.request({ origins: ['https://api.example.com/*'] })
```

权限请求应由用户手势触发，解释为什么需要；被拒绝后提供降级，不循环弹窗。

## 隔离世界

Content Script 与页面共享 DOM，但 JavaScript 全局环境默认隔离。页面的变量/函数不能直接读取；DOM 属性和事件仍是共享边界。若必须进入 MAIN world，风险更高，输入和消息必须严格校验。

## CSP 与代码执行

- 禁止 eval/new Function 和任意远程脚本；
- 第三方库随包发布并固定版本；
- `web_accessible_resources` 只暴露必要资源，并限制 match；
- 向页面插入 HTML 使用 textContent/可信模板，防 XSS；
- 不将网页数据当可信指令执行。

## 消息安全

所有消息都是不可信输入。验证 sender.id、sender.url/origin、tab、消息 type 和 payload schema。External Messaging/Native Messaging 更需白名单和用户授权。

## 敏感数据

- chrome.storage 不是加密保险箱；本地恶意软件和扩展上下文漏洞仍可能读取；
- 不保存用户密码、长期云密钥和 OAuth Client Secret；
- OAuth 使用浏览器 identity 流程、PKCE 和短期 Token；
- 日志、崩溃报告和同步存储不得泄露页面内容或 Token；
- 隐私政策必须准确说明收集、用途、共享和删除。

## 供应链

锁定依赖、审查安装脚本、生成 SBOM/许可证清单、限制发布账号权限和启用 MFA。扩展更新拥有已安装用户的高权限，发布账号被盗属于严重供应链事件。
