# 环境变量与发布流程

前端构建变量最终会进入浏览器可下载的 JavaScript，任何 `VITE_*`、`NEXT_PUBLIC_*` 等公开变量都不是秘密。环境管理的首要原则是区分构建期公开配置、服务端秘密和运行时配置。

## 配置分类

| 类型 | 示例 | 存放位置 |
| --- | --- | --- |
| 公开构建配置 | API public URL、Sentry DSN | 构建变量，可进入客户端 |
| 服务端秘密 | DB 密码、OAuth Client Secret | Secret Manager/CI Environment |
| 运行时动态配置 | 灰度开关、地区 API | 配置服务或部署注入 |
| 用户功能开关 | 实验、逐步开放 | Feature Flag 系统 |

## 校验

应用启动/构建时使用 schema 校验必填、URL、枚举和数字范围，失败立即终止。不要让缺失变量变成 `undefined` 并到线上才报错。

## `.env` 约定

- 提交 `.env.example`，不提交真实 `.env.local`；
- `.gitignore` 不是 Secret 管理方案，已提交的密钥必须撤销轮换；
- 明确 `.env`、shell、CI 和框架 mode 的覆盖顺序；
- 日志只输出配置名称与安全摘要，不输出秘密值。

## 完整发布流程

1. PR：lint、类型、测试、构建、安全与 changeset；
2. Preview：部署临时 URL，运行 E2E/视觉/性能；
3. Merge：主分支生成不可变产物并签名/记录 SBOM；
4. Staging：注入环境配置，执行 smoke 和迁移验证；
5. Production：Canary/Rolling 发布；
6. Verify：错误、性能、业务指标和资源加载；
7. Promote/Rollback：扩大流量或恢复上一产物；
8. Cleanup：删除预览环境、过期 flag 和旧 artifact（保留回滚窗口）。

## 前端静态资源发布

- 文件名使用内容哈希并长期缓存；
- HTML 短缓存/重新验证；
- 先上传新资源，再切换 HTML；
- 保留旧哈希资源，兼容旧页面和灰度用户；
- Source Map 上传监控平台，不必公开托管；
- Service Worker 单独设计更新提示、缓存迁移和紧急禁用。

## Feature Flag

Flag 需要 owner、默认值、目标用户、创建/过期日期和审计。权限/计费不能只靠前端 Flag，服务端必须校验。实验结束后删除 flag 和旧代码路径，避免永久分支增加测试矩阵。

## 发布清单

- 版本、commit、artifact 和配置可追踪；
- 数据迁移向后兼容；
- 核心路径 smoke 通过；
- 回滚步骤经过演练；
- 告警、值班和负责人明确；
- 更新日志和用户迁移说明已准备。
