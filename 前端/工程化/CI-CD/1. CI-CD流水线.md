# CI/CD 流水线

CI 持续验证每次变更；CD 把通过验证的产物安全交付到环境。核心要求是可重复、可追踪、最小权限、同一产物逐环境晋级和可快速回滚。

## 推荐阶段

1. Checkout、固定 Node/包管理器版本；
2. 冻结 lockfile 安装；
3. 格式、lint、类型检查、单元/组件测试；
4. 构建一次并生成 immutable artifact；
5. 依赖/Secret/镜像安全扫描；
6. 部署预览环境，运行 E2E、视觉、性能预算；
7. 审批/自动策略后发布生产；
8. Smoke Test、监控、自动或人工回滚。

## 缓存与产物

- 缓存下载存储和任务结果，key 包含 lockfile、运行时、配置与平台；
- 缓存不可信输入产生的可执行产物时考虑投毒风险；
- Artifact 包含 commit、构建号和 Source Map 映射；
- 不在不同环境重新构建，环境差异通过运行时配置或部署配置注入。

## 并发与环境

- 同一分支新提交可取消旧流水线；生产部署使用 concurrency lock；
- Preview Environment 自动创建并在 PR 关闭后销毁；
- 数据库迁移向后兼容，采用 expand/migrate/contract，避免新旧实例滚动期间冲突。

## 发布策略

- Rolling：逐步替换实例；
- Blue-Green：新旧环境切换，回滚快但资源成本高；
- Canary：小流量验证错误与性能再扩大；
- Feature Flag：部署与功能开放解耦，但需要生命周期和清理治理。

## 安全

- CI 使用 OIDC/短期凭证，避免长期云密钥；
- fork PR 不应获得 Secret；
- Environment 权限、审批和审计日志；
- 第三方 Action 固定 commit SHA，审查权限；
- 构建日志和 artifact 不得包含 Token、`.env` 或 Source Map 私密地址。

## 回滚

回滚应用版本、静态资源、配置和数据库兼容必须共同设计。发布后监控错误率、关键 API、Web Vitals 和业务转化；超过阈值停止扩量或自动回滚。
