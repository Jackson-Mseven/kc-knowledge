# Turborepo 与 Nx

两者都能基于任务依赖图运行、缓存和分发 Monorepo 任务。Turborepo 偏轻量任务编排；Nx 提供更完整的项目图、插件、生成器和边界治理。

## Turborepo

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] },
    "test": { "dependsOn": ["build"], "outputs": [] },
    "dev": { "cache": false, "persistent": true }
  }
}
```

- `^build` 表示先构建依赖包；
- 缓存 key 由输入、依赖、环境等决定；
- `outputs` 必须准确，否则可能缓存缺失或无关文件；
- Remote Cache 可跨 CI/开发者复用，但需要权限和敏感产物治理。

## Nx

Nx 建立 Project Graph/Task Graph，支持 affected、插件推断、生成器、模块边界和分布式任务。适合希望以平台化方式治理大型仓库的团队，但学习和配置成本更高。

## 对比

| 维度 | Turborepo | Nx |
| --- | --- | --- |
| 心智模型 | package scripts + task pipeline | project graph + plugins/targets |
| 上手 | 较轻 | 功能多、学习成本更高 |
| 生成器/迁移 | 较少，依赖生态 | 强 |
| 边界治理 | 需结合 lint/自建规则 | 内建能力更完整 |
| 适合 | 已有 workspace，主要需要缓存编排 | 大型多团队、需要工程平台治理 |

## 缓存正确性

输入必须包含源码、配置、lockfile、环境变量和生成器版本；输出不能包含密钥。日期、随机数、外部网络等非确定性会破坏缓存，应消除或声明不可缓存。缓存命中后仍要保证产物可复现。

## 选型

先使用 Workspace 解决包链接；当 CI 重复工作明显时引入任务编排。只需要简单构建缓存优先 Turborepo；需要项目生成、迁移、边界和大型组织治理时评估 Nx。不要同时叠加多个任务编排器。
