# ESLint 与 Prettier

ESLint 检查代码质量、潜在错误和团队规则；Prettier 负责确定性的代码格式。职责分离可以减少规则冲突和评审噪声。

## ESLint Flat Config

```js
// eslint.config.js
import js from '@eslint/js'
import tseslint from 'typescript-eslint'

export default tseslint.config(
  { ignores: ['dist/**', 'coverage/**'] },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  {
    files: ['src/**/*.{ts,tsx}'],
    rules: { 'no-console': ['warn', { allow: ['warn', 'error'] }] },
  },
)
```

- 按文件类型配置 parser/plugin/rules；
- 类型感知规则需要 TypeScript Program，准确但更慢，可只在 CI 或源码范围启用；
- 不把 dist、coverage、生成文件交给 lint；
- 共享配置做成内部包，版本化发布。

## Prettier

```json
{
  "semi": false,
  "singleQuote": true,
  "trailingComma": "all"
}
```

Prettier 规则应少讨论、全仓一致。使用 eslint-config-prettier 关闭与格式冲突的 ESLint 规则；格式化可由编辑器保存、pre-commit 和 CI check 共同保证。

## 规则治理

- 规则必须说明解决的问题，避免审美规则和格式化重复；
- 新规则先 warn 观察，再修复存量并升级为 error；
- 禁用规则写最小范围和原因，避免全文件永久关闭；
- 自定义规则只用于组织真实且重复的错误模式。

## lint-staged

```json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{css,md,json,yaml,yml}": "prettier --write"
  }
}
```

pre-commit 只处理暂存文件，保证快速；CI 仍运行全量检查，因为本地 Hook 可以跳过。自动修复后应由 lint-staged 正确重新暂存。

## 注意事项

- ESLint 不能替代 TypeScript 类型检查和测试；
- Prettier 不能发现逻辑错误；
- 不在 CI 使用 `--fix` 静默修改代码，应以 check 失败提示开发者；
- IDE、CLI、CI 使用相同配置和版本。
