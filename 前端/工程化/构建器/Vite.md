# Vite

> 官方文档：[Vite](https://vite.dev/guide/)。Vite 是面向现代 Web 项目的构建工具，目标是提供更快、更精简的开发体验：开发阶段以原生 ES Modules 为基础提供开发服务器与 HMR，生产阶段输出优化后的静态资源。

## 架构与核心能力

- **开发服务器**：浏览器按需请求源码模块，Vite 只转换当前需要的模块，因此启动与更新无需先打完整 bundle；并提供快速 HMR。
- **依赖预构建**：预先处理依赖以改善 CommonJS/UMD 兼容和开发时模块请求性能。依赖变更或缓存失效时会重新优化。
- **生产构建**：官方当前文档描述由预配置的 **Rolldown** 进行生产打包；Vite 负责提供默认优化、代码分割和静态资源处理。应以项目锁定的 Vite 主版本文档为准，因为底层实现会随版本演进。
- **插件体系**：多数 Vite 插件遵循 Rollup 插件接口，并提供开发服务器和 HMR 相关钩子。

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': '/src' } },
  server: { port: 5173 },
  build: { sourcemap: true },
})
```

## 常用命令与配置

| 命令/配置 | 用途 |
| --- | --- |
| `vite` | 启动开发服务器 |
| `vite build` | 构建生产静态资源 |
| `vite preview` | 本地预览构建产物，不是生产服务器替代品 |
| `root` | 指定项目根目录；Vite 将 `index.html` 视为源码图的一部分 |
| `base` | 部署在子路径或 CDN 时设置资源公共基础路径 |
| `resolve.alias` | 配置模块路径别名 |
| `server.proxy` | 在开发服务器代理 API，避免本地跨域问题 |
| `build` | 配置产物目录、Source Map、目标环境和构建细节 |

Vite 暴露给客户端的环境变量默认需要 `VITE_` 前缀，并通过 `import.meta.env` 访问。不要将密钥放进任何客户端可读取的变量中，前缀只是一种暴露规则，不是安全保护。

## HMR、静态资源与部署

- HMR 会尝试局部替换模块；模块的副作用、状态边界和框架插件决定更新是否能保留状态，无法接受更新时会回退为整页刷新。
- `public` 目录适合不参与模块图、需要原样按根路径提供的资源；被源码 `import` 的静态资源会进入构建流程并获得哈希、内联或复制等处理。
- 部署子路径时需设置 `base`，否则构建后的资源 URL 可能请求错误位置。
- Vite 加速的是开发与构建流程，业务首屏性能仍取决于产物体积、网络、渲染、缓存与服务端响应。

## 常见问题

### Vite 为什么开发启动快？

它利用浏览器原生 ESM 按需提供和转换源码模块，而非每次启动都先完成整应用 bundle；依赖会被预构建以减少浏览器加载大量小模块与兼容性问题。

### `vite preview` 能否作为生产服务器？

不能。它的目的只是本地检查 `vite build` 产物。生产部署应使用 CDN、静态托管或专门的 Web 服务器，并配置缓存、压缩、安全响应头和回退规则。

### 为什么 `.env` 中的变量在浏览器拿不到？

只有符合 `envPrefix`（默认 `VITE_`）的变量才会暴露给客户端，且要通过 `import.meta.env` 读取。未暴露变量应仅在服务端/构建环境使用；任何客户端变量都不能包含秘密信息。
