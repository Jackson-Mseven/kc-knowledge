# SemVer 与 Changesets

语义化版本格式为 `MAJOR.MINOR.PATCH`：不兼容变更升级 major，向后兼容功能升级 minor，向后兼容修复升级 patch。SemVer 的前提是包有清晰公共 API。

## 版本范围

- `1.2.3`：精确版本；
- `^1.2.3`：通常允许同 major 的兼容更新；0.x 规则更严格；
- `~1.2.3`：通常允许 patch 更新；
- prerelease：`2.0.0-beta.1`，不会被普通稳定范围自动选中。

应用 lockfile 固定实际版本，库的 peerDependencies 应表达真实兼容范围并运行兼容测试。

## Changesets 流程

1. 开发者为用户可见变更运行 `changeset`，选择受影响包和 major/minor/patch；
2. 提交生成的 Markdown 变更文件；
3. 发布机器人聚合 changeset，更新版本与 changelog；
4. 合并版本 PR 后发布 npm/Git tag；
5. 已消费的 changeset 被删除。

```md
---
"@repo/ui": minor
---

新增 DatePicker 的 range 模式。
```

## Fixed 与 Independent

- Fixed/统一版本：相关包始终同版本，理解简单但发布频繁；
- Independent：各包独立版本，精确但依赖联动和用户理解更复杂；
- Linked groups 可让部分包保持关联版本。

## Breaking Change

删除/重命名导出、改变参数/返回、收紧 peer range、改变 CSS/DOM/行为都可能破坏消费者。提供迁移指南、codemod、弃用窗口和 prerelease 验证。

## 发布注意事项

- npm 发布使用 provenance/可信发布、2FA 和最小权限；
- 发布前检查 `files`、exports、types、README、license 和 pack 内容；
- 用临时目录安装生成的 tarball 做消费者测试；
- npm 已发布版本通常不可覆盖，修复需发布新版本；
- changelog 面向使用者，不能只复制提交标题。
