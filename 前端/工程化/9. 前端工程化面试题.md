# 前端工程化面试题

## 1. npm、Yarn、pnpm 如何选择？

看生态兼容、Workspace、磁盘效率、依赖严格性和团队现状。pnpm 适合 Monorepo 和严格依赖；npm 门槛最低；已有成熟 Yarn 体系无需仅因潮流迁移。必须固定版本并提交单一 lockfile。

## 2. lockfile 有什么作用？

固定完整依赖解析、传递依赖和完整性信息，使 CI/本地可复现。package.json 的范围不能替代 lockfile；CI 使用冻结安装防止隐式修改。

## 3. Monorepo 的优缺点？

统一依赖、原子重构、共享规范和 affected CI；代价是仓库规模、权限、构建、发布和边界治理更复杂。它是协作方式，不是多项目必然选择。

## 4. Turborepo 和 Nx 区别？

Turborepo 以 package scripts 和缓存流水线为主，较轻；Nx 提供项目图、插件、生成器、迁移和边界治理，更平台化。按团队规模和治理需求选择。

## 5. ESLint 与 Prettier 为什么都需要？

ESLint 检查潜在错误和代码质量，Prettier 统一格式。使用 config-prettier 关闭冲突规则，CI 分别检查；二者都不能替代类型检查和测试。

## 6. Husky 和 Commitlint 能保证提交质量吗？

只能提供本地快速反馈和消息格式约束。Hook 可跳过，CI 必须兜底；代码质量仍依赖评审、测试和发布门禁。

## 7. SemVer 如何判断 Breaking Change？

任何破坏已声明公共 API 或消费者可依赖行为的变化都可能是 breaking，包括类型、DOM/CSS、默认值和 peer 范围。需要 major、迁移指南和弃用窗口。

## 8. Changesets 解决什么问题？

在多包仓库中让开发者随变更记录受影响包、版本级别和用户说明，再由发布流程聚合版本与 changelog，避免发布时从提交历史猜测影响。

## 9. CI 缓存为何可能不正确？

缓存 key 漏掉源码、配置、环境或 lockfile，会复用过期产物；任务含时间、随机数、网络也不确定。必须准确声明 inputs/outputs，并确保缓存不包含秘密。

## 10. 为什么要 Build Once, Deploy Many？

同一个已验证 artifact 在各环境晋级，避免生产重新构建得到不同依赖或代码。环境差异通过安全的运行时/部署配置注入，产物和 commit 可追踪。

## 11. 前端环境变量为什么不能保存秘密？

构建期变量会被替换进静态 JS，用户可以下载查看。Client Secret、数据库密码只能在服务端或安全 Secret 系统使用。

## 12. 如何设计静态资源发布和回滚？

新资源使用内容哈希先上传，HTML 后切换；旧资源保留回滚窗口；HTML 短缓存。发布记录关联版本、配置和 Source Map，异常时恢复上一入口/流量。
