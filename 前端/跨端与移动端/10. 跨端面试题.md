# 跨端与移动端面试题

## 1. 跨端主要方案有哪些？

Web/PWA、Hybrid WebView、React Native 原生视图、Flutter 自绘、Taro/uni-app 编译多端、Electron/Tauri 桌面。它们在渲染、系统能力、复用和发布上不同。

## 2. React Native 与 WebView 区别？

RN 把 React 组件映射为原生视图，通过 JSI/原生模块协作；Hybrid 在 WebView 渲染 DOM/CSS，通过 Bridge 调系统能力。前者原生交互更自然，后者 Web 复用更高。

## 3. Flutter 为什么多端一致？

Flutter 使用自身 Widget 和渲染引擎绘制大部分 UI，不完全依赖平台控件；一致性的代价是引擎包体、Dart 生态和平台集成成本。

## 4. Bridge 有哪些风险？

序列化与频繁通信性能、协议版本、线程、超时和安全。XSS 若能调用高权限 Bridge 会放大危害，因此必须校验 Origin、方法和参数并最小授权。

## 5. 小程序为什么不能直接复用所有 Web 库？

小程序没有完整浏览器 DOM/BOM，组件、CSS、网络、包体和运行时由平台限制。依赖 DOM 或动态代码的库可能不可用。

## 6. PWA 能完全替代原生 App 吗？

不能一概而论。PWA 安装、离线和 Push 能满足部分应用，但后台执行、系统 API、商店分发和平台支持仍有限。按功能和用户渠道决定。

## 7. Electron 和 Tauri 如何选择？

Electron 自带 Chromium，兼容一致、Node 生态成熟但体积/内存高；Tauri 使用系统 WebView 和 Rust，通常更轻，但平台差异和 Rust 集成成本更高。

## 8. 跨端代码应该共享什么？

优先共享领域逻辑、API schema、类型、状态和 token；UI 仅在平台语义一致时共享。强行共享全部 UI 会积累条件分支并损害平台体验。

## 9. OTA 更新需要注意什么？

资源签名、原子下载、灰度、回滚和 runtimeVersion 兼容；不能用 OTA 下发依赖新原生模块的代码，也必须遵守应用商店政策。

## 10. 如何测试跨端应用？

共享逻辑单测、各端组件/集成、真机 E2E、Bridge/API 契约和发布包 Smoke。按真实设备分布维护矩阵，模拟器不能替代权限、性能和系统生命周期测试。

## 11. React Native 新架构解决了什么？

JSI 让 JavaScript 能以更直接的方式与 C++/原生能力交互；TurboModules 改进原生模块加载与类型契约；Fabric 是新渲染系统；Codegen 从类型声明生成胶水代码。它减少旧 Bridge 的 JSON 序列化和全异步限制，但不意味着跨线程调用没有成本，也不自动解决业务层卡顿。

## 12. Flutter 的 Widget、Element、RenderObject 有什么区别？

Widget 是不可变 UI 配置，可频繁创建；Element 是 Widget 在树中的持久实例，维护位置、状态和依赖；RenderObject 负责布局、绘制和命中测试。`setState` 标记对应 Element 需要重建，并不等于整棵应用树都会重绘。

## 13. 为什么移动应用不能依赖退出回调保存数据？

操作系统可因内存、耗电或用户操作直接终止进程，应用未必收到可靠的退出通知。关键状态应在变更时增量持久化，并能在冷启动时从存储、Deep Link 和服务端恢复。

## 14. 如何设计一个安全的 JS Bridge？

固定方法白名单和类型 schema；验证调用页面 Origin、窗口和用户权限；限制文件/网络/系统能力范围；定义超时、取消、错误码与版本；敏感调用二次确认；记录审计但不泄漏数据。外部网页不能获得业务 Bridge。

## 15. 移动端列表卡顿如何排查？

先用 Profile/Release 真机确认是 JS/UI/Raster/主线程哪一侧慢，再看 item 渲染、状态更新范围、布局测量、图片解码、虚拟窗口和事件通信。不要先盲目加缓存；同时观察内存，扩大渲染窗口可能只是用内存换空白问题。

## 16. Deep Link 需要处理哪些场景？

自定义 Scheme 与域名关联链接、已安装/未安装、冷启动/热启动、登录前后恢复、旧版本未知路由、参数校验和敏感操作确认。Universal Link/App Link 可减少 Scheme 被抢占，但仍不能信任外部参数。

## 17. 如何处理权限永久拒绝？

先检查平台权限状态。可再次申请时在用户触发功能后解释用途；不可再次询问时提供降级能力，并在确有必要时引导系统设置。不能循环弹窗，也不能把系统授权等同于无限制收集数据。

## 18. 跨端应用的状态如何分层？

把临时 UI 状态、跨页面客户端状态、服务端缓存、持久化离线数据和原生系统状态分开。共享层优先保存平台无关领域状态；权限、网络、前后台等通过能力接口输入，避免业务直接依赖平台全局对象。

## 19. 如何控制跨端平台分支？

少量样式差异可使用平台选择器或平台文件；系统能力通过稳定 adapter/interface 隔离；大幅不同的交互应允许独立页面。避免在共享业务中散布大量 `if (ios)`，并用契约测试保证各端实现语义一致。

## 20. 为什么客户端环境变量不能保存秘密？

客户端代码、资源和二进制最终交给用户，可以被反编译、抓取或运行时读取。环境变量只解决构建配置，不提供保密。服务端密钥必须留在服务端；客户端 Key 只能通过域名、Bundle ID、签名、配额和服务端代理限制滥用。

## 21. 冷启动、热启动和恢复有什么区别？

冷启动需要创建进程和运行时，成本最高；热启动通常是已有进程重新展示；恢复还可能包含系统重建页面或跨端引擎状态。三类路径的初始化工作和性能指标不同，不能只统计一个“启动时间”。

## 22. 跨端项目为什么仍需要原生工程能力？

签名、权限、通知、Deep Link、商店发布、原生 SDK、构建失败和系统版本兼容都发生在 iOS/Android 工程层。框架覆盖常用路径，但复杂应用最终仍需要阅读 Xcode/Gradle 日志并修改 Swift/Kotlin 或平台配置。
