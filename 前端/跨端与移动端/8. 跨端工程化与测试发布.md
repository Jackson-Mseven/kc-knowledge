# 跨端工程化、测试与发布

## 代码共享

优先共享纯业务、API schema、领域类型、设计 token 和无平台依赖状态逻辑。UI 只有语义和交互一致时共享；平台差异使用 adapter，而不是遍布条件判断。

```text
packages/core        # 领域与 API
packages/design-token
apps/web
apps/native
apps/miniapp
apps/desktop
```

## 能力抽象

定义 Camera、Storage、Share、Auth、Analytics 接口，各端实现。能力返回明确 unsupported/denied/error，不能 silently no-op。平台专有功能允许专属 UI。

## 测试矩阵

- 共享逻辑：单元/契约测试；
- Web：Playwright + 移动真机；
- RN/Flutter：组件、集成和原生 E2E；
- 小程序：开发者工具 + 真机自动化/人工；
- Desktop：安装包、窗口、IPC、更新；
- 契约：Bridge、Deep Link、Push payload、API schema。

按真实用户占比定义 OS/设备矩阵，不可能覆盖所有型号。关键支付、登录、更新和离线流程跨主要平台运行。

## CI/CD

前端 JS、iOS、Android、桌面和小程序有独立签名与发布流水线。固定 Xcode/Android SDK/Flutter/Node 版本；保护证书和 Provisioning Profile；构建产物与 commit/runtimeVersion 关联。

## 灰度与监控

应用商店分阶段发布；JS/资源 OTA 也需灰度、签名和回滚。监控 JS 错误、原生崩溃、ANR、启动、内存、网络、Bridge 错误和版本分布。

## 版本兼容

服务端必须支持旧 App 长期存在。API、Deep Link、Push 和 Bridge 向后兼容；强制升级只用于安全/不可兼容场景，并提供清晰路径。

## 隐私与合规

权限在使用时申请；维护 iOS Privacy Manifest、Android 数据安全和商店隐私说明；SDK 数据收集与用户同意一致；账户注销和本地数据清理可验证。
