# 跨端基础与移动 Web

跨端开发的目标是在多个平台复用业务逻辑、UI 或工程体系。不存在“写一次完全一致运行”，平台能力、交互规范、审核和性能仍需适配。

## 学习路径

1. 先掌握本文的渲染路线、移动 Web 和平台差异；
2. 阅读 [[11. iOS与Android平台基础]]，理解生命周期、权限、签名和发布；
3. 根据技术栈选择 [[2. React Native与Expo]]、[[3. Flutter]]、[[4. Taro、uni-app与小程序]] 或 [[5. Hybrid、Capacitor与WebView]]；
4. 桌面应用阅读 [[6. Electron与Tauri]]，渐进式 Web 应用阅读 [[7. PWA]]；
5. 最后学习 [[8. 跨端工程化与测试发布]]、[[12. 移动端性能、安全与可访问性]] 和 [[9. 跨端方案对比]]；
6. 使用 [[10. 跨端面试题]] 检查是否理解核心取舍。

学习时重点回答三个问题：UI 最终由谁渲染、业务代码运行在哪个运行时、系统能力通过什么边界调用。多数跨端差异都可以由这三点推导。

## 主要路线

| 路线 | 渲染 | 代表方案 | 特点 |
| --- | --- | --- | --- |
| 响应式 Web/PWA | 浏览器 DOM | Web、PWA | 复用最高、发布快，系统能力受限 |
| Hybrid | WebView + Native Shell | Capacitor、自研容器 | Web 迭代快，通过 Bridge 调原生 |
| Native 跨端 | 原生 View | React Native | 接近原生 UI，需原生工程能力 |
| 自绘引擎 | Skia/自有渲染 | Flutter | 一致性强，包体和引擎成本较高 |
| 编译到多平台 | 转换为小程序/H5/RN | Taro、uni-app | 覆盖平台广，受各端语义交集限制 |
| 桌面 Web 技术 | WebView/Chromium + Native | Electron、Tauri | 桌面应用，资源与安全模型不同 |

## 移动 Web 适配

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

- 使用 Flex/Grid、Container Query、`clamp()` 和逻辑属性，不按设备型号硬编码；
- 刘海/圆角屏使用 `env(safe-area-inset-*)`；
- 移动视口高度优先评估 `dvh/svh/lvh`，传统 `100vh` 可能受地址栏影响；
- 点击目标足够大，处理 hover 不存在、触摸滚动和键盘操作；
- 表单输入设置正确 type、inputmode、autocomplete；
- 软键盘可能改变 visual viewport，底部固定输入框需真实设备测试。

## 触摸与手势

Pointer Events 统一鼠标、触控和笔；使用 pointer capture 完成拖拽。`touch-action` 告诉浏览器哪些手势由页面处理，避免过度 preventDefault 阻塞滚动。高频 pointermove 用 rAF/节流。

```css
.drag-handle {
  touch-action: none;
  user-select: none;
}

.horizontal-carousel {
  touch-action: pan-y;
}
```

点击区域不能只看图标视觉尺寸，可用 padding 扩大命中区。注意 300 ms 点击延迟在正确 viewport 的现代浏览器已通常消失，不应为了“优化”全局禁用缩放，这会损害无障碍。

## 性能

移动设备 CPU、内存、带宽和散热更有限。控制首屏 JS/图片、长任务、DOM、动画图层和后台活动；图片按 DPR/显示尺寸提供；列表虚拟化；用中低端真机和弱网测试。

## 网络与离线

移动网络会切换、断连和高延迟。请求设置超时/取消；写操作幂等；离线队列处理重复与冲突；展示明确同步状态。不要假设 `online` 事件等于业务 API 可用。

## 注意事项

移动端需同时覆盖横竖屏、字体缩放、深色、无障碍、低电量/后台、权限拒绝和系统返回手势。模拟器不能替代真机测试。

## 常见误区

- 代码复用率高不等于总成本低，调试、构建、商店和原生升级仍占成本；
- 多端 UI 完全一致不一定正确，导航、返回、菜单和权限应遵循平台习惯；
- 能调用原生 API 不等于适合该方案，还要评估实时性、线程、数据量和插件维护；
- 模拟器流畅不代表中低端真机流畅，Debug 构建也不能代表 Release 性能；
- 热更新是发布能力而非安全边界，必须做签名、兼容、灰度和回滚。
