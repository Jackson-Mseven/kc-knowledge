# Hybrid、Capacitor 与 WebView

Hybrid 应用用原生壳承载 WebView，通过 Bridge 暴露相机、文件、通知等系统能力。Capacitor 提供跨平台插件和原生工程集成，适合把 Web 应用封装为移动 App。

## 架构

```text
Web UI -> JS Bridge -> Native Plugin -> iOS/Android API
Native Event -> Bridge -> Web Event/Promise
```

Bridge 接口必须版本化、校验参数、声明权限和线程。不要暴露任意文件、命令或网络代理能力。

## 通信协议

```ts
type BridgeRequest = { id: string; method: 'camera.takePhoto'; params: { quality: number } }
type BridgeResponse = { id: string; result?: unknown; error?: { code: string; message: string } }
```

处理超时、取消、重复响应、页面刷新、容器版本和能力检测。大量二进制不要 Base64 频繁跨 Bridge，优先文件 URI/流式原生能力。

## WebView 安全

- 仅加载可信 HTTPS Origin，限制导航和弹窗；
- 禁止不必要文件访问、调试和混合内容；
- Bridge 校验当前页面 Origin，接口最小权限；
- 外部 URL 用系统浏览器打开；
- Token 使用原生安全存储，通过短期会话提供给 Web；
- 防止 XSS，因为成功 XSS 可能调用高权限 Bridge。

## 生命周期

处理前后台、内存回收、网络切换、系统返回键、Deep Link、键盘、状态栏和安全区域。WebView 页面可能被系统销毁，状态需恢复。

## 更新

Web 资源热更新必须签名、原子下载、校验、回滚，并遵守商店政策。原生插件变化需要新二进制；Web 版本与 Bridge runtimeVersion 必须兼容。

## 适用场景

已有成熟 Web 应用、内容/表单为主、原生能力有限时成本低。重动画、复杂手势、高性能音视频和深度系统集成通常更适合原生/RN/Flutter。
