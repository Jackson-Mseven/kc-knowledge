# React Native 与 Expo

React Native 使用 React 声明 UI，渲染为原生视图，不是网页 DOM。现代架构包含 Fabric Renderer、TurboModules、JSI 与 Codegen，减少旧 Bridge 的序列化和异步通信限制。

## 基本组件

```tsx
import { useState } from 'react'
import { Pressable, StyleSheet, Text, View } from 'react-native'

export function Counter() {
  const [count, setCount] = useState(0)
  return (
    <View style={styles.container}>
      <Text accessibilityLiveRegion="polite">{count}</Text>
      <Pressable
        accessibilityRole="button"
        onPress={() => setCount((value) => value + 1)}
      >
        <Text>增加</Text>
      </Pressable>
    </View>
  )
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center' },
})
```

- View/Text/Image/ScrollView 是原生抽象，不能使用 div/CSS；
- StyleSheet 接近 CSS 但属性集合和布局语义不同，Flex 默认方向等需注意；
- FlatList/SectionList 用于大列表，稳定 key、估算布局和 memo item；
- Platform/平台文件处理 iOS/Android 差异。

React Native 的 Flexbox 默认 `flexDirection: 'column'`，尺寸通常没有 CSS 单位，数值代表逻辑像素。文本必须放在 `Text` 中；不是所有 CSS 属性、伪类和浏览器 API 都存在。

## Expo

Expo 提供项目工具、路由、原生模块 SDK、构建和更新服务。Development Build 支持自定义原生模块；Expo Go 只包含预置能力，不代表生产应用限制。

```bash
npx create-expo-app@latest
npx expo start
```

常见项目结构：

```text
app/                 # Expo Router 文件路由
components/          # 可复用视图组件
features/            # 按业务领域拆分
services/            # API、存储、通知等适配器
assets/              # 图片、字体
app.json             # Expo 配置
eas.json             # EAS Build/Submit/Update 配置
```

## 导航、状态与数据

Expo Router/React Navigation 管理原生栈、Tab、Deep Link 和 Universal Link。服务端状态可用 TanStack Query；局部/客户端状态保留 React/Zustand 等。导航参数应可序列化，不传巨大对象。

文件路由示例：

```tsx
// app/users/[id].tsx
import { useLocalSearchParams } from 'expo-router'

export default function UserScreen() {
  const { id } = useLocalSearchParams<{ id: string }>()
  return <Text>用户：{id}</Text>
}
```

应用进入后台后定时器、网络、相机和定位的行为会改变。通过 `AppState` 感知前后台，但不要假设应用一定能收到终止回调；重要状态要增量持久化。

## 原生能力

相机、通知、位置、文件和生物识别都需要平台权限、Manifest/Info.plist 配置及拒绝降级。敏感数据使用 Keychain/Keystore 安全存储，而非 AsyncStorage。

原生模块分三类：Expo SDK 已提供的模块、社区模块、自研 TurboModule/原生 View。引入前检查 New Architecture、目标 RN/Expo 版本、平台维护状态和构建方式；原生依赖变化需要重新构建 Development Build/安装包。

## 性能

- 避免 JS 线程长任务和频繁跨原生边界；
- 动画使用 Reanimated 等可在 UI 线程执行的方案；
- 图片缓存、列表窗口、包体和启动时间需监控；
- Hermes 引擎、Source Map 和原生崩溃符号要与 release 关联。

调优时先确定瓶颈所在：JS FPS 下降通常是 JS 线程繁忙；UI FPS 下降可能是布局、绘制或原生主线程；列表空白和跳动常与 item 测量、窗口参数、图片解码有关。不要在没有 Profiling 数据时到处添加 `memo`。

## 测试与调试

- 纯函数和 Hook：Vitest/Jest；
- 组件交互：React Native Testing Library，以可访问角色和文本查询；
- 关键流程：Detox、Maestro 等真机/模拟器 E2E；
- 网络：覆盖超时、断网、恢复和旧版本 API；
- 原生问题：结合 Xcode、Android Studio、Logcat、原生崩溃和 JS 日志。

## 发布

iOS/Android 签名、证书、隐私声明、商店审核和分阶段发布分别管理。OTA 更新只能修改允许的 JS/资源，并确保 runtimeVersion 与原生二进制兼容；不能绕过商店政策下发原生能力。

## 优劣势

React 团队复用心智、原生 UI 与生态丰富；代价是原生依赖升级、双平台调试、构建签名和性能边界，复杂应用仍需 iOS/Android 能力。
