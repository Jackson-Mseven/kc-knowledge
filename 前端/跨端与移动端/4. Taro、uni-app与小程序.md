# Taro、uni-app 与小程序

小程序运行在平台提供的逻辑层/渲染层和受限 API 中，不等同于普通浏览器。Taro、uni-app 通过编译和运行时适配把统一源码输出到微信/支付宝/抖音/H5 等平台。

## Taro

偏 React 语法和工程生态，可输出多种小程序/H5，并支持插件和平台条件编译。适合已有 React 团队和复杂工程治理。

```tsx
import { Button, View } from '@tarojs/components'
import Taro, { useLoad } from '@tarojs/taro'

export default function Home() {
  useLoad((query) => console.log('页面参数', query))

  return (
    <View>
      <Button onClick={() => Taro.navigateTo({ url: '/pages/detail/index?id=1' })}>
        查看详情
      </Button>
    </View>
  )
}
```

组件优先从 `@tarojs/components` 引入，平台 API 通过 Taro 统一层访问。React 生态库只有在不依赖 DOM/BOM 且与目标运行时兼容时才能直接复用。

## uni-app

偏 Vue 语法，覆盖小程序、H5、App 等，配套组件、插件市场和原生扩展。适合 Vue 团队和广平台业务。

```vue
<script setup lang="ts">
function openDetail() {
  uni.navigateTo({ url: '/pages/detail/detail?id=1' })
}
</script>

<template>
  <view class="page">
    <button @click="openDetail">查看详情</button>
  </view>
</template>
```

uni-app 的 `pages.json` 管理页面、导航栏、TabBar 和分包，`manifest.json` 管理各平台应用配置。条件编译用于少量无法统一的能力，业务核心不应被大量平台宏切碎。

## 小程序运行模型

小程序一般把逻辑线程和渲染层隔离，通过序列化数据驱动视图；不同平台实现细节并不完全相同。频繁传输大对象、深层响应式更新和超长列表会放大跨层成本。

典型生命周期包括应用启动/前后台、页面加载/显示/隐藏/卸载和组件挂载/卸载。页面隐藏不等于销毁，订阅、播放器、定位和计时器要按业务生命周期暂停并释放。

## 核心限制

- 只能使用框架支持的组件/API 交集；
- DOM、CSS、事件、路由和包体限制因平台不同；
- 平台专有登录、支付、分享和隐私协议必须分别实现；
- 第三方 Web 库依赖 DOM 时可能无法运行；
- 条件编译过多会形成多个隐藏代码库。

基础库版本也会影响 API 是否可用。既要在配置中声明最低版本，也要用能力检测处理旧客户端，并提供更新引导或降级路径。

## 分包与性能

主包保持最小，页面/功能使用分包和预下载；避免 setData/跨层传输巨大对象；图片 CDN 化；长列表使用平台能力；控制自定义组件层级和频繁更新。

不要把所有依赖打进每个分包；分析构建产物，提取合理公共依赖，同时留意平台对主包、单包和总包的限制。首屏只请求必要数据，骨架屏不能掩盖长时间主线程任务。

## 登录与安全

小程序登录 code 必须由后端换取会话，App Secret 不能放客户端。支付签名、手机号解密和权限均由服务端验证；前端隐藏按钮不等于权限控制。

登录 code 通常短期且一次性使用。服务端将平台身份映射为业务账户，再签发自己的会话；不要把 openid 当授权凭证。订阅消息、手机号、定位等还要符合平台最新的用户授权与隐私规范。

## 测试发布

分别使用各平台开发者工具和真机；覆盖扫码/分享/支付/授权/后台恢复；维护体验版、审核版和生产版；平台审核规则和隐私清单独立治理。

## 选型

主要微信且深度使用专有能力时原生小程序最稳；多平台和团队复用优先 Taro/uni-app；平台差异超过共享收益时按端拆实现。
