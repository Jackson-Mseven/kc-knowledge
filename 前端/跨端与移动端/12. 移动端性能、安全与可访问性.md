# 移动端性能、安全与可访问性

移动端质量受中低端硬件、网络切换、系统生命周期、触摸交互和应用商店规则共同影响。优化目标不是单一跑分，而是在真实设备上稳定完成核心任务。

## 性能指标

| 方向 | 常见指标 | 关注点 |
| --- | --- | --- |
| 启动 | 冷启动、热启动、可交互时间 | 首屏初始化和依赖装载 |
| 流畅度 | FPS、慢帧、冻结帧 | UI/JS/Raster/主线程阻塞 |
| 响应 | 点击到反馈、页面切换、输入延迟 | 同步任务、锁和跨线程通信 |
| 资源 | PSS/RSS、峰值内存、CPU、耗电 | 图片、泄漏、后台任务 |
| 网络 | 成功率、P50/P95、流量、重试 | 弱网、切网、超时和重复提交 |
| 稳定性 | Crash-free、ANR、OOM | 原生和跨端错误统一关联 |
| 包体 | 下载、安装、增量更新体积 | 原生库、架构、资源和符号 |

指标要按平台、设备档位、系统和 App 版本分组。平均值会掩盖低端设备和 P95/P99 的真实问题。

## 启动优化

启动链路通常包括系统创建进程、原生初始化、跨端运行时启动、加载 Bundle/Dart/HTML、恢复状态、首屏请求和渲染。

- 只初始化首屏必需依赖，分析 SDK 的同步启动成本；
- 非关键监控、预取和插件延迟到首帧后；
- 首屏先使用本地最小数据，再增量刷新；
- 控制 JS Bundle、Dart snapshot、动态库和字体图片体积；
- 避免启动时串行等待多个可并行任务；
- 不用不可取消的全屏 Splash 掩盖真实耗时；
- 明确冷启动、热启动和从后台恢复，分别监控。

启动图到真实首屏的背景、状态栏和布局应连续，避免白屏和跳变。骨架屏只表达结构，不能代替错误、空数据和离线状态。

## 渲染与动画

60 Hz 屏幕一帧约 16.7 ms，120 Hz 约 8.3 ms，留给业务的实际预算更少。卡顿首先定位哪个线程超时，再处理根因。

- 大列表使用虚拟化/懒构建，item 高度尽可能稳定；
- 图片按显示尺寸解码，使用缩略图、缓存和占位；
- 减少同步布局测量、复杂阴影、过度模糊和大面积透明叠加；
- 动画使用 transform/opacity 或框架的 UI/Raster 线程能力；
- 手势更新不要每帧跨 Bridge 或触发全树状态更新；
- 避免在 render/build 中做排序、JSON 解析和网络副作用；
- 只在 Profile/Release 构建和真机上评价帧率。

虚拟化参数不是越激进越好：窗口小会出现白块，窗口大增加内存和渲染成本。应按 item 复杂度、滚动速度和设备档位测量。

## 内存与资源

常见泄漏来源包括未注销事件/通知、计时器、闭包持有页面、图片缓存无上限、WebView 未释放、原生模块回调和多媒体资源。

排查时反复进入/退出目标页面并记录 Heap/Native Memory 是否回落。区分真正泄漏、缓存保留和 GC 尚未触发；同时关注内存峰值，因为峰值可能直接导致系统杀进程。

图片内存近似由解码后像素决定，而不是压缩文件大小：宽 × 高 × 每像素字节数。一张体积很小的超高分辨率 JPEG 仍可能占用大量内存。

## 网络与离线

- 设置连接/读取/总超时和取消，页面离开后停止无意义请求；
- 只对安全或具有幂等键的请求重试，使用退避和随机抖动；
- 上传下载支持分片、断点续传、校验和后台恢复；
- 合并短时间重复请求，对 GET 进行合理缓存；
- 切换 Wi-Fi/蜂窝、VPN、代理和弱网时重新验证连接；
- 离线写入维护队列、顺序、幂等 ID、冲突与用户可见状态；
- `online` 只表示网络接口状态，不保证 DNS、网关或业务服务可用。

不要自动无限重试支付、下单等操作。客户端生成操作 ID，服务端以该 ID 幂等处理；超时后先查询最终状态，而不是盲目再次提交。

## 客户端安全边界

客户端运行在用户设备上，可被抓包、调试、反编译和修改。混淆、证书绑定、越狱检测只能提高成本，不能替代服务端身份认证、授权和数据校验。

### 数据与凭证

- 全链路 HTTPS，敏感接口的日志和错误信息做脱敏；
- 短期 Access Token 与可撤销 Refresh Token 分离；
- Token 放 Keychain/Keystore 等安全存储，不放 URL、普通日志或 Web localStorage；
- 生物识别只是访问本地密钥的门，服务端仍验证会话和业务授权；
- 本地数据库按敏感度决定是否加密，并保护加密密钥；
- 剪贴板、截图、系统备份和任务切换预览也可能泄漏数据。

### WebView 与 Bridge

- 只允许可信 HTTPS Origin，限制导航、弹窗、文件协议和混合内容；
- 关闭不必要的 JS、调试、文件访问和通用原生接口；
- Bridge 使用固定方法白名单、参数 schema、来源验证和权限模型；
- 外部页面用系统浏览器或隔离 WebView，不获得业务 Bridge；
- 把 XSS 当成原生权限提升风险，配合 CSP、输出编码和依赖审计。

### 供应链

移动 SDK 可能收集设备标识、位置和行为数据。引入前检查维护者、权限、网络域名、隐私条款、二进制架构和已知漏洞；维护 SBOM 和锁文件，持续升级原生及跨端运行时安全版本。

## 隐私合规

建立“数据类型 -> 收集目的 -> 触发页面 -> SDK/接口 -> 保存期限 -> 删除方式”的清单。实际行为、系统权限用途文案、应用内隐私政策和商店申报要一致。

- 非必要不收集，不用功能前不提前申请权限；
- 用户拒绝后提供合理降级，不以误导方式反复弹窗；
- 同意前限制非必要 SDK 初始化和数据上报；
- 支持查看、更正、导出、注销和删除；
- 区分开发、测试、生产数据，测试日志不含真实隐私数据；
- 版本升级新增数据用途时重新评估是否需要告知或同意。

## 移动端可访问性

跨端组件最终仍要映射为平台可访问语义。不要只做视觉上的按钮和输入框。

- 使用语义化 Button、Text、Heading、Input，或设置正确 role/label/state；
- 图标按钮提供可朗读名称，装饰图片对读屏隐藏；
- 状态变化、错误和加载结果用 live region/平台公告适度通知；
- 支持系统字体放大，文本不能被固定高度截断；
- 点击目标建议至少接近 44 × 44 iOS points / 48 × 48 Android dp；
- 颜色不是唯一信息，文本和关键控件满足对比度；
- 焦点顺序与视觉顺序一致，弹窗打开后聚焦并在关闭时恢复；
- 横竖屏、屏幕放大、Reduce Motion、深色和高对比模式均需测试。

手势操作应有可点击替代方案，例如侧滑删除同时提供菜单按钮。拖拽、验证码和超时流程也要有无障碍路径。

## 触摸、键盘与输入

触摸没有 hover，用户可能使用单手、手写笔、外接键盘或辅助开关。重要操作不能依赖悬停或复杂多指手势。

- 避免边缘手势与系统返回/主页手势冲突；
- 防止双击导致重复提交，禁用态与服务端幂等共同处理；
- 输入框设置合适键盘类型、自动填充、返回键行为；
- 键盘弹起时保证当前输入项和提交按钮可见；
- 表单校验说明具体问题并将焦点移到合理位置；
- 桌面/平板形态支持 Tab、方向键、Esc 和快捷键。

## 可观测性

统一一次用户操作的前端事件、网络请求、Bridge/原生调用和服务端 trace，至少携带匿名会话、平台、App 版本、构建号和 runtimeVersion。

监控应包括：

- JS/Dart 错误与 Source Map；
- iOS dSYM、Android mapping/native symbols；
- Native Crash、ANR、OOM 和被系统终止；
- 启动、慢帧、内存、耗电和网络成功率；
- 权限拒绝、Deep Link、Push、Bridge、OTA 和更新失败；
- 版本分布、设备档位和灰度批次。

日志禁止包含 Token、密码、完整手机号、身份证、精确位置等。采样和保留期既要控制成本，也要满足隐私约束。

## 发布前检查清单

- Release 构建在主要真机完成核心流程；
- 弱网、断网、切网、后台恢复和系统杀进程可恢复；
- 权限允许、拒绝、永久拒绝均有路径；
- Deep Link、Push、支付回跳和第三方登录覆盖冷/热启动；
- 低端设备启动、帧率、内存和包体达到预算；
- 字体放大、读屏、横屏、深色和安全区域可用；
- 隐私声明、权限用途和 SDK 行为一致；
- 崩溃符号、Source Map、版本和监控环境正确；
- 灰度、Feature Flag、服务端兼容和紧急降级已演练；
- 签名、商店元数据、审核账号和更新说明完整。
