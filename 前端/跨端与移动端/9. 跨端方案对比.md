# 跨端方案对比

| 方案 | UI 渲染 | 代码复用 | 性能/体验 | 适合 |
| --- | --- | --- | --- | --- |
| 响应式 Web/PWA | DOM | 最高 | 浏览器能力边界 | 内容、表单、轻应用 |
| Capacitor/Hybrid | WebView | 很高 | 受 WebView 和 Bridge 限制 | Web 为主、少量原生能力 |
| React Native/Expo | 原生 View | JS/React 逻辑高 | 接近原生 | React 团队移动 App |
| Flutter | 自绘 | Dart 全端 | 一致性与动画强 | 多端统一体验 |
| Taro/uni-app | 编译到各端 | 多小程序高 | 受平台交集限制 | 多小程序/H5 |
| 原生小程序 | 平台组件 | 单平台 | 平台适配最好 | 深度微信/支付宝能力 |
| Electron | Chromium | Web 高 | 一致、资源占用较高 | 复杂桌面应用 |
| Tauri | 系统 WebView | Web 高 | 轻量、平台差异 | 轻桌面与 Rust 团队 |

## 决策问题

1. 目标是 Web、移动、小程序还是桌面？
2. UI/动画和硬件能力要求多高？
3. 是否需要 SEO、离线、后台和 Push？
4. 团队掌握 React/Vue/Dart/Rust/原生到什么程度？
5. 应用商店、热更新和隐私政策有何限制？
6. 平台差异是否超过共享代码收益？

## 能力维度对比

| 维度 | Web/PWA | Hybrid | RN/Expo | Flutter | Taro/uni-app | 原生 |
| --- | --- | --- | --- | --- | --- | --- |
| SEO/URL | 最强 | 容器内无 SEO | 不适用 | Flutter Web 较弱 | H5 端视实现 | 不适用 |
| 原生 UI 习惯 | 浏览器体验 | Web 体验 | 较好 | 需主动适配 | 受目标端组件影响 | 最好 |
| 复杂动画 | 中等 | 受 WebView 限制 | 较强 | 很强 | 受平台限制 | 最强 |
| 硬件/后台 | 有限 | 依赖插件 | 原生模块 | 插件/平台通道 | 平台 API 交集 | 完整 |
| Web 代码复用 | 原生 | 最高 | 逻辑可复用，UI 少 | 很少 | H5/小程序较高 | 很少 |
| OTA | Web 发布 | Web 资源可更新 | JS/资源受策略限制 | 一般走商店 | 小程序平台发布 | 走商店 |
| 团队门槛 | Web | Web + 少量原生 | React + 原生工程 | Dart + 原生工程 | React/Vue + 平台规则 | Swift/Kotlin |

## 典型场景

- 新闻、营销、文档、搜索入口：优先响应式 Web，按需增强 PWA；
- 企业表单、内部系统已有 Web 且只需相机/扫码：评估 Capacitor；
- 消费级 App、React 团队、需要原生导航与交互：评估 React Native/Expo；
- 高一致性 UI、复杂自绘动画、多移动端同步交付：评估 Flutter；
- 电商活动同时覆盖微信/支付宝/抖音小程序：评估 Taro/uni-app；
- 深度音视频、系统服务或极致平台体验：原生或原生主导的混合架构；
- IDE、协作工具等复杂桌面 Web 产品：Electron；轻量桌面工具可评估 Tauri。

## PoC 验证清单

不要只实现首页。使用真实依赖做一个纵向切片：登录、分页列表、复杂表单、相机/文件、Deep Link、Push、离线恢复、埋点、崩溃监控和一次发布构建。

记录首屏、包体、内存、慢帧、跨端差异代码量、原生插件数量、CI 时间和修复一个原生问题所需成本。PoC 的目标是暴露风险，而不是展示最顺利的 Demo。

## 建议

内容和轻交互优先 Web/PWA；已有 Web 快速封装选 Capacitor；React 团队原生体验选 RN/Expo；强视觉一致性选 Flutter；多小程序选 Taro/uni-app；桌面按 Chromium 一致性与资源成本在 Electron/Tauri 间选择。

不要只比较 Demo 开发速度。用登录、列表、相机、推送、Deep Link、离线、升级和崩溃监控做 PoC。
