# PWA

PWA 使用 Web App Manifest、Service Worker、安全上下文和浏览器能力，让 Web 应用具备安装、离线、推送和类应用体验。

## Manifest

```json
{
  "name": "Tasks",
  "short_name": "Tasks",
  "start_url": "/?source=pwa",
  "display": "standalone",
  "icons": [{ "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" }],
  "theme_color": "#ffffff",
  "background_color": "#ffffff"
}
```

安装条件和 UI 由浏览器/平台决定，不能强制弹出。提供正确图标、名称、scope、启动 URL 和主题。

## Service Worker

- 静态哈希资源 Cache First；
- 内容 Stale While Revalidate；
- 强一致 API Network Only/First；
- 离线页面和请求失败回退；
- 版本化缓存、新旧 Worker 兼容和更新提示。

最小离线回退示例：

```js
const CACHE = 'app-shell-v1'
const SHELL = ['/', '/offline.html', '/assets/app.css', '/assets/app.js']

self.addEventListener('install', (event) => {
  event.waitUntil(caches.open(CACHE).then((cache) => cache.addAll(SHELL)))
})

self.addEventListener('fetch', (event) => {
  if (event.request.mode !== 'navigate') return
  event.respondWith(fetch(event.request).catch(() => caches.match('/offline.html')))
})
```

生产项目通常使用 Workbox/Vite PWA 等生成和管理 precache manifest，避免手写资源版本遗漏。Service Worker 只能在 HTTPS（localhost 例外）和自己的 scope 内拦截请求。

## 更新生命周期

新 Worker 下载后通常进入 waiting，旧页面仍由旧 Worker 控制。直接 `skipWaiting()` 可能让旧 HTML 与新资源混用；更稳妥的方式是检测 waiting、提示用户刷新，并确保部署期间新旧资源都可访问。

清理旧缓存应放在 activate，但不能误删其他业务或旧页面仍在使用的缓存。HTML 通常不做永久 Cache First，否则新版本很难触达。

## 离线数据

IndexedDB 保存本地副本和待同步操作。写操作生成幂等 ID，恢复网络后重放；处理重复、冲突、顺序和用户退出后的数据清理。

离线不是简单“缓存接口”：需要明确本地数据模型、同步方向、冲突策略、删除墓碑、时钟和重试上限。多人编辑可按业务使用 last-write-wins、版本号/ETag、操作日志或 CRDT，但必须让用户看到未同步和冲突状态。

## Push 与 Background

通知需要用户授权和真实价值，不在首屏立即索取。Push Subscription 在服务端与用户绑定并可撤销。Background Sync/Periodic Sync 支持和配额有限，不能作为可靠任务系统。

## 平台差异

iOS、Android、桌面浏览器对安装、Push、后台、Badge、文件和分享 API 支持不同。使用渐进增强和能力检测，不把 PWA 当完全一致的原生替代。

```js
if ('share' in navigator && navigator.canShare?.({ url: location.href })) {
  await navigator.share({ title: document.title, url: location.href })
} else {
  await navigator.clipboard.writeText(location.href)
}
```

能力检测也不代表授权或调用一定成功，仍要捕获拒绝、系统限制和用户取消。

## 安全与存储

- Service Worker 权限很高，XSS 可能污染缓存或注册恶意 Worker，必须配合 CSP、依赖治理和输出编码；
- Cache Storage/IndexedDB 不是加密保险箱，不保存长期高价值密钥；
- 登录退出时清理用户专属缓存，本地离线数据要区分账户和租户；
- 缓存响应前校验请求身份，不能把 A 用户接口数据返回给 B 用户；
- 浏览器可能因存储压力清理数据，关键数据仍需服务端确认。

## 测试

测试首次安装、离线启动、旧缓存、Worker 等待/激活、登录退出、存储清理和网络抖动。Lighthouse 只能检查基础项，不能证明离线数据正确。
