# iOS 与 Android 平台基础

跨端框架隐藏了部分平台差异，但不会消除操作系统、工程、签名、生命周期和商店规则。能够定位跨端问题，至少要理解 iOS 与 Android 的共同边界。

## 平台与语言

| 维度 | iOS | Android |
| --- | --- | --- |
| 主要语言 | Swift、Objective-C | Kotlin、Java |
| UI | SwiftUI、UIKit | Jetpack Compose、View |
| IDE | Xcode | Android Studio |
| 构建 | Xcode Build、Swift Package Manager/CocoaPods | Gradle、Android Gradle Plugin |
| 安装产物 | `.app`、`.ipa` | `.apk`、`.aab` |
| 应用商店 | App Store/TestFlight | Google Play/各地区渠道 |
| 安全存储 | Keychain | Android Keystore、加密存储 |

跨端项目仍然包含原生工程。依赖升级可能要求新的 Xcode、iOS Deployment Target、Android compile/target SDK、Gradle、Kotlin 或 JDK 版本，因此要把整套工具链锁定并记录。

## 应用组成

### iOS

- App/Scene 描述应用和窗口生命周期；
- `Info.plist` 声明权限用途、URL Scheme 和应用配置；
- Entitlements 控制 Push、Associated Domains、Keychain Group 等能力；
- Bundle 存放只读资源，Documents/Library/tmp 用于不同生命周期的数据；
- Extension 可实现 Widget、Share Extension、Notification Service 等独立目标。

### Android

- Activity 表示带 UI 的入口，Fragment/Compose 组织页面；
- Service 承担受约束的后台工作，BroadcastReceiver 接收系统/应用广播；
- ContentProvider 暴露结构化数据，通常由特定需求或库使用；
- `AndroidManifest.xml` 声明组件、权限、Intent Filter 和元数据；
- Application 进程可能承载多个组件，但不保证一直存活。

跨端的“页面”不一定等于一个 Activity/ViewController。多数框架以单个原生容器承载自己的路由栈，因此系统返回、状态恢复和多窗口需要额外衔接。

## 生命周期与状态恢复

应用可能经历前台活跃、暂时非活跃、后台、进程被回收和冷启动。系统可以在没有业务终止回调的情况下杀死进程，所以不能只在“退出”时保存数据。

需要分别处理：

- 冷启动：进程不存在，由图标、通知或 Deep Link 启动；
- 热启动/恢复：进程还在，从后台回到前台；
- 页面隐藏：页面不再可见，但应用可能仍在前台；
- 内存警告：释放可重建的图片、缓存和大对象；
- 进程重建：从持久化数据和路由输入恢复最小可用状态；
- 多窗口/画中画：可见性不再是简单的单一布尔值。

网络请求、相机、定位、音视频和订阅应绑定到正确生命周期。界面销毁后异步回调不能继续更新已释放对象。

## 线程与并发

UI 只能在主线程更新。网络、数据库、图片解码和计算任务使用异步 API 或后台线程，完成后切回主线程提交 UI。

- iOS 常用 async/await、Task、Actor、GCD；
- Android 常用 Kotlin Coroutines、Flow、Dispatcher；
- RN 还要区分 JS 线程、UI 线程和原生模块线程；
- Flutter 常见 UI Isolate、Raster 线程与原生平台线程。

异步不等于不会阻塞：在主线程执行同步 JSON 解析、图片处理或大循环仍会掉帧。任务还应支持取消、超时和生命周期结束后的结果丢弃。

## 权限与隐私

权限应在用户触发相关功能时申请，并在申请前说明用途。流程至少覆盖：首次询问、允许、拒绝、永久拒绝/不再询问、系统限制和设置中撤销。

```text
检查当前状态
  -> 已授权：执行业务
  -> 可询问：展示上下文说明，再调用系统弹窗
  -> 已拒绝但可再问：提供降级和再次触发入口
  -> 永久拒绝/受限：说明原因，按需引导系统设置
```

`Info.plist` 用途描述、Android Manifest/运行时权限、商店隐私表单和第三方 SDK 实际采集行为必须一致。权限获批也不代表可以无限收集，仍要遵守最小化、目的限制和保留期限。

## 文件与安全存储

- Bundle/Assets 内资源通常只读；
- Cache 可被系统清理，不能保存唯一副本；
- Documents/持久目录用于用户数据，并评估是否参与云备份；
- 临时文件用完及时删除；
- Token、私钥和高价值标识使用 Keychain/Keystore，不放普通偏好设置；
- 数据库和文件要按账户隔离，退出登录时清理或重新加密；
- 不信任外部传入的文件名、MIME、URI 和路径，防止目录穿越及恶意内容。

移动客户端无法永久保密内置密钥。服务端密钥、支付私钥和第三方 App Secret 不能打进安装包；可提取的 API Key 只能依赖服务端限制、签名校验或平台绑定降低滥用。

## Deep Link 与 Universal/App Link

自定义 URL Scheme 简单但可能被其他应用抢占。生产登录、支付回跳优先使用经过域名关联验证的 Universal Links（iOS）和 App Links（Android）。

Deep Link 处理要覆盖：

1. 应用未安装时的 Web/商店回退；
2. 冷启动和应用运行中两条入口；
3. 登录前保存目标，登录后恢复；
4. 参数白名单、长度和类型校验；
5. 未知路由与旧版本客户端的兼容；
6. 防止外部链接直接触发转账、删除等敏感动作。

## Push 通知

APNs/FCM Token 会变化，不应当作用户 ID。客户端把 Token、设备、环境和账户关系上报服务端，并在刷新、登出时更新。

通知点击只是一种外部路由输入；payload 不应包含敏感数据。前台、后台、被杀进程的处理路径不同，静默推送和后台执行都受系统策略限制，不能保证准时或必达。

## 后台任务

移动系统严格限制后台耗电。持续定位、音频、蓝牙等只有特定合法场景可长期运行，并伴随权限和明显系统提示。普通同步任务使用系统调度能力，但执行时间由系统决定。

不要用无限计时器维持在线。重要任务由服务端负责，客户端恢复时对账；上传下载使用平台支持的后台传输能力并设计幂等、续传和过期策略。

## 构建、签名与环境

开发、测试、预生产和生产至少区分：

- Bundle ID/Application ID；
- API Base URL、Deep Link 域名；
- Push 环境和证书；
- OAuth Client、地图等平台配置；
- 图标、应用名和日志采样；
- 签名证书、Provisioning Profile/Keystore。

环境变量不是秘密，编译进客户端后都可提取。签名密钥放在受保护的 CI Secret/签名服务中，限制访问并制定轮换和灾备流程。

## 商店发布

发布前除功能测试外，还要检查版本号、截图文案、隐私政策、数据安全表、年龄分级、出口合规、第三方登录要求、账号注销和审核账号。

采用 TestFlight/Internal Testing、灰度比例和监控逐步放量。商店回滚通常是再发布一个更高版本，不像 Web 能立即撤回，因此服务端 Feature Flag、兼容旧客户端和紧急降级尤其重要。

## 调试排查顺序

1. 确认是 JS/Dart、框架、原生插件还是操作系统层问题；
2. 记录设备、系统、应用版本、构建环境和操作路径；
3. 对比 Debug/Release、模拟器/真机、iOS/Android；
4. 查看 JS 日志、原生日志、网络、崩溃栈和性能时间线；
5. 最小化为单一插件或页面，排除业务状态；
6. 检查权限、签名、Manifest/Entitlement 和版本兼容；
7. 用真实发布构建复现，避免只在开发容器中验证。
