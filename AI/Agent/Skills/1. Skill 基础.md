# 什么是 Agent Skills？

Agent Skills 是一种轻量级、开放式的格式，可以通过专门的知识和工作流程来扩展 AI 代理的能力。

从根本上说，技能本质上是一个包含 `SKILL.md` 文件的文件夹。这个文件中包含了元数据（至少包括 `name` 和 `description` 信息），以及指导代理如何执行特定任务的指令。此外，技能还可以包含脚本、参考资料、模板以及其他资源。

```
my-skill/
├── SKILL.md          # 必须: 元数据 + 指示
├── scripts/          # 可选: 可执行的代码
├── references/       # 可选: 文档
├── assets/           # 可选: 模版, 资源
└── ...               # 任何其他文件或目录
```

---
# 为什么选择 Agent Skills？

Agent 的能力日益增强，但他们往往缺乏可靠执行实际任务所需的背景信息。而 Skills 则***通过将程序性知识以及针对公司、团队和用户的具体上下文整合到可移植且可版本控制的文件夹中***，从而解决了这一问题。这样，代理角色就可以根据需求加载相应的信息了。

- **领域专业知识**：收集各种专业知识——从法律审核流程到数据分析流程，再到演示文稿格式设计等各个方面——将这些知识作为可复用的指导和资源。
- **可重复执行的工作流程**：将多步骤任务转化为标准化、可审计的操作流程。
- **交叉产品复用**：只需构建一次技能，然后可以在任何兼容该技能的代理中使用它。

---
# Agent Skills 是如何运作的？

Agent 通过**渐进式发现**的方式在三个阶段中掌握各种 Skills：

1. **发现**：在启动阶段，Agent 只加载了每个可用 Skills 的名称和描述，这样的信息足够判断这些技能是否有可能与当前需求相关。
2. **激活过程**：当任务与某项 Skill 的描述相匹配时，Agent 会完整读取相关的 `SKILL.md` 指令信息，并将其纳入上下文中进行处理。
3. **执行**：Agent 按照指令进行操作，根据需要执行预编译的代码或加载指定的文件。

完整的操作说明只有在需要时才会被加载，这样 Agent 只需占用少量的内存空间即可掌握多种 Skills。

# 规范说明

## 目录结构

Skill 实际上是一个目录，其中至少包含一个 `SKILL.md` 文件。

```
skill-name/
├── SKILL.md          # Required: metadata + instructions
├── scripts/          # Optional: executable code
├── references/       # Optional: documentation
├── assets/           # Optional: templates, resources
└── ...               # Any additional files or directories
```

---
## `SKILL.md` 格式

`SKILL.md` 文件必须以 YAML 格式的元数据开头，其后才是 Markdown 格式的内容。

###  前置内容

| 字段              | 是否必须 | 规则                                     |
| --------------- | ---- | -------------------------------------- |
| `name`          | 是    | 最多 64 个字符。只能包含小写字母、数字和连字符。开头和结尾不能是连字符。 |
| `description`   | 是    | 最多 1024 个字符。不能为空。需描述该技能的用途以及使用时机。      |
| `license`       | 否    | 许可证名称或对相关许可文件的引用。                      |
| `compatibility` | 否    | 最多 500 个字符。用于说明环境要求（目标产品、系统组件、网络连接等）。  |
| `metadata`      | 否    | 用于存储额外元数据的任意键值对映射。                     |
| `allowed-tools` | 否    | 以空格分隔的、该技能可以使用的预先批准过的工具列表。（实验性功能）      |
**最简单的示例：**
 
 ```SKILL.md
---
name: skill-name
description: A description of what this skill does and when to use it.
---
 ```

**包含可选字段的示例：**

```SKILL.md
---
name: pdf-processing
description: Extract PDF text, fill forms, merge files. Use when handling PDFs.
license: Apache-2.0
metadata:
  author: example-org
  version: "1.0"
---
```

#### `name` 字段

必须的 `name` 字段：

 - 必须包含 1 到 64 个字符。
 - 只能包含 Unicode 小写字母数字字符（`a-z`, `0-9`）和连字符（`-`）。
 - 不得以连字符开头或结尾（`-`）。
 - 不得包含连续的连字符（`--`）。
 - 必须与父目录的名称相同。

有效示例：

```SKILL.md
name: pdf-processing
```

```SKILL.md
name: data-analysis
```

```SKILL.md
name: code-review
```

**无效的示例：**

```SKILL.md
name: PDF-Processing # 不支持大写字符
```

```SKILL.md
name: -pdf # 不能以连字符开头
```

```SKILL.md
name: code-review # 不支持连续的连字符
```

#### `description` 字段

必须的 `description` 字段：

- 必须包含 1 到 1024 个字符。
- 应同时说明该技能的用途以及何时使用它。
- 应包含一些具体的关键词，以便 Agents 能够准确识别相关任务。

**好例子：**

```SKILL.md
description: Extracts text and tables from PDF files, fills PDF forms, and merges multiple PDFs. Use when working with PDF documents or when the user mentions PDFs, forms, or document extraction.
```

**坏例子：**

```SKILL.md
description: Helps with PDFs.
```

#### `license` 字段

可选的 `license` 字段：

- 指定应用于该 Skill 的许可证类型。
- 我们建议将其保持简短（可以是许可证的名称，也可以是捆绑式许可证文件的名称）。

**示例：**

```SKILL.md
license: Proprietary. LICENSE.txt has complete terms
```

#### `compatibility` 字段

可选的 `compatibility` 字段：

- 如果提供该内容，其长度必须在 1 到 500 个字符之间。
- 只有当你的 Skill 有特定的环境要求时，才应将其包含在内。
- 可以说明所期望的产品、所需的系统组件、网络接入需求等信息。

**示例：**

```SKILL.md
compatibility: Designed for Claude Code (or similar products)
```

```SKILL.md
compatibility: Requires git, docker, jq, and access to the internet
```

```SKILL.md
compatibility: Requires Python 3.14+ and uv
```

> 大多数 Skill 都不需要 `compatibility` 字段。

#### `metadata` 字段

可选的 `metadata` 字段：

- 一个字符串键映射到字符串值的映射表。
- 客户端可以利用此功能来存储那些未被 Agent Skills 规范所定义的额外属性。
- 我们建议将密钥名称设置得尽可能独特，以避免意外冲突。

**示例：**

```SKILL.md
metadata:
  author: example-org
  version: "1.0"
```

#### `allowed-tools` 字段

可选的 `allowed-tools` 字段：

- 一组经过预先批准、可以运行的工具，这些工具以空格分隔而成。
- **实验性功能**。不同智能体实现方式对这一功能的支持程度可能有所不同。

**示例：**

```SKILL.md
allowed-tools: Bash(git:*) Bash(jq:*) Read
```

### 正文内容

在前置内容之后的 Markdown 文本中，可以编写与 Skill 相关的操作指南。没有格式上的限制。只要能帮助智能体更有效地完成任务，就可以随意编写内容。

推荐阅读部分：

- 分步操作指南
- 输入和输出的示例
- 常见的边缘情况

请注意，一旦决定启用某项 Skill，该 Agent 就会加载整个文件。建议将较长的 `SKILL.md` 内容拆分成多个单独的文件来处理。

---
## 可选的目录/文件夹

### `scripts/`

包含 Agent 可以运行的可执行代码。脚本应满足以下要求：

- 要么做到自给自足，要么明确记录所有依赖关系。
- 请包含有用的错误信息。
- 妥善处理各种边缘情况。

所支持的语言取决于具体的 Agent 实现方式。常见的编程语言包括 Python、Bash 和 JavaScript。

### `references/`

其中包含 Agent 在需要时可以查阅的额外文档：

- `REFERENCE.md` - 详细技术参考资料
- `FORMS.md` - 表单模板或结构化数据格式
- 特定于领域的文件（`finance.md` 、 `legal.md` 等）

请确保各个[参考文件](https://agentskills.io/specification#file-references)的规模适中。Agents 会根据需要来加载这些文件，因此，文件规模越小意味着使用更少的上下文。

### `assets/`

包含静态资源：

- 模板（文档模板, 配置模板）
- 图片（图表, 示例）
- 数据文件（查询表, 数据结构）

---
# 渐进式加载

Agents 会渐进式地加载各种 Skills，只有在任务需要时才会加载更详细的细节信息。Skills 的设计应充分利用这一机制。

1. **元数据**（约 100 个标记）：所有 Skills 在启动时都会加载 `name` 和 `description` 字段。
2. **使用说明**（建议字符数少于 5000）：该 Skill 被激活时， `SKILL.md` 的全部内容都会被加载出来。
3. **所需资源**：只有在需要时，才会加载相关文件（例如 `scripts/` 、 `references/` 或 `assets/` 中的文件）。

请确保主文件 `SKILL.md` 的行数不超过 500 行。将详细的参考资料另存为单独的文件。

---
# 文件参考

在 Skill 中引用其他文件时，请使用从 Skill 根目录开始的相对路径：

```SKILL.md
See [the reference guide](references/REFERENCE.md) for details.

Run the extraction script:
scripts/extract.py
```

请确保文件引用层次不超过 `SKILL.md` 的那一层。避免使用过于复杂的嵌套引用结构。

---
# 验证

请使用 [skills-ref](https://github.com/agentskills/agentskills/tree/main/skills-ref) 来验证自己的 Skill：

```SKILL.md
skills-ref validate ./my-skill
```

该检查用于确认您的 `SKILL.md` 前置信息是否有效，且符合所有的命名规范。
