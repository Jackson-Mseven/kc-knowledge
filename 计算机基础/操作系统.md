# 操作系统

操作系统（Operating System，OS）是管理计算机硬件并向应用程序提供统一抽象和服务的软件。它的核心目标是：**让多个程序安全、高效、公平地共享 CPU、内存、设备与文件**。

## 一、核心职责与运行模式

### 操作系统做什么

- **处理器管理**：创建、调度和终止进程/线程，让 CPU 在多个任务间切换。
- **内存管理**：分配、回收与保护内存，并借助虚拟内存扩展可用地址空间。
- **文件与设备管理**：用文件系统统一组织数据，用驱动程序管理磁盘、网络、键盘等 I/O 设备。
- **安全与隔离**：区分用户权限，隔离进程地址空间，限制程序直接操作硬件。
- **系统调用接口**：应用通过 `open`、`read`、`write`、`fork`、`exec`、`socket` 等接口请求内核服务。

### 用户态与内核态

| 模式 | 权限与特点 | 典型代码 |
| --- | --- | --- |
| 用户态（User Mode） | 权限受限，不能直接访问硬件或任意内存 | 浏览器、Node.js、业务进程 |
| 内核态（Kernel Mode） | 可执行特权指令、访问设备和内核内存 | 调度器、内存管理、驱动程序 |

- **系统调用**是用户态主动切换到内核态以请求服务的受控入口；完成后会返回用户态。
- **中断**通常由外部设备或时钟触发；**异常**由当前指令执行引起，例如缺页、除零或非法访问。三者都可能使 CPU 进入内核处理程序。
- 用户态与内核态切换有成本，因此高频、细粒度系统调用可能影响吞吐；但不能为了“快”而绕过隔离和权限控制。

## 二、进程、线程与上下文切换

### 进程与线程

| 对比项 | 进程（Process） | 线程（Thread） |
| --- | --- | --- |
| 定义 | 资源分配和隔离的基本单位 | CPU 调度的基本单位（常见实现） |
| 地址空间 | 每个进程独立 | 同进程线程共享代码、堆、全局数据和文件描述符 |
| 私有资源 | 虚拟地址空间、进程信息等 | 栈、寄存器、程序计数器、线程局部存储 |
| 创建/切换成本 | 通常较高 | 通常较低，但仍有调度和同步成本 |
| 主要风险 | 通信成本更高 | 共享内存带来数据竞争 |

- 多进程隔离性好，单个进程崩溃通常不直接破坏其他进程；多线程共享数据方便，但必须处理同步。
- 一个进程至少有一个线程。多核 CPU 可以真正并行执行不同线程；单核上的“同时执行”主要来自快速切换。
- 协程是用户态的轻量级并发抽象，调度通常由运行时负责；它不等同于 OS 线程，但可在少量线程上管理大量任务。

### 进程状态

常见状态：

- **新建（New）**：正在创建；
- **就绪（Ready）**：已具备运行条件，等待 CPU；
- **运行（Running）**：正在使用 CPU；
- **阻塞/等待（Blocked/Waiting）**：等待 I/O、锁或事件，暂时不能运行；
- **终止（Terminated）**：执行结束，资源待回收。

就绪不等于运行：就绪任务只是在等待调度器分配 CPU。I/O 完成后，阻塞任务通常转回就绪队列，而不是直接占用 CPU。

### 上下文切换

上下文切换是 CPU 从一个任务切换到另一个任务时，保存当前执行现场并恢复下一个任务现场的过程，可能包括寄存器、程序计数器、栈指针、页表相关状态等。它会引入内核调度开销，并可能导致 CPU 缓存、TLB 失效或命中率下降。

常见触发原因：时间片用完、更高优先级任务到来、任务主动让出 CPU、等待 I/O/锁、发生中断或异常。线程切换通常比进程切换轻，但不应忽视其成本。

## 三、CPU 调度

调度指标包括 CPU 利用率、吞吐量、周转时间、等待时间、响应时间和公平性。不同场景取舍不同：交互程序重视响应，批处理任务更关心吞吐和周转。

| 算法 | 核心思想 | 优点 | 局限 |
| --- | --- | --- | --- |
| FCFS 先来先服务 | 按到达顺序运行 | 简单、公平直观 | 长任务会拖慢短任务（护航效应） |
| SJF 最短作业优先 | 优先执行预计最短的任务 | 平均等待时间较低 | 任务时长难准确预测，长任务可能饥饿 |
| 优先级调度 | 优先运行更重要的任务 | 可满足业务优先级 | 低优先级可能饥饿，可用老化解决 |
| 时间片轮转 RR | 每个就绪任务轮流运行一个时间片 | 交互性、公平性较好 | 时间片过小切换频繁，过大退化为 FCFS |
| 多级反馈队列 MLFQ | 多个优先级队列，按行为动态调整 | 兼顾交互与批处理 | 实现和参数更复杂 |

- **抢占式调度**可在任务未结束时剥夺 CPU，响应更快；**非抢占式调度**通常等任务主动放弃或结束。
- **饥饿**是任务长期得不到资源；**老化（aging）**会随等待时间提高优先级，缓解饥饿。

## 四、并发、同步与死锁

### 临界区与数据竞争

临界区是访问共享资源的代码段。两个或多个线程未正确同步地同时读写同一数据，且至少一个是写操作时，会产生**数据竞争**，结果依赖不可预测的执行时序。

正确的同步机制应满足：互斥（同一时刻最多一个执行者进入临界区）、进展（没有人占用时应能选择进入者）和有限等待（不能无限期等待）。

### 常用同步原语

| 原语 | 作用 | 典型使用场景 |
| --- | --- | --- |
| 互斥锁 Mutex | 同一时刻仅一个线程进入临界区 | 保护共享对象 |
| 自旋锁 Spinlock | 获取不到锁时忙等 | 临界区极短、不可睡眠的低层场景 |
| 信号量 Semaphore | 计数型资源许可或通知 | 连接池、生产者-消费者 |
| 读写锁 RWLock | 多个读者可并发，写者独占 | 读多写少的数据 |
| 条件变量 Condition Variable | 等待某个条件成立 | 队列为空/已满时的协作 |
| 原子操作 CAS | 无锁地比较并更新值 | 计数器、无锁数据结构基础 |

- 锁应只覆盖必要的临界区；锁粒度过大降低并发，过小又增加复杂度和死锁风险。
- 条件变量必须与锁和循环条件检查配合使用，防止虚假唤醒或竞争条件。
- `volatile` 通常不能替代锁或原子操作：它不保证复合操作的原子性，也不提供完整的线程同步语义。

### 死锁

死锁是多个执行单元互相等待对方持有的资源，导致都无法继续。经典必要条件（同时满足才可能死锁）：

1. **互斥**：资源一次只能被一个执行单元占有；
2. **占有并等待**：已持有资源时继续等待其他资源；
3. **不可抢占**：资源不能被强制夺走；
4. **循环等待**：存在资源等待环。

常用处理方式：

- 预防：统一加锁顺序、一次申请全部资源、使用可抢占资源设计；
- 避免：在分配前判断是否仍处于安全状态，例如银行家算法；
- 检测与恢复：发现等待图存在环后终止任务或回滚、释放资源；
- 工程实践：锁超时、`tryLock`、缩短锁持有时间、避免在持锁时调用外部/阻塞代码。

## 五、内存管理与虚拟内存

### 地址空间与分页

每个进程看到的是独立的**虚拟地址空间**。MMU（内存管理单元）使用页表将虚拟地址映射为物理地址；内存以固定大小的页（page）管理，物理内存中的对应单元称为页框（frame）。

- 分页避免了连续内存分配导致的大量外部碎片，便于按页换入换出；代价是页表存储和地址翻译开销。
- TLB（快表）缓存近期页表映射，加速虚拟地址到物理地址的转换。上下文切换或映射变更可能影响 TLB 命中率。
- **内部碎片**来自已分配块中未使用的空间；**外部碎片**来自空闲空间不连续，难以满足大块连续分配。

### 虚拟内存、缺页与换页

虚拟内存让进程可使用大于物理内存的地址空间，并通过按需分页只将实际访问的页面加载进内存。

1. CPU 访问的虚拟页不在内存，触发**缺页异常**；
2. 内核检查访问是否合法；非法则终止进程或发送异常信号；
3. 合法则从磁盘/交换区读取页面，必要时按页面置换算法淘汰其他页；
4. 更新页表后重新执行触发缺页的指令。

常见页面置换思想：OPT（理论最优，淘汰最晚再使用的页）、FIFO、LRU（淘汰最久未使用页）、Clock（近似 LRU）。当系统频繁换入换出页面、CPU 大量等待磁盘时称为**抖动（thrashing）**，通常需降低并发度、增加内存或改善工作集管理。

### 堆、栈与内存泄漏

| 区域 | 常见用途 | 生命周期/特点 |
| --- | --- | --- |
| 栈（Stack） | 函数调用帧、局部变量 | 自动分配回收，空间通常较小 |
| 堆（Heap） | 动态分配对象 | 显式释放或由 GC 回收，管理较灵活 |
| 代码段/只读数据 | 指令、常量 | 通常可共享、受保护 |
| 全局/静态区 | 全局变量、静态变量 | 进程生命周期内存在 |

内存泄漏指不再需要的内存仍被程序持有、无法释放或回收。GC 语言也可能泄漏，例如全局缓存无限增长、事件监听器未移除、闭包意外引用大对象。内存溢出（OOM）则是申请内存超过可用限制，二者相关但不是同一概念。

## 六、文件系统与 I/O

### 文件与文件描述符

文件系统以目录和文件组织持久化数据，负责命名、权限、空间分配和元数据管理。Unix/Linux 中，文件描述符（FD）是进程访问已打开文件、套接字或管道等 I/O 对象的非负整数句柄；标准输入、输出、错误通常为 `0`、`1`、`2`。

- `open` 创建或获取 FD，`read`/`write` 读写，`close` 释放。未关闭 FD 会造成描述符泄漏，进程可能触及 `ulimit` 限制。
- inode 通常存储文件元数据和数据块索引，目录本质上维护文件名到 inode 的映射。具体实现随文件系统不同而变化。
- 文件删除通常是移除目录项、减少链接计数；若仍有进程打开该文件，磁盘空间会在最后一个引用关闭后才真正释放。

### 缓冲与 I/O 模型

- **阻塞 I/O**：调用线程等待直到数据就绪或操作完成，编程简单但线程可能被占用。
- **非阻塞 I/O**：立即返回，未就绪时由调用方稍后重试。
- **I/O 多路复用**：一个线程通过 `select`、`poll`、`epoll`、`kqueue` 等监视多个 FD 的就绪事件，适合大量连接。
- **异步 I/O**：提交操作后由内核在完成时通知应用；它与“非阻塞”相关但概念不同，具体语义取决于平台接口。

`select` 有 FD 数量限制且每次需遍历集合；`poll` 改善表示方式但仍要线性扫描；`epoll`（Linux）通过内核维护关注集合并返回活跃事件，适合高并发连接。它们解决的是 I/O 等待效率，不会自动消除业务计算、锁竞争或下游依赖造成的瓶颈。

### 缓存与写入一致性

操作系统会使用页缓存（page cache）缓存文件数据，读写并不一定立刻触盘。`fsync` 等操作可请求将已修改数据同步到稳定存储，但具体持久化保证还受文件系统、磁盘缓存和硬件配置影响。数据库等对一致性敏感的软件会在日志、刷盘顺序和恢复流程上额外设计。

## 七、常用 Linux 观察命令

| 命令 | 常见用途 |
| --- | --- |
| `ps aux`、`top`、`htop` | 查看进程、CPU、内存与负载 |
| `free -h`、`vmstat` | 查看内存、交换分区和系统活动 |
| `df -h`、`du -sh` | 查看文件系统容量、目录占用 |
| `lsof -p <pid>`、`lsof -i` | 查看进程打开文件、网络连接 |
| `ss -lntp` | 查看监听端口与关联进程 |
| `pidstat`、`iostat` | 查看进程 CPU/I/O、磁盘 I/O 指标 |
| `dmesg`、`journalctl` | 查看内核与系统日志 |

排查性能问题时，应先区分 CPU、内存、磁盘 I/O、网络和锁竞争哪个是主要瓶颈；结合进程指标、系统指标和应用日志交叉验证，避免只凭单个瞬时指标下结论。

## 八、面试常考题

### 1. 进程和线程有什么区别？

进程是资源分配与隔离的单位，拥有独立虚拟地址空间；线程是执行和调度的单位，同一进程的线程共享代码、堆和打开文件，但各自有栈和寄存器上下文。线程通信开销低但容易发生数据竞争，进程隔离更强但 IPC 成本更高。

### 2. 为什么线程切换通常比进程切换快？

同进程线程共享地址空间和多数资源，切换通常不必更换页表或进行同等程度的地址空间切换；但仍需保存/恢复寄存器和栈，并可能影响缓存。因此“更快”是相对概念，频繁切换依旧昂贵。

### 3. 用户态和内核态为什么要分开？

隔离限制普通程序直接执行特权指令、访问设备或其他进程内存，避免单个程序错误破坏整个系统。应用通过受校验的系统调用请求内核服务，实现安全与资源管理。

### 4. 什么是僵尸进程和孤儿进程？

子进程退出后，父进程尚未通过 `wait` 读取其退出状态时，子进程保留少量进程表项，称为僵尸进程；父进程先退出时，仍在运行的子进程成为孤儿进程，通常会被 `init/systemd` 等收养并在结束后回收。大量僵尸会耗尽 PID/进程表资源。

### 5. 什么是上下文切换，为什么它有成本？

它是保存当前任务 CPU 现场、选择并恢复下一任务现场的过程。除内核调度开销外，缓存与 TLB 局部性被破坏也会让后续指令和内存访问变慢。

### 6. 常见 CPU 调度算法有哪些？

FCFS 简单但可能有护航效应；SJF 降低平均等待但可能饿死长任务；时间片轮转适合交互；优先级调度满足重要任务但要防饥饿；多级反馈队列结合优先级与任务行为，在通用系统中常见。

### 7. 死锁的四个必要条件是什么？如何避免？

互斥、占有并等待、不可抢占、循环等待。工程中最常用的预防方法是统一资源/锁的获取顺序，避免在持锁时执行阻塞或外部调用，必要时使用超时、`tryLock` 与死锁检测。

### 8. 互斥锁、信号量和读写锁有什么区别？

互斥锁强调单一拥有者互斥访问；信号量通过计数控制多个相同资源许可或用于线程通知；读写锁允许多个读者并行但写者独占，适用于读多写少。选型取决于共享资源模型和访问比例。

### 9. 什么是虚拟内存？它有什么好处？

虚拟内存为每个进程提供连续、隔离的地址空间，并按页映射物理内存。它简化内存分配、提供保护和共享机制，还能借助按需分页让程序使用超过物理内存的地址空间，但过度依赖交换会导致抖动。

### 10. 缺页中断（缺页异常）发生时会怎样？

CPU 访问未映射到物理内存的虚拟页时陷入内核；内核检查是否合法，合法则分配或置换页框、从磁盘/交换区读取数据、更新页表后重试指令；非法访问则向进程报告错误并通常终止它。

### 11. 页面置换算法有哪些？LRU 为什么常被近似实现？

常见算法有 FIFO、LRU、Clock 和理论最优 OPT。精确 LRU 需要在每次访问时维护全局访问顺序，硬件/软件成本高；Clock 使用访问位循环扫描，以较低成本近似“最近使用”的判断。

### 12. 堆和栈有什么区别？

栈保存调用帧和局部变量，通常随函数调用自动增长和回收，分配快但容量有限；堆用于动态对象，生命周期灵活，需显式释放或由 GC 管理，容易产生碎片、泄漏或管理开销。具体布局与语言、运行时和平台有关。

### 13. 什么是内存泄漏？GC 语言还会内存泄漏吗？

内存泄漏是无用对象仍被引用，无法释放或回收。GC 只能回收不可达对象；若对象被全局变量、缓存、闭包、监听器或队列意外持有，它仍可达，GC 语言同样会泄漏。

### 14. `select`、`poll`、`epoll` 的区别？

三者都是 I/O 多路复用机制。`select` 有 FD 数量限制且每次要传递/遍历集合；`poll` 移除了固定集合位图限制但仍线性扫描；`epoll` 在内核维护关注列表，按事件返回就绪 FD，适合大量长连接。它们的实际表现还取决于连接活跃度和应用处理逻辑。

### 15. 文件删除后，为什么磁盘空间有时没有马上释放？

删除目录项后，若文件仍被进程打开，内核会保留该文件的数据与 inode，直到最后一个文件描述符关闭才真正回收空间。可用 `lsof` 查找标记为 deleted 但仍被占用的文件。

### 16. 阻塞 I/O、非阻塞 I/O、I/O 多路复用和异步 I/O 的区别？

阻塞 I/O 会让调用线程等待；非阻塞 I/O 立即返回并由应用重试；多路复用让一个线程等待多个 FD 的就绪事件；异步 I/O 则提交操作并在操作完成时接收通知。多路复用通知的通常是“可读/可写”，不一定表示完整读写已完成。
