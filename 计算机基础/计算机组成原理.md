# 计算机组成原理

计算机组成原理关注计算机如何在硬件层面执行程序：指令如何被 CPU 取出、译码和执行，数据如何在寄存器、缓存、内存与磁盘之间流动，以及各部件如何协同工作。

## 一、计算机系统概览

典型冯·诺依曼结构由**运算器、控制器、存储器、输入设备、输出设备**组成。程序和数据以二进制形式存储在存储器中，CPU 按顺序取出并执行指令；跳转、中断和异常会改变这一线性流程。

| 部件 | 核心职责 |
| --- | --- |
| CPU | 执行指令，包含控制器、运算器、寄存器和缓存 |
| 主存（RAM） | 保存正在运行的程序和数据，断电后内容丢失 |
| 外存（SSD/HDD） | 持久化保存数据，容量大但访问延迟远高于主存 |
| I/O 设备与控制器 | 连接网络、磁盘、显示器、键盘等设备 |
| 总线/互连 | 在 CPU、内存和设备之间传输地址、数据和控制信号 |

- **冯·诺依曼瓶颈**：CPU 与内存之间的带宽和延迟会限制整体性能。缓存、预取、流水线和更快的互连都在缓解这一问题。
- 现代系统通常是多核、分层缓存和复杂互连结构；上述模型是理解基础，不应把它误解为硬件实现的唯一形态。

## 二、数据表示与运算

### 数制与单位

- 位（bit）是二进制位；8 bit = 1 Byte（B）。常见容量单位有 KB、MB、GB、TB。实际产品中可能使用十进制（1 GB = 10^9 B）或二进制（1 GiB = 2^30 B）口径。
- 二进制转十六进制很方便：4 个二进制位对应 1 个十六进制位。例如 `1111 1010` 为 `0xFA`。

### 有符号整数：原码、反码、补码

现代计算机通常使用**补码**表示有符号整数：正数与原码相同；负数为对应正数按位取反后加 1。

- n 位补码范围是 `-2^(n-1)` 到 `2^(n-1) - 1`。
- 例如 8 位补码中，`-1` 是 `1111 1111`，`-128` 是 `1000 0000`。
- 使用补码可让加法器统一处理正负数，并使 0 的表示唯一。
- 有符号溢出发生在同号数相加却得到异号结果时；无符号溢出通常表现为进位超出最高位。程序应避免依赖溢出结果。

### 浮点数

IEEE 754 浮点数通常由**符号位、指数、尾数（有效数）**组成，以近似形式表示很大或很小的实数。二进制浮点无法精确表达许多十进制小数，例如 `0.1`，因此 `0.1 + 0.2` 可能不严格等于 `0.3`。

- 金额等精确小数场景应使用定点整数（如分）或十进制高精度类型，而非直接比较二进制浮点。
- 比较浮点数通常使用允许误差 `epsilon`，但误差阈值要结合数值量级选择。

### 算术逻辑单元（ALU）

ALU 执行加、减、与、或、异或、移位和比较等基本运算。乘除法可由专用电路或多步算法实现。移位常用于位运算和部分乘除 2 的幂的优化，但对有符号数与溢出必须遵循具体语言语义。

## 三、CPU 与指令执行

### CPU 的主要组成

- **控制器（Control Unit）**：取指、译码，发出控制信号，协调各部件工作。
- **ALU**：执行算术和逻辑运算。
- **寄存器**：CPU 内部最快的小容量存储，例如通用寄存器、程序计数器（PC）、指令寄存器（IR）、栈指针（SP）、状态寄存器。
- **缓存（Cache）**：位于 CPU 和主存之间，用于降低常用数据访问延迟。

### 指令周期

一条指令的抽象执行过程：

1. **取指（Fetch）**：根据 PC 从内存/指令缓存取出指令，并更新 PC；
2. **译码（Decode）**：识别操作码、寻址方式与操作数；
3. **执行（Execute）**：ALU 运算、地址计算、分支判断或设备操作；
4. **访存（Memory）**：需要时读取或写入数据缓存/主存；
5. **写回（Write Back）**：将结果写入寄存器或状态位。

实际 CPU 会把多个阶段重叠执行，并可能因缓存未命中、分支预测失败、数据依赖或中断而停顿或回滚。

### 指令集架构（ISA）

ISA 是软件与硬件之间的约定，规定指令、寄存器、数据类型、寻址方式和异常等。编译器将高级语言转换为特定 ISA 的机器指令。

| 类型 | 特点 | 代表 |
| --- | --- | --- |
| CISC | 指令种类和寻址方式较丰富，指令长度可能可变 | x86-64 |
| RISC | 指令相对规整、常见 load/store 架构，便于流水线实现 | ARM、RISC-V |

RISC/CISC 是设计取向而非绝对性能结论；现代处理器内部实现可能将复杂指令拆解为更简单的微操作。

### 流水线、冒险与分支预测

流水线让多条指令分别处于取指、译码、执行等不同阶段，提高吞吐量。理想情况下每周期可完成一条指令，但会遇到三类冒险：

- **结构冒险**：多个阶段竞争同一硬件资源；
- **数据冒险**：后续指令依赖前一条尚未产生的结果，如 RAW（读后写）；
- **控制冒险**：分支去向未确定，后续已取指令可能错误。

处理方式包括资源复制、暂停（stall）、数据前递（forwarding）、乱序执行、分支预测和推测执行。分支预测错误会清空错误路径上的工作，形成预测失败代价。推测执行相关的侧信道风险说明性能优化也需要安全边界。

## 四、存储层次与缓存

### 存储层次结构

越靠近 CPU 的存储通常越快、更小、更贵；越远则更慢、更大、更便宜：

`寄存器 -> L1 Cache -> L2 Cache -> L3/LLC -> 主存 RAM -> SSD/HDD/网络存储`

缓存有效的前提是程序具有局部性：

- **时间局部性**：刚访问的数据或指令很快可能再次访问；
- **空间局部性**：访问某地址后，附近地址也可能被访问。

### Cache 基础

缓存以**缓存行（cache line）**为单位在主存与 Cache 间搬运数据。地址通常被划分为标记（tag）、组索引（index）和块内偏移（offset）。

| 映射方式 | 特点 |
| --- | --- |
| 直接映射 | 每个内存块只能映射到一个缓存位置，简单但冲突未命中较多 |
| 全相联 | 可放入任意位置，冲突少但查找硬件复杂 |
| 组相联 | 映射到固定组、组内任选位置，性能与成本折中 |

缓存未命中常分为：首次访问的**强制未命中**、容量不够的**容量未命中**、映射冲突导致的**冲突未命中**。优化访问局部性、合理的数据布局和分块（blocking）可改善命中率。

### 写策略与多核一致性

- **写直达（write-through）**：写 Cache 时立即写主存，实现简单但写流量大。
- **写回（write-back）**：先只更新 Cache，缓存行被替换时再写主存，性能高但一致性更复杂。
- **写分配 / 非写分配**：写未命中时是否先把对应缓存行加载进 Cache。

多核各自拥有缓存时，一个核心写入数据后，其他核心的缓存副本可能过期。**缓存一致性协议**（例如 MESI 思想）负责让各核心对同一缓存行的读写维持一致的可观察状态。它不自动解决所有并发逻辑问题；应用仍需使用锁、原子操作和内存序。

## 五、主存、DMA 与 I/O

### RAM 与 ROM

- **RAM** 可读写、断电易失，主存通常使用 DRAM：容量大、成本较低但需要刷新。
- CPU 内部缓存通常使用 SRAM：速度快、无需刷新但面积和成本更高。
- **ROM/Flash** 用于存放固件等非易失数据，现代设备常可被受控地重写。

### 总线与 DMA

总线/互连在 CPU、内存、设备控制器之间传递地址、数据和控制信号。I/O 设备速度通常远低于 CPU，因此使用缓冲、队列和中断降低 CPU 忙等。

**DMA（直接内存访问）**允许设备控制器直接在设备与主存间搬运大块数据，CPU 只负责配置 DMA 并在完成后处理中断。DMA 减少 CPU 参与的数据拷贝，但仍需要考虑缓存一致性、内存保护和 I/O 调度。

### 中断与异常

- **中断**由外部事件触发，如网卡收到数据、磁盘 I/O 完成、时钟到期；
- **异常**由当前指令触发，如缺页、除零、非法指令；
- CPU 保存必要现场，跳转至内核的处理程序，处理结束后恢复或终止当前任务。

中断让 CPU 可在等待慢设备时执行其他工作。高频中断会有开销，系统可能通过中断合并、轮询或 NAPI 等机制折中处理。

## 六、性能指标与优化视角

### 常见指标

- **时钟频率**：每秒周期数，不等同于实际程序性能；
- **CPI**：平均每条指令所需时钟周期；
- **IPC**：平均每周期执行的指令数，约为 CPI 的倒数（在相同定义下）；
- CPU 时间可粗略表示为：`CPU 时间 = 指令数 × CPI × 时钟周期时间`；
- **延迟（latency）**衡量单次操作耗时，**吞吐量（throughput）**衡量单位时间完成的工作量。

优化应先测量并定位瓶颈。降低指令数、降低 CPI、提高频率都可能改善性能，但也可能受到内存墙、功耗、散热、I/O 与并发争用限制。阿姆达尔定律指出：整体加速比受未优化部分限制，优先优化耗时占比高的路径。

## 七、面试常考题

### 1. 冯·诺依曼体系结构包括哪些部分？

包括运算器、控制器、存储器、输入设备和输出设备。程序与数据都存放在存储器中，CPU 通过取指、译码、执行循环运行程序；现代系统在此基础上增加了缓存、多核和复杂互连。

### 2. 为什么整数通常使用补码表示？

补码让加法器可以用同一套加法逻辑处理正数和负数，零只有一种表示，并且符号扩展规则自然。n 位补码的取值范围是 `-2^(n-1)` 到 `2^(n-1)-1`。

### 3. 浮点数为什么会出现精度问题？

浮点数用有限二进制位近似表示实数，许多十进制小数在二进制中是无限循环，无法精确存储；加减乘除还会发生舍入。金额等精确场景应使用定点整数或十进制类型，比较浮点数使用合适误差范围。

### 4. CPU 执行一条指令的过程是什么？

抽象上依次经历取指、译码、执行、访存和写回。真实 CPU 使用流水线、缓存和乱序等技术让多条指令重叠执行，遇到依赖、分支预测失败或缓存未命中时会发生停顿或回滚。

### 5. 什么是 CPU 流水线？有哪些冒险？

流水线将指令执行拆为多个阶段并重叠运行，以提高吞吐。结构冒险是资源冲突，数据冒险是指令间数据依赖，控制冒险来自分支去向不确定。可用暂停、前递、资源复制、分支预测和乱序执行等方法缓解。

### 6. 分支预测失败为什么会影响性能？

CPU 会预测分支方向并提前执行预测路径上的指令。预测错误后，错误路径上的推测工作必须丢弃，再从正确位置取指，流水线被清空或部分回滚，造成周期损失。

### 7. Cache 为什么有效？什么是局部性原理？

程序常反复访问近期使用的数据（时间局部性），也常访问相邻地址（空间局部性）。Cache 将近期或邻近数据放在更靠近 CPU 的高速存储中，从而减少访问主存的平均延迟。

### 8. Cache 的三种未命中是什么？

强制未命中来自首次访问；容量未命中表示工作集超过缓存容量；冲突未命中来自多个内存块映射到同一缓存位置。增加容量、提高相联度或改善数据访问局部性可分别缓解其中一部分。

### 9. 写直达和写回有什么区别？

写直达每次更新缓存也更新主存，一致性处理直观但内存写流量大；写回先只更新缓存，替换脏缓存行时再写主存，性能更好但需要记录脏位并处理更复杂的故障与一致性情形。

### 10. 多核下为什么需要缓存一致性？

多个核心可能缓存同一内存地址的副本。若一个核心写入后其他核心仍读旧副本，程序会观察到不一致结果。MESI 等协议让缓存行状态在核心间协调；应用级并发正确性还需锁、原子操作和内存序保证。

### 11. RAM、SRAM、DRAM 有何区别？

RAM 是可读写易失存储的总称。SRAM 速度快、不需刷新、成本高，常用于 CPU Cache；DRAM 容量大、单位成本低、需周期刷新，常作为主存。

### 12. 什么是 DMA，它有什么价值？

DMA 让设备控制器直接在设备和内存间传输数据，CPU 只配置任务并处理完成中断。它减少大块 I/O 数据搬运时的 CPU 占用，提高系统并行性；仍需考虑缓存一致性、内存保护和设备错误处理。

### 13. 中断和异常有什么区别？

中断通常来自外部异步事件，如网卡或时钟；异常由当前执行指令同步触发，如缺页或除零。两者都会保存现场并进入内核处理程序，但来源和处理语义不同。

### 14. 时钟频率越高，CPU 一定越快吗？

不一定。性能还取决于每周期完成的工作量（IPC/CPI）、指令数量、缓存命中率、分支预测、内存和 I/O 等。提高频率也会受功耗与散热约束，应结合实际工作负载评估。

### 15. 什么是阿姆达尔定律？

它说明整体性能提升受未优化部分限制。即使某一小部分被无限加速，最大收益仍由它原本在总执行时间中的占比决定，因此优化应优先针对占比高的瓶颈路径。
